# CF 2261B — What's the Capital of France?

题目：[Codeforces 2261B](https://codeforces.com/problemset/problem/2261/B)。分类：位运算、极值、不变量、构造证明。

收录原因：**先从操作中找出答案的限制，再构造一个确实能达到限制的状态。** 将“最多能有多大”和“怎样才能做到”分开思考，避免只猜公式。

## 题目模型

数组中的元素排成一行。每次选择**两个相邻元素**：

- 若不同，**较小的元素加 1**，较大的不变。
- 若相同，什么也不发生。

可以操作任意次，也可以不操作。求某个可达状态下，**全部元素按位 OR 的最大值**，不需要输出具体操作。

约束：$1\le n\le2\times10^5$，$0\le a_i\le10^9$；多测的 $n$ 之和不超过 $2\times10^5$。

## 1. 从几个例子观察答案

### 情况一：全部相等，没有调整空间

数组为 `[8,8,8]`，相邻元素都相等，任何操作都不能改变它们。

$$
8\mathbin{\mathrm{OR}}8\mathbin{\mathrm{OR}}8=8.
$$

因此答案就是 8。**只有一个元素时，也属于这种情况。**

### 情况二：单个数不能超过最大值，OR 却可以

数组为 `[2,4]`。选择这一对，把 2 增加一次，得到 `[3,4]`。

$$
3=(0011)_2,\qquad 4=(0100)_2.
$$

3 提供低两位的 1，4 提供更高一位的 1。

$$
3\mathbin{\mathrm{OR}}4=(0111)_2=7.
$$

虽然每个数都没有超过 4，**合起来的 OR 已经达到 7**。

还能得到 8 或更大吗？不能。任何元素都无法增加到 8，也就无法提供代表 8 的那一位。

> **要限制的是各个二进制位能否出现 1，不能直接把最大元素当成答案上限。**

### 情况三：高位相同，尝试补齐低位

数组为 `[8,14]`，先观察二进制：

$$
8=(1000)_2,\qquad 14=(1110)_2.
$$

两个数的最左边都是 1，第一次不同出现在后面的这一位：

```text
8  =  1 | 0 | 00
14 =  1 | 1 | 10
       ↑   ↑
    相同高位 最高不同位
```

让 8 依次增加到 9、10、11。它始终小于相邻的 14，因此每一步都合法。

$$
11=(1011)_2,\qquad 14=(1110)_2.
$$

11 补齐低两位，14 提供最高不同位上的 1。

$$
11\mathbin{\mathrm{OR}}14=(1111)_2=15.
$$

这时可变化的后三位已经全部为 1，不能再大。

**不需要把较小值一直增加到最大值，只要停在能补齐低位的位置。**

### 情况四：共同高位中有 0，这些 0 不能随便补齐

数组为 `[10,11]`：

$$
10=(1010)_2,\qquad 11=(1011)_2.
$$

两者共同的高位是 `101`，只在最后一位不同。

数组中的值只能保持为 10 或增加到 11，因此共同高位里的那个 0 不会变成 1。

$$
10\mathbin{\mathrm{OR}}11=(1011)_2=11.
$$

所以答案是 **11，而不是 15**。

> **能补齐的是“最高不同位及以下”，不是最大值最高位以下的所有位置。**
>
> 最高不同位上方的共同高位，原来是什么，就必须保留什么。

## 2. 为什么共同高位始终不变？

先明确操作的限制：

1. **每个元素只会增加，不会减小。**
2. **增加的是相邻两数中的较小者，一次只加 1，最多追平较大者。**
3. 因而没有元素能超过初始最大值，所有值始终位于初始最小值和最大值之间。

例如初始最小值为 10、最大值为 11，那么每个元素都留在 `[10,11]` 内。

$$
[10,11]=[(1010)_2,(1011)_2].
$$

这个范围只包含共同高位为 `101` 的数；若改变更高的某一位，就会离开这个范围。

**一般情况下也一样：从最小值走到最大值，最高不同位上方的共同高位不会改变。**

所以答案有一个明确上限：

> **共同高位保持原样，最高不同位及以下全部置 1。**

不过，这还只是上限。**接下来必须证明：在相邻操作的限制下，确实存在一个状态达到它。**

## 3. 最小值和最大值不相邻，怎么办？

### 先看一个不相邻的例子

数组为 `[8,10,14]`，最小值 8 和最大值 14 不能直接互相操作。

仍然观察刚才的最高不同位：

```text
8  =  1 | 0 | 00
10 =  1 | 0 | 10
14 =  1 | 1 | 10

这一位： 0     0     1
             └─相邻─┘
```

虽然 8 和 14 不相邻，**10 和 14 相邻，而且它们在关键的这一位上分别为 0、1**。

只操作这一对，把 10 增加到 11：

$$
[8,10,14]\longrightarrow[8,11,14].
$$

11 已经补齐所需低位，14 提供更高一位的 1。

$$
8\mathbin{\mathrm{OR}}11\mathbin{\mathrm{OR}}14=15.
$$

因此，不需要最小值和最大值亲自相邻。它们只负责帮助确定**应该观察哪一位**。

### 为什么一定能找到这样一对相邻元素？

按最高不同位，将所有元素分成两类：

- **这一位为 0。** 最小值属于这一类。
- **这一位为 1。** 最大值属于这一类。

两类都存在。沿着数组从左向右看，**必然至少有一次相邻的 0、1 切换**。

例如，下面几种排列都能找到边界：

```text
0 0 1 1    → 中间有 0 / 1 边界
1 1 0 0    → 中间有 1 / 0 边界
0 1 0 1    → 有多处边界，任选一处即可
```

**不要求原数组有序，也不需要排序。** 相邻两类的左右顺序不影响操作。

### 找到相邻边界后，为什么总能补齐？

这对元素的共同高位相同，但最高不同位分别为 0、1，因此 **0 这一侧一定更小**。

只增加较小值，让它停在：

```text
共同高位 | 0 | 低位全部为 1
```

这是“共同高位不变、关键位仍为 0”的最大数，**不会小于原来的较小值**。

而相邻的较大值为：

```text
共同高位 | 1 | 任意低位
```

所以即使较小值已经补满低位，它也仍然小于这个邻居。增加过程不会提前追平，所有操作都合法。

若低位原本就已全为 1，则无需增加，直接使用当前状态。

最后，两个数各自提供所需的位：

- 较小值提供**全部低位的 1**。
- 较大值提供**最高不同位上的 1**。
- 更高的共同部分保持不变。

> **这样得到的是同一时刻的一个合法状态，确实达到了上限。**
>
> 其他元素无需改变，OR 也不会因为加入其他元素而丢失已有的 1。

## 4. 对照例子，得到代码中的公式

仍以最小值 8、最大值 14 为例。

### 第一步：用异或找到不同的位置

$$
8\mathbin{\mathrm{XOR}}14=(0110)_2=6.
$$

异或结果中为 1 的位置，就是两个数不同的位置。

### 第二步：取出其中最高的一位

$$
\mathrm{high}=(0100)_2=4.
$$

`high` 表示这一位对应的数值 **4**，不是它的位编号 **2**。

### 第三步：减去 1，得到低位全为 1 的数

$$
\mathrm{high}-1=4-1=(0011)_2=3.
$$

它只负责把最高不同位**以下**的两位补成 1，不会改变上面的位。

### 第四步：与最大值按位 OR

$$
14\mathbin{\mathrm{OR}}3=(1111)_2=15.
$$

最高不同位在最大值中本来就是 1，所以只需补齐它下面的位。

对应代码：

```cpp
int ans = maxx | (high - 1); // 保留高位，把最高不同位以下全部置 1
```

**这里的 3 只是用来置位的数，不是实际操作要达到的值。** 上面的合法构造停在 11，不能把 8 减少到 3。

## 5. 原实现

原代码只调整排版与说明性注释，保留 `solve()` 逻辑。通用头文件和多测框架不重复展示。

```cpp
void solve() {
    int n;
    cin >> n;
    vector<int> a(n);

    for (int& x : a)
        cin >> x;

    int minn = *min_element(a.begin(), a.end());
    int maxx = *max_element(a.begin(), a.end());

    if (minn == maxx) {
        cout << maxx << '\n';
        return;
    }

    int dif = minn ^ maxx; // 为 1 的位置，表示两者对应位不同
    int high = 1;

    while (high <= dif / 2)
        high <<= 1; // 最终为 dif 的最高置位对应的位权

    int ans = maxx | (high - 1);
    cout << ans << '\n';
}
```

`dif` 的最高置位对应 `high`。循环从 1 开始，每次乘 2，直到再乘 2 就会超过 `dif`。

$$
\mathrm{high}\le\mathrm{dif}<2\times\mathrm{high}.
$$

此时 `high` 恰好就是需要的最高位权。

**要比较对应位，必须用异或，不能用最大值减最小值。** 例如：

$$
8-7=1,\qquad 8\mathbin{\mathrm{XOR}}7=(1111)_2=15.
$$

7 和 8 虽然只差 1，却在多位上不同；最高不同位对应的数值为 8，最终答案为 15。

原实现时间为 $O(n+\log V)$，$V$ 为值域上界；保存数组的空间为 $O(n)$。

### 可选：输入时直接维护极值

后续不需要原数组，读入部分也可以写成：

```cpp
int minn = INT_MAX, maxx = 0; // 原题保证输入非负
for (int i = 0; i < n; ++i) {
    int x;
    cin >> x;
    minn = min(minn, x);
    maxx = max(maxx, x);
}
```

其余判断与求最高不同位的代码不变，额外空间降为 $O(1)$。原实现已符合题目规模，保留即可。

## 6. 另外两个容易误判的地方

### 数值增加，不代表 OR 增加

数组 `[3,4]` 本来就有：

$$
3\mathbin{\mathrm{OR}}4=7.
$$

如果继续把 3 增加到 4，两个数就都变成了 4。

$$
4\mathbin{\mathrm{OR}}4=4.
$$

**加法进位可能清掉原来的低位 1。** 因此不能认为“全部追平最大值”最优。

### 证明能做到，不代表需要实际模拟

本题只要求最大 OR，不要求操作序列。

证明某一对相邻元素可以逐步达到目标后，**直接计算答案即可**，无需真的执行大量加一操作。

数值范围方面，原题输入小于 $2^{30}$，答案至多为 $2^{30}-1$，使用 `int` 足够。`high` 最大为 $2^{29}$，循环使用 `dif/2` 判断，避免先计算两倍 `high`。

## 如何想到

可以依次问四个问题：

1. **操作再多，也突破不了什么？** 较小者只能追平较大者，所以初始最大值不会被突破。
2. **这些限制反映到二进制上是什么？** 极值的共同高位始终不变。
3. **理想答案还缺哪些位？** 最高不同位以下尽量补成 1。
4. **相邻限制会阻止构造吗？** 两类元素之间必有相邻边界，能让一对元素共同提供所需的 1。

**先观察例子 → 找到始终不变的限制 → 提出上限 → 用合法构造达到上限。**

极值能决定本题答案，是上面这些论证的结果。若操作次数受限，就不能直接套用同一结论。
