# CF 2277D1 — Number Operating（简单版）

题目：[Codeforces 2277D1](https://codeforces.com/contest/2277/problem/D1)。

收录原因：**找到重置点，把依赖历史的操作拆成独立组，再将剩余目标转成同类子问题。**

x 初始为 0。连续做操作 1，依次加 1、2、4……；操作 2 减 1，并重置连续计数，允许减成负数。

f(n) 表示恰好得到 n 的最少操作数。要求区间内 f(n) 之和，对 998244353 取模。虽然 r≤10¹⁸，但所有区间长度之和仅为 2×10⁵，因此可以逐个求 f(n)。

## 1. 参考实现

采用[官方递推](https://codeforces.com/blog/entry/158113)，保留参考实现与当前的 `__lg(n)` 写法，省略通用 main。

```cpp
using ll = long long;

constexpr ll MOD = 998244353;

ll f(ll n) {
    if (n <= 1) return n;
    if (n == 2) return 3;
    if (n == 3) return 2;

    // n>=4，__lg(n) 取得最高位 1 的位置。
    int k = __lg(n);
    ll p = 1LL << k; // 2^k <= n < 2^(k+1)

    // 做一组 k 次加法和一次重置，剩余目标从连续计数 0 重新求解。
    ll a = f(n - p + 2) + k + 1;

    // 最后一段直接加到 2^(k+1)-1，再逐次减到 n；不额外算重置。
    ll b = (1LL << (k + 1)) - n + k;

    return min(a, b);
}

void solve() {
    ll l, r;
    cin >> l >> r;

    ll ans = 0;
    for (ll n = l; n <= r; ++n) {
        ans = (ans + f(n)) % MOD;
    }

    cout << ans << '\n';
}
```

## 2. 先分组：完整组与最后一段

连续加 3 次，再重置：

$$
0\xrightarrow{+1}1\xrightarrow{+2}3\xrightarrow{+4}7\xrightarrow{-1}6.
$$

**花 4 次操作，净增 6，下一组重新从 +1 开始。** 一般地：

$$
\underbrace{1+2+\cdots+2^{t-1}}_{t\text{ 次加法}}-1=2^t-2.
$$

因此一个完整组的**贡献是 2ᵗ−2，成本是 t+1**。每组都以连续计数 0 开始、结束，所以组之间可以交换顺序。

**最后一段不必重置。** 例如目标是 7，连续加 3 次就结束，不能再补一次减法。这段贡献是 2ᵗ−1，成本只有 t。

## 3. 先识别递归，再写两种选择

取 k 满足：

$$
2^k\le n<2^{k+1}.
$$

### A：先完成一组，再解决剩余目标

先连续加 k 次并重置，花 k+1 次操作，净增 2ᵏ−2。剩余目标是：

$$
n-(2^k-2)=n-2^k+2.
$$

**这里要先认出：剩下的不是一个新问题，而是原问题缩小后的版本。**

- 原问题：连续计数为 0，从 0 出发，恰好增加 n。
- 做完一组：连续计数又回到 0，只需再增加 n−2ᵏ+2。
- 把当前位置看成新的 0，**操作规则完全相同，改变的只有目标大小**，因此剩余最少次数就是 f(n−2ᵏ+2)。

这就是递归的识别信号：**完成一个选择后，剩余任务仍能用同一个函数描述。** 当前层支付本组成本，余下的同类选择交给下一层处理。

还要确认规模确实减小：

$$
2\le n-2^k+2<n\qquad(n\ge4).
$$

所以递归会落到前面的几个小目标。若没有重置，下一次加多少还受此前连续次数影响，就不能只凭剩余目标直接调用同一个 f。

剩余部分也必须取最少次数，否则替换成更短的同目标过程，整体还能更优。于是：

$$
\boxed{A=f(n-2^k+2)+k+1.}
$$

### B：直接超过目标，再减回来

连续加 k+1 次，到达 2ᵏ⁺¹−1；再减去多出的部分：

$$
B=(k+1)+(2^{k+1}-1-n)=2^{k+1}-n+k.
$$

**到达目标就结束，不额外支付重置成本。** 两种选择取小，得到 n≥4 时的递推：

$$
\boxed{f(n)=\min\left\{
\begin{aligned}
&f(n-2^k+2)+k+1,\\
&2^{k+1}-n+k.
\end{aligned}
\right.}
$$

小目标直接确定：

$$
f(0)=0,\quad f(1)=1,\quad f(2)=3,\quad f(3)=2.
$$

以 n=13、k=3 为例，一边先净增 6，再求 f(7)；另一边直接加到 15，再减 2：

$$
A=f(7)+4=7,\qquad B=4+2=6.
$$

所以 f(13)=6。**不是永远先做完整组，最后一段的直接收尾也可能更优。**

### 为什么只需这两种长度？

先删掉零贡献的“+1 后重置”；末尾单独的 +1 也可与前一次减法抵消。剩下讨论 t≥2。

两组同长度 t 可以合成一组 t+1，再减 2，贡献不变：

$$
2(2^t-2)=(2^{t+1}-2)-2.
$$

新旧成本之差为：

$$
(t+2)+2-2(t+1)=2-t\le0.
$$

**反复合并，可以让各段长度互不相同，成本不增加。** 若其中一段是末尾不重置段，两边各少一次减法，比较仍成立。

若所有段都比 k 短，即使把末段少减的一次算上，最多也只能得到：

$$
1+\sum_{t=2}^{k-1}(2^t-2)=2^k-2k+1<2^k\le n.
$$

所以必有一段长度至少为 k：

- **最长恰好为 k：** 单段还达不到 n，将它做成完整组放在开头，剩余部分对应 A。
- **有 k+1 或更长的段：** 单段已能超过目标，其他组只增加成本与回减次数；直接用 k+1 次加法收尾即可，对应 B。

**关键不是猜两种方案，而是把其他方案整理成它们之一，证明不会更差。**

## 4. 可迁移的思考方式

> **完成一个选择 → 识别剩下仍是同一个问题 → 检查状态与规模 → 写递归关系。**

- **优先识别同型子问题：** **做完一组，能否把剩余任务重新描述成“从头解决一个更小的目标”？本题靠重置恢复起始状态，再靠平移消除当前位置**。
- **检查递归能否成立：**  **规则相同、必要状态一致、目标严格变小，并有可直接回答的边界。不是只要出现“剩余量”，就可以递归**。
- **中间与结尾分开：** 中间要为继续操作付出重置成本，结束时未必需要。
- **缩小选择要有证明：** 用合并、交换或成本比较排除方案，不能直接猜“取最大的”。
- **最后看数据范围：** 单点递推足够快，区间长度又小，就直接枚举，不急着设计大值域求和。

递归只进入 A 一次，剩余目标小于 $n/2+2$，单点 $O(log(n+2))$；总时间为区间长度之和乘对数，递归空间为 $O(log(r+2))$。候选比较使用真实值，只在外层累加时取模。
