# CF 1494B — Berland Crossword

题目：[Codeforces 1494B](https://codeforces.com/problemset/problem/1494/B)。分类：小状态枚举、bitmask、边界耦合。

收录原因：学会先识别约束之间的耦合位置，通过固定少量关键选择，把整体可行性问题分解为独立的局部判断；同时警惕数值处理丢失变量的结构关系。

## 题目模型

在 `n × n` 网格的边界染黑若干格，使上、右、下、左边黑格数分别恰为 `U、R、D、L`，判断是否存在方案。角落同时计入相邻两条边，内部格不参与。约束：`2 <= n <= 100`，各边需求在 `[0,n]`，测试数不超过 `1000`。

## 最初方向：排序后对数值分类

```cpp
// 不合适的方向：只保留四个数的大小，丢失它们所属的边。
sort(dir.begin(), dir.end());
```

四个数不是可任意交换的需求，它们按 `U → R → D → L → U` 构成相邻关系。相邻两边共享角落，对边不共享；只看大小无法恢复这种区别。

反例：`n=2` 时，以下两组排序后都得到 `[0,0,1,1]`，答案却不同。

| `(U,R,D,L)` | 答案 | 原因 |
| --- | --- | --- |
| `(0,0,1,1)` | YES | 只把左下角染黑即可 |
| `(0,1,0,1)` | NO | 上、下两行必须全白，整个 `2×2` 网格已全白 |

经验不是“带位置的数据一律不能排序”，而是：**排序不能丢掉判断答案所需的身份与关系。** 带着方向标签排序后仍按原方向处理，并非错误；整体旋转或镜像也保留邻接关系。任意重排四个裸数则不具备这种保证。

## 核心转化：只枚举四个角

每条边中间有 `n-2` 个格子，只属于这一条边。真正让不同边互相影响的，只有四个角。

| bit | 角落 | 染黑后减少的需求 |
| --- | --- | --- |
| 0 | 左上 | `u、l` |
| 1 | 右上 | `u、r` |
| 2 | 右下 | `d、r` |
| 3 | 左下 | `d、l` |

四角各有黑、白两种状态，共 $2^4=16$ 种。整数 `mask` 的低四位表示选择，`mask & (1 << i)` 非零表示第 `i` 个角染黑。

例如 `mask=5` 的低四位为 `0101`：左上、右下黑，另外两角白。二进制书写从高位到低位，右端才是 bit 0；四角顺序必须与扣减规则一致。

每种状态恢复 `u=U、r=R、d=D、l=L`，扣除黑色角落的贡献。随后只需检查四个剩余需求都在 `[0,n-2]`。

## 整理实现

代码保留四角扣除需求的核心逻辑，完整程序为整理实现。

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n, U, R, D, L;
    cin >> n >> U >> R >> D >> L;

    // bit 0..3：左上、右上、右下、左下；1 表示染黑。
    for (int mask = 0; mask < 16; ++mask) {
        int u = U, r = R, d = D, l = L; // 每种状态重新恢复需求

        if (mask & 1) { // 左上角同时属于上边、左边
            --u;
            --l;
        }
        if (mask & 2) { // 右上角同时属于上边、右边
            --u;
            --r;
        }
        if (mask & 4) { // 右下角同时属于下边、右边
            --d;
            --r;
        }
        if (mask & 8) { // 左下角同时属于下边、左边
            --d;
            --l;
        }

        // 去掉角落后，各边中间格互不共享，每边容量为 n-2。
        if (0 <= u && u <= n - 2 &&
            0 <= r && r <= n - 2 &&
            0 <= d && d <= n - 2 &&
            0 <= l && l <= n - 2) {
            cout << "YES\n";
            return; // 存在一种合法角落状态即可
        }
    }
    cout << "NO\n"; // 16 种状态全部不合法
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T;
    cin >> T;
    while (T--) solve();
    return 0;
}
```

单组时间 `O(16 × 4)=O(1)`，辅助空间 `O(1)`。原核心思路已经适合本题，不额外制造第二种“更优”代码；完整程序补齐输入输出、找到可行状态后的退出，以及枚举完仍无解时的处理。

## 正确性与边界

**必要性：** 任意实际染色都对应某一种四角状态。去掉角落贡献后，每边中间格只能提供 `0..n-2` 个黑格，因此四个余量必须落在这个范围内。

**充分性：** 固定一种四角状态后，四条边的中间格互不共享。若各边余量合法，就能分别选出对应数量的中间格染黑，得到满足全部要求的方案。枚举覆盖所有角落组合，故不会漏掉解。

- `n=2`：每边没有中间格，四个余量必须全部为 `0`。
- 需求为 `0`：该边的两个角都不能染黑；余量下界不可省略。
- 需求为 `n`：该边两角都必须染黑，否则中间格容量不足。
- 每次枚举都从原需求复制，不能在上一状态扣减后的结果上继续修改。
- 找到一个合法状态即返回；循环内某个状态不合法，不能立即判整个题无解。

## 如何想到与进步空间

```text
四边数量彼此影响，分类条件越来越多
→ 找到产生共享影响的位置：四个角
→ 每角二选一，状态总数只有 16
→ 固定共享部分后，四条边中间格独立
→ 用容量范围检查代替具体构造网格
```

关键不只在“状态少就枚举”，还在**找对需要枚举的状态**。整个边界有 `4n-4` 个格子，逐格枚举需 `2^(4n-4)` 种；固定四个角后，中间格不必逐一决定，只需判断数量能否达到。

bitmask 只是四个二元选择的紧凑表示，不自动保证复杂度小。一般有 `c` 个二元变量就有 `2^c` 种状态，仍需结合每种状态的检查成本判断是否可行。

## 范式与核验

- [枚举少量耦合变量：固定共享部分后独立求解](../patterns/small-coupling-enumeration.md)：只枚举让各部分相互影响的少量选择。
- [枚举降维](../patterns/enumeration-dimension-reduction.md)：其余变量能够由约束直接算出时，只枚举自由变量；本题剩余染色不唯一，范围检查足以判断存在性。

整理实现以 C++17、`-O2 -Wall -Wextra` 编译，无警告；通过原题 4 组样例、2,258 组小规模输入穷举核验及 4 组 `n=100` 边界。

小规模覆盖 `2 <= n <= 5`、`0 <= U,R,D,L <= n` 的全部需求组合。校验器枚举实际边界格的全部染色，直接统计可实现的四边计数，不使用四角余量判据；上述排序反例也已核验。大边界包括全零、四边全满、单边满而相邻边为零、上下满且左右需求均为 `2`。平台通过记录未核验，不将本地通过标为新增 AC。
