# CF 2271B — MEX Game

题目：[Codeforces 2271B](https://codeforces.com/contest/2271/problem/B)。

收录原因：训练从定义发现遗漏、用反例检验直觉的习惯；学习把过程复杂的博弈转化为资源阈值判定，再用双方策略证明结论。

## 题意与定义

有偶数张牌 `n`，Alice 先手，两人轮流任取一张，直到各拿到 `n/2` 张。对多重集合 `S`，定义：

$$
\mathrm{mex}_k(S)=\min\lbrace x\ge0:\mathrm{cnt}_S(x)<k\rbrace.
$$

`k=1` 时就是通常的 MEX（Minimum Excluded，最小未出现非负整数）。Alice 希望双方的 `mex_k` **不同**，Bob 希望它们**相同**。输出 `YES` 表示 Alice 在双方最优时必胜，否则输出 `NO`；相同是 Bob 获胜，不是平局。

题目约束：`2 ≤ n ≤ 2×10^5`，`n` 为偶数，`1 ≤ k ≤ n`，`0 ≤ a[i] ≤ n`，所有测试的 `n` 之和不超过 `2×10^5`。

## 一、初始思路：按数值分组，构造双方牌组

我的实现先统计频率、排序去重，再按已分配牌数的奇偶分配当前数值：数量为偶数时均分；数量为奇数时，当前轮到的一方多拿一张。

这等价于把所有牌排序，按位置交替放入 `A`、`B`。对每个数值 `x`，构造出的双方数量分别是：

$$
\left\lfloor\frac{cnt[x]}2\right\rfloor,\qquad
\left\lceil\frac{cnt[x]}2\right\rceil.
$$

**这是一种平衡分配模型。**它是否能判定真实博弈，需要另行证明，不能假设双方都会从小到大拿牌。

反例：`n=6, k=1`，牌为 `0 0 0 0 1 2`。若 Alice 每次拿最小值，Bob 可以依次拿 `1、0、2`，最终双方 MEX 都是 `1`。但 Alice 首手拿 `1`，后续争取 `0`，就能保证自己的 MEX 大于 `1`，而 Bob 的 MEX 不超过 `1`。

## 二、WA 的准确原因：只检查了已有数字

原来的 MEX 计算按连续相同元素分段，只检查已有数值的频率，不足 `k` 就返回该数值；全部满足时使用 `back()+1`。

遗漏在于：**没有出现的数，频率也是 `0`，同样满足 `0 < k`。** MEX 必须检查从 `0` 开始的连续整数，不能只遍历集合中已有的值。

| 输入中的 `n, k, a` | 原 WA 输出 | 正确输出 | 暴露的问题 |
|---|---|---|---|
| `2, 1, [1,2]` | YES | NO | 双方都缺少 `0`，原程序却得到 MEX 为 `2、3` |
| `4, 1, [0,1,2,2]` | NO | YES | 构造的 `{0,2}`、`{1,2}` 实际 MEX 为 `1、0`，原程序都算成 `3` |
| `4, 1, [0,0,2,3]` | YES | NO | 漏掉中间缺失的 `1` |
| `2, 2, [0,1]` | YES | NO | 每人只有一张牌，双方 `0` 的频率都不足 `2` |

当 `k=1` 时，所有已出现数的频率必然达标，原程序实际上退化成比较两组的最大值，而不是比较 MEX。

### 尾状态经验与本次 WA 要分开

> 写代码时得到的经验是：如果只在状态变化时结算上一段，循环结束后要处理最后一段。但原 WA 代码已经有 `if (!found)` 的尾段判断，**不能再把“忘记尾段结算”列为这份代码的实际错误**。尾段处理完整，也不能补救定义域扫描错误。

另外，题目保证 `n` 为偶数且至少为 `2`，所以当前构造中双方长度相等、都非空；共用长度和调用 `back()` 不构成本题合法输入下的越界反例。

## 三、个人 AC：保留分配，按定义计算 MEX

修正的关键是从 `0` 开始检查频率。缺失键按 `0` 处理，自然覆盖起点缺失和中间空缺。

下面是个人 AC 思路的整理版：保留分组交替分配，去掉调试输出和无用变量。

```cpp
#include <bits/stdc++.h>
using namespace std;

int mex_k(const vector<int>& v, int k) {
    unordered_map<int, int> cnt;
    for (int x : v) ++cnt[x];
    int m = 0;
    while (cnt[m] >= k) ++m;  // 未出现的数会得到频率 0
    return m;
}

void solve() {
    int n, k;
    cin >> n >> k;
    vector<int> values(n);
    unordered_map<int, int> cnt;
    for (int& x : values) {
        cin >> x;
        ++cnt[x];
    }
    sort(values.begin(), values.end());
    values.erase(unique(values.begin(), values.end()), values.end());

    vector<int> a, b;
    int used = 0;
    for (int x : values) {
        int c = cnt[x];
        // 已分配偶数张时，下一张轮到 Alice。
        int take_a = c / 2 + ((used % 2 == 0) ? c % 2 : 0);
        int take_b = c - take_a;
        a.insert(a.end(), take_a, x);
        b.insert(b.end(), take_b, x);
        used += c;
    }
    cout << (mex_k(a, k) != mex_k(b, k) ? "YES\n" : "NO\n");
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--) solve();
}
```

排序为 `O(n log n)`；哈希操作平均为常数时，总时间为 `O(n log n)`，辅助空间为 `O(n)`。`unordered_map` 不提供最坏情况常数时间保证。

这一阶段解决了 MEX 实现问题，但“构造出一个结果”本身还不能证明“一方可以强制这个结果”。

## 四、提炼临界条件：第一个无法同时满足双方的数

在平衡分配下，一个数要让双方都达到 `k` 次，总频率至少要有 `2k`。因此设：

$$
t=\min\lbrace x\ge0:cnt[x]<2k\rbrace.
$$

对所有 `x<t`，平衡分配让双方各至少得到 `k` 张，所以双方 MEX 都不会停在这些位置。只需看 `t`：

| `cnt[t]` | 平衡分配后的数量 | MEX 关系 |
|---|---|---|
| `2k-1` | 一方 `k`，另一方 `k-1` | 一个大于 `t`，一个等于 `t` |
| 不超过 `2k-2` | 双方都不超过 `k-1` | 都等于 `t` |

这里的数量结论依赖**平衡分配**。例如 `k=3`、总共 `4` 张时，任意分配仍可能是 `3+1`，不能仅凭 `4<2k-1` 就说双方都不足 `k`。

## 五、配对策略证明：为什么这个模型能判定博弈

先把相同数值的牌尽量两两配对。每个奇数频次数值剩下一张，再把所有剩余牌任意两两配对。由于 `n` 为偶数，剩余牌数也为偶数。

若每对牌最终都由双方各拿一张，那么相同数值的成对部分会被均分；每个奇数频次数值的唯一剩余牌落在任意一方，都会得到向下、向上取整的两份。因此，**所有按对拆分的结果，都具有前面的 MEX 关系**。

接着分别证明双方能强制拆分每对牌。

**Bob 的策略：**Alice 拿一张，Bob 就拿它的配对牌。每轮开始时所有未拿的牌都是完整的对，因此回复始终合法。

**Alice 的策略：**首手任拿一张，留下它的配对牌作为唯一一张落单牌。每次 Bob 行动前，未拿牌由“一张落单牌 + 若干完整对”组成：

- Bob 从完整对中拿一张，Alice 就拿该对的另一张，原落单牌保留。
- Bob 拿走落单牌，若还有牌，Alice 就从完整对中拿一张，留下新的落单牌。
- 最后只剩落单牌时，Bob 拿走它，游戏结束。

每个被拆开的对都由双方各拿一张；这是对 Bob 任意合法选择都成立的不变量。

于是：

- `cnt[t] ≤ 2k-2`：Bob 强制平衡分配，双方 MEX 相同，Bob 必胜。
- `cnt[t] = 2k-1`：Alice 强制平衡分配，双方 MEX 不同，Alice 必胜。

得到充要条件：

$$
\boxed{\text{Alice 必胜}\iff cnt[t]=2k-1.}
$$

个人 AC 构造的也是平衡分配，因而能正确判定胜负。证明支持的是**胜负判定等价**，不要求真实对局产生相同的 `A、B`。

## 六、线性实现：只统计原数组频率

既然答案只取决于第一个不达 `2k` 的频率，就不必排序、分牌或计算两次 MEX。

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n, k;
    cin >> n >> k;
    vector<int> cnt(n + 1, 0);  // 题目保证 0 <= a[i] <= n
    for (int i = 0; i < n; ++i) {
        int x;
        cin >> x;
        ++cnt[x];
    }

    int x = 0;
    while (cnt[x] >= 2 * k) ++x;
    cout << (cnt[x] == 2 * k - 1 ? "YES\n" : "NO\n");
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--) solve();
}
```

扫描经过 `x` 个合格数，至少消耗 `2kx` 张牌，因此 `x ≤ floor(n/(2k)) ≤ n`，不会访问 `cnt[n+1]`。本题范围内 `2*k` 也不会溢出 `int`。时间、辅助空间均为 `O(n)`。

## 七、边界与验证

- 没有 `0`：双方 MEX 都为 `0`，输出 `NO`。
- 中间缺数：频率为 `0` 的位置必须参与扫描。
- `k>n/2`：每人牌数不足 `k`，双方 MEX 必为 `0`，输出 `NO`。
- 首个不足位置恰为 `2k-1`：输出 `YES`；降到 `2k-2` 则输出 `NO`。
- 前面存在奇数频率但不少于 `2k`：多出的一张不影响双方都达标。

文内两份完整 C++ 程序均经过 C++17 编译，并对照独立极小化极大搜索验证了 5,512 个用例：`n∈{2,4,6,8}`、`a[i]∈[0,min(n,4)]` 的全部多重集合，以及每个集合的 `k∈[1,n]`。另外通过题面 5 个样例、上述 4 个反例及 4 个 `n=200000` 的阈值边界用例。有限穷举用于发现反例，完整正确性由配对策略证明支撑。
