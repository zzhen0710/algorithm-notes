# 后缀预处理：用未来摘要辅助当前决策

## 什么时候想到

数组已给定，正向处理当前位置时，反复需要知道“当前位置之后还有什么”：剩余值是否出现、右侧极值、下次出现位置、后缀 MEX 等。若不断向后扫描，就先问：

> 能否从右往左预先记录，让正向决策只读取所需信息？

这里的“后缀信息数组”指保存每个后缀的摘要，与字符串算法中的 Suffix Array（后缀排序数组）无关。

## 核心模型

先明确 `suffix[i]` 的含义，再设计从右到左的更新：

```text
明确当前决策需要的右侧信息
→ 从右往左维护该信息并保存各起点的摘要
→ 正向扫描读取摘要
→ 结合当前状态判断行动是否合法、何时完成
```

例如保存右侧最大值：

```cpp
// 非空数组；mx[i] 表示 a[i..n-1] 的最大值。
vector<int> mx(n);
mx[n - 1] = a[n - 1];
for (int i = n - 2; i >= 0; --i) {
    mx[i] = max(a[i], mx[i + 1]); // O(1) 更新当前后缀摘要
}
```

预处理 `O(n)`、每次查询 `O(1)`、额外空间 `O(n)`。其他统计要单独核算更新和存储成本，不能只因写成后缀数组就默认都是线性。

## 代表题：CF 1628A

[Meximum Array 完整复盘](../problems/CF1628A_Meximum_Array.md)每段都需要知道当前剩余后缀的 MEX。正向反复重建后缀没必要，可以从右侧只增不删地维护出现情况：

```cpp
// 题目保证 0 <= a[i] <= n；MEX 最多为 n。
vector<bool> present(n + 2, false);
vector<int> suffixMex(n);
int mex = 0;
for (int i = n - 1; i >= 0; --i) {
    present[a[i]] = true;
    while (present[mex]) ++mex; // 所有循环累计只增长 O(n) 次
    suffixMex[i] = mex;
}
```

注意：一个整数 MEX 不足以独立更新出下一个后缀 MEX，还要维护出现情况。保存每个后缀的答案，不意味着维护状态本身也是一个整数。

随后在段起点读取目标，收齐它要求的值再切割。**后缀摘要确定可争取的目标，当前过程判断目标是否已经达到。** 不能仅看到后缀 MEX 下降就切段，也不能假设贪心正确性由预处理自动保证。

## 如何迁移与选择

| 题目现象 | 可考虑记录的信息 |
| --- | --- |
| 判断某值后面还会不会出现 | 后缀计数或下一次出现位置 |
| 当前选择需要与所有右侧元素比较 | 后缀最小值/最大值 |
| 删除前缀后，反复查询剩余部分性质 | 每个后缀的对应摘要 |
| 排除某个元素后合并左右信息 | [前后缀分解](prefix-suffix-exclusion.md)，同时保存两侧 |

先找重复查询，再挑选能影响当前决策的最少状态。已有频率表或单调指针能在线性时间维护时，后缀预处理可能只是另一种组织方式，不能虚构复杂度提升。

## 适用边界

- 摘要通常基于静态原数组；只移动边界可复用，任意修改元素可能使旧摘要失效。
- 明确后缀包含当前位置还是从下一位开始，防止查询对象偏一位。
- 初始化空后缀、去重状态和多组测试；MEX 的出现状态不可在每个反向位置清零。
- 无法从摘要恢复所需信息时，要补充状态，不能直接将两个 MEX 相减来求区间 MEX。
- 预处理只加速信息获取，选择是否正确仍需题目性质支持。

> 正向决策反复依赖右侧，且数组静态？先明确摘要，再考虑反向预处理。
