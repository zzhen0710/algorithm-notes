# 二分答案：把优化与可行性判定分开

## 什么时候想到

直接求“最少时间、最小容量、最大长度”需要反复尝试，但**固定候选后，能否完成任务更容易判断**。

> **先固定答案参数，让复杂的优化问题退化为一次可行性检查；再证明判定单调，寻找真假分界。**

## 建模过程

```text
明确候选值代表什么
→ 写出 check(x) 的完整含义
→ 证明宽松条件可行、严格条件不可行的传递关系
→ 给出覆盖答案的范围
→ 独立验证 check
→ 接入二分寻找边界
```

将判定单独写成 lambda，可以只传入当前候选，捕获题目数据。它的价值在于**分清两项证明与两类错误**：

| 层次 | 需要保证什么 | 典型错误 |
| --- | --- | --- |
| 判定 | 给定候选时，返回真实可行性 | 漏项、贪心不成立、混淆至多与恰好 |
| 二分 | 根据单调结果找到正确边界 | 范围遗漏、更新方向错误、不推进 |

lambda 只是代码组织方式，不会自动带来单调性或正确性。临时计数在每次调用中重新初始化，不能沿用前一次判定状态。

## 判定 lambda 怎么写

先明确语法：**写作 `auto check = [&](ll limit) { ... };`，不是 `auto check() = ...`。** `check` 是保存 lambda 的变量，定义后通过 `check(mid)` 调用。

下面的片段放在 `solve()` 等函数内部，用简单阈值演示完整结构；`using ll` 也可放在通用框架中：

```cpp
using ll = long long;

ll need = 6; // 已在外部准备的题目数据

auto check = [&](ll limit) -> bool {
    // 固定当前候选，只判断它是否满足要求
    return limit >= need;
};

bool ok = check(5); // false；这里只进行一次判定，不会自动二分
```

| 部分 | 含义 |
| --- | --- |
| `auto check` | 保存 lambda，由编译器推导其类型 |
| `[&]` | 按引用捕获用到的外部局部变量，如数组、目标数量；不复制整个数组 |
| `(ll limit)` | 本次候选参数，按值传入；可以代表时间、容量或长度 |
| `-> bool` | 明确返回可行与否；简单写法可省略 |
| `{ ... }` | 一次判定的过程；结束后的分号不能省略 |

**`[&]` 不表示所有状态都应写在外面。** 输入数组与固定目标可以捕获，累计和、段数等临时量应在 lambda 内初始化；修改捕获变量会影响外部状态，不能因此把上一轮判定结果带入下一轮。

## 带注释的判定骨架

以下是**需要按题意填写的伪代码，不能直接编译或提交**：

```text
auto check = [&](ll limit) -> bool {
    // 1. 初始化本次候选的状态：当前和、已用数量、频次等
    当前状态 = 初始状态;

    // 2. 固定 limit，扫描数据或执行本题的判定算法
    for (每个需要处理的元素) {
        更新当前状态;

        // 3. 已能确定不可行时，可提前返回
        if (已违反且后续无法修复的约束) return false;

        // 如果目标一旦达成就不会再被破坏，也可提前 return true
    }

    // 4. 检查最终状态；不能漏掉不触发提前返回的情况
    return 最终状态满足题目要求;
};
```

提前退出必须有依据：**一时超限可能被后续负数抵消时，不能直接返回失败；后面仍可能出现新限制时，也不能过早返回成功。**

再根据候选的含义选择方向：

- **上限、时间越大越宽松：** 证明判定为 `false → true` 后，调用 `firstTrue(L,R,check)` 找最小可行值。
- **每份要求越大越严格：** 证明判定为 `true → false` 后，调用 `lastTrue(L,R,check)` 找最大可行值。

> **先填好并单独测试 `check`，再接入二分。参数名叫 `limit`，不代表判定方向一定是哪一种。**

## 来源：P1182

[数列分段复盘](../notes/02-sequence-techniques/06-binary-search-on-answer.md#92-p1182从前缀和判定到最小滚动状态)中，候选值是“每段和允许的上限”。固定上限后，先验证最少需要多少段；上限增大时，原来合法的分段仍合法，因此可以寻找最小可行上限。

这题还暴露了三个与二分配套的状态设计问题：

- **顺序处理不等于必须预处理。** 只需将下一项加入当前段时，滚动和就足够；若要反复查询不同区间、跳段或复用已有区间信息，前缀和仍有价值。
- **等于边界时先判断语义。** 本题等于上限仍合法，不必提前结算；后续加入正数导致超限时再开新段，加入零则继续保留。其他题若等号代表事件发生，仍需要单独处理。
- **计数应直接对应观察量。** 从 `cnt=1` 记录已用段数，再比较 `cnt>m`，比间接解释剩余额度更便于检查。递减计数也可以正确实现，两者复杂度相同。

## 可以迁移到哪里

| 场景 | 固定什么 | 判定什么 | 常见方向 |
| --- | --- | --- | --- |
| 多台机器并行生产 | 可用时间 | 能否完成目标数量 | 最小可行值 |
| 连续任务分组 | 每组允许的资源上限 | 能否在给定组数内安排 | 最小可行值 |
| 等量分配或材料切分 | 每份大小 | 是否能提供足够份数 | 最大可行值 |

这些场景仍需分别证明判定；资源可否拆分、是否保持顺序、是否允许负数，都可能改变算法。

## 边界与不适用情况

- 不因题面出现“最大/最小”就直接二分；判定反复真假切换时，边界搜索不成立。
- “至少、至多、恰好”不能直接替换。P1182 能从至多段数转成恰好段数，依赖非负元素、允许拆段以及段数不超过元素数。
- 判定若使用贪心、DP 或搜索，分别计入正确性证明与单次成本；二分不会自动让复杂判定变快。
- 先直接测试候选值，再测试完整搜索。小输入枚举可帮助区分“判定错”与“二分错”。
- 已有公式或单次扫描可以求解时，先比较是否还需要增加二分这一层。
