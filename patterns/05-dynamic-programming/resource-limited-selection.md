# 背包建模：使用次数、状态边界与优化目标

[本章范式索引](README.md) · [全部范式](../README.md)

有些题目不提“物品、重量、价值”，只要求安排任务、凑出金额或买够数量。先回答：**选什么、每种能选几次、下标记录什么总量、表值优化什么**。

> **背包 DP 是一组相关模型，不是只有“重量限制下最大价值”这一种。** 0/1 与完全按使用次数区分，恰好与不超过按状态约束区分，最大与最小按目标区分；这些条件可以组合。

## 1. 哪些线索值得想到背包

依次检查：

1. **有完整的选择对象**：一件物品、一次购买、一枚硬币等，每次选择带来确定的总量变化。
2. **使用次数有限制**：每件最多一次，考虑 0/1；每种任意次，考虑完全；有限多次不能直接当成无限次。
3. **状态轴能够有限枚举**：时间、重量、金额等是可累计的整数，或能转成适当整数状态；至少型还可能需要证明上界。
4. **目标能从前驱继续更新**：最大收益、最少费用、最多或最少件数等，每次增加多少要说清。
5. **状态保留了必要信息**：已处理哪些对象、当前总量等足以决定后续，不必记完整选择顺序；有额外依赖时不能省略。
6. **状态规模可接受**：普通容量写法通常为 $O(nC)$，容量数值过大就不能照搬开表。

**不可拆只提示需要考虑组合，不直接证明必须 DP。** 仍要检查贪心或枚举能否更简单地解决。比如价格非负、目标仅为最多件数且没有其他限制时，排序贪心也可能合适。

## 2. 典型模型怎样对应

表中的“状态推进量”表示一次选择让下标增加多少；“目标增量”表示写入表中的比较值增加多少。

| 模型 | 每个对象能用几次 | 状态推进量 | 目标增量 | 状态要求与优化方向 |
| --- | --- | --- | --- | --- |
| P1048 采药 | 每株一次 | 采摘时间 | 草药价值 | 时间不超过上限，最大价值 |
| P1616 疯狂采药 | 每种无限次 | 采摘时间 | 草药价值 | 时间不超过上限，最大价值 |
| 最少硬币 | 每种无限次 | 硬币面额 | 1 枚 | 恰好金额，最少枚数 |
| CF 189A 剪彩带 | 每种无限次 | 一段的长度 | 1 段 | 恰好总长，最多段数 |
| P2392 两边分担任务 | 每题一次 | 题目耗时 | 同一个耗时 | 不超过一半，最大化较轻侧承担时间 |
| P2918 购买干草 | 每种无限次 | 单包重量 | 单包价格 | 恰好重量的最小费，再在至少需求的终态中取最小 |
| 多重背包 | 每种最多给定件数 | 单件占用，或整包占用 | 单件价值，或整包价值 | 容量上限内求最大；可拆成少量 0/1 包 |

完整转移和个人实现分别在 [0/1 背包](../../notes/05-dynamic-programming/02-zero-one-knapsack.md)与[完全背包及变式](../../notes/05-dynamic-programming/03-complete-knapsack.md)，本篇只负责识别与联系。

### 有限数量：压缩转移轮数，不改变容量语义

若同一种有很多相同物品，先检查瓶颈是否在重复枚举件数。**倍增将线性枚举“选几件”，改成对 $O(\log(m+1))$ 个包分别做“选／不选”的 DP**，其中 m 是这一种的可用件数；每包继承 0/1 背包倒序更新。倍增减少轮数，数量覆盖证明保证不漏选，DP 比较组合并合并相同状态，不必显式枚举全部包组合。

**关键是保留每个原可选数量，而不是唯一表示它。** 要证明所有数量都能组合出来、任何包组合不超上限，并保持占用与价值；剩余包可以不是 2 的幂。重复表示不影响最优值，却可能让方案计数重复。

完整代码、区间接合证明及规模估算见 [5.10 多重背包](../../notes/05-dynamic-programming/10-bounded-knapsack.md#4-13-件怎样拆为什么所有件数都能选到)。这与滚动数组减少存储维度不同，优化的是转移轮数。若还需进一步减少候选比较，可尝试[同余分组后的单调队列转移](../../notes/05-dynamic-programming/11-monotonic-queue-dp.md)，但须单独推导固定分数与合法窗口。

### 正占用与有限容量：无限次也有有效上限

容量为 C、单次占用 w 为正时，任何合法方案的使用次数都不超过 $\lfloor C/w\rfloor$。因此可把无限次转换成这个有限上限，再复用多重背包；**统一了输入语义，不代表这种实现一定比完全背包正序更快**。

这类转换要先解释输入标志，例如原题用 0 表示无限次，而通用函数用 0 表示没有物品。实例见 [P1833 的次数适配](../../notes/05-dynamic-programming/10-bounded-knapsack.md#无限次为什么也能交给多重背包)。

### 同组互斥：把整组当作一个处理阶段

如果多个方案来自同一类决策，且至多只能采用一种，先把它们组织为同一组。**组内是多个候选竞争一个最优结果，组与组之间才继续累积。**

1. 状态保存已经处理哪些组、资源上限内的最优值。
2. 同组每个候选都从此前组的状态出发；允许不选时，再保留不选本组的方案。
3. 压缩时检查读取的前驱是否仍是旧组：保留 old 最直接；一维原地用组→容量倒序→候选，当前格先暂存 best 再写回。
4. “每组必须选一个”要取消不选分支并标出不可达；它不意味着资源必须用满。

代码与零占用边界见 [5.12 分组背包](../../notes/05-dynamic-programming/12-group-knapsack.md#4-为什么能省掉-old先证明读写再压缩)。本轮只补同组互斥，不扩展依赖背包或把组阶段误认为多维费用。

## 3. cost / value 不必是两个不同数

在常见最大价值写法中，`cost` 是推进容量下标的占用，`value` 是每次增加的价值。但这只是常用命名，**不能只凭字段名决定谁作下标、谁拿来取最优**。

常见情况包括：

- **两个数不同**：花多少时间，得到多少价值。
- **两者相同**：任务占用时间 $t$，也让选中的一侧多承担 $t$ 的工作；对应最大可选子集和。
- **目标增量恒为 1**：每次选一枚或一段，分别求最少枚数或最多段数。
- **目标是费用而非收益**：重量推进状态，价格累加到表值，最后取最小。

所以“有限资源寻找最多”里的最多，不一定是最多件数；还可能是最大价值、最多已承担时间。改成最小化时，也不是更换一套完全无关的算法，而是重新确认状态与比较方向。

**常量 1 表示每次选择使计数增加 1**，不是把某个输入字段机械删掉。最少硬币与剪彩带恰好体现同一状态骨架、不同优化目标。

成本与收益同为非负数 $t$ 时，若 `dp[j]` 表示上限内最大可选总和，则 `dp[j] <= j`。普通背包中收益与容量单位不同，不能这样比较。

## 4. 容量上限与实际选择

固定已经处理的物品，定义 `dp[j]` 为**总占用不超过 `j` 时的最大收益**。

容量从 $j-1$ 增加到 $j$ 时，原来合法的子集仍然合法，只可能增加新候选，不会失去旧候选。因此：

$$
dp[j]\ge dp[j-1].
$$

查询 `dp[C]` 已覆盖所有占用不超过 $C$ 的方案，**不需要找到某个“恰好用满”的容量，也不用再枚举所有 `dp[j]` 取最大值**。

例如只有一个占用 3、收益 3 的元素，容量为 4 时，`dp[4] = 3` 完全合法。

但不能把这条单调性推广到恰好状态：只有一件占用 2 的物品时，恰好 2 可行，恰好 3 不可行。买干草时，恰好重量更大也可能更便宜，**最先达到需求的重量不一定有最小费用**。

上限不必恰好可达，但必须由题意或证明给出；不能随意放大上限后仍沿用原来的答案关系。两边分担任务中的一半上限，正是由较轻侧定义推出来的，见 [P2392 复盘](../../notes/05-dynamic-programming/02-zero-one-knapsack.md#82-洛谷-p2392kkksc03-考前临时抱佛脚)。

## 5. 三项条件分别决定什么

| 判断项 | 主要影响 |
| --- | --- |
| 每件一次或每种无限次 | 转移读取上一轮还是当前轮；物品在外层时，一维容量倒序或正序 |
| 不超过、恰好或至少 | 状态定义、合法起点、不可达表示、最终答案范围 |
| 最大、最小或可行性 | 每次目标增量、取 `max`、`min` 或逻辑判断，以及哨兵选择 |

基本检查顺序：

1. **先写目标**，必要时用总量关系转化，不能只凭题目名字套算法。
2. **列出每次选择的两种作用**：状态增加多少，目标数值增加多少。
3. **把状态写成完整句子**，包括已经处理哪些对象、下标是上限还是恰好总量。
4. **由语义确定初值**：合法零值与不可达不同，恰好状态不能随意继承前一个位置。
5. **按依赖安排计算**：检查读取时前驱属于哪一轮；优化值的不同循环组织见[完全背包与剪彩带对照](../../notes/05-dynamic-programming/03-complete-knapsack.md#7-和-cf-189a-的外层顺序对照)。
6. **回到原题读取答案**：DP 可能算中间量；要求至少满足时也可能需要比较多个终态，不能把最早与最优混为一谈。

至少型若上方状态无限，可尝试[利用最优性证明状态上界](optimality-state-bound.md)，再核对所证范围是否适合枚举。

## 6. 什么时候还不能直接用

- **多项资源、先后依赖、同组互斥**：需要把额外约束纳入模型，不是普通单容量转移就能表达。
- **目标不是可直接累加的量**：先检查状态是否保留了必要信息，不能只改成 `max` 或 `min` 就认定正确。
- **改为统计方案数**：循环层次可能改变是否区分顺序，计数初值也有含义，不能直接照搬最优化模型。
- **状态范围过大或存在负的推进量**：需要重新选状态与计算顺序，不能沿用正占用的数组范围。

真正要统一的是**建模时的检查步骤**，并不是强行维护一个适用于所有题目的万能模板。
