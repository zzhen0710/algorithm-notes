# 记忆化搜索与数组递推：同一状态，怎样安排计算

[本章范式](README.md) · [全部范式](../README.md)

## 先识别：两者都在做 DP

已经定义了“当前位置／已处理范围＋必要条件”，而多个历史会来到相同状态时，可以选择记忆化 DFS，也可以按依赖顺序填写数组。

**先确定状态和转移，再选择执行方式。** 递归不会自动减少状态维度，循环也不会自动消除重复计算；关键是相同的后续问题只算一次。

## 横向对照：参数、缓存与循环各对应什么

以[数位和余数统计](../../notes/05-dynamic-programming/09-digit-dp.md#dfs-与三维递推逐项对应)为例，`dfs(pos,rem,tight)` 返回：已经填写 pos 位、数位和余数为 rem、上界限制为 tight 时，剩余位置的合法填法数。

| 记忆化写法 | 保持同一含义的数组递推 | 职责 |
| --- | --- | --- |
| `dfs(pos,rem,tight)` | `dp[pos][rem][tight]` | 完整状态有三个分量 |
| 递归调用 `dfs(pos+1,...)` | 先算完 `dp[pos+1]`，再算 `dp[pos]` | 保证依赖已经得到结果 |
| 根据需要进入某个状态 | 三层循环枚举 pos、rem、tight | 选择这次要计算哪个状态 |
| 函数内 `for (d=0; d<=up; ++d)` | 最内层仍枚举 d | 选择本位数字，确定下一状态 |
| `ways += dfs(...)` | `dp[pos][rem][tight] += dp[pos+1][...]` | 合并不同选择的结果 |
| 填完时 `return rem==0` | 初始化 `dp[n][0][0/1]=1` | 结束条件变成数组边界 |

**枚举 d 是转移循环，不是额外的状态维度。** 缓存只有 `memo[pos][rem]`，则是因为本实现仅缓存 tight=false；这个条件固定了，不代表完整问题只有两个分量。

```mermaid
flowchart LR
    A["当前状态 pos, rem, tight"] -->|"选择本位 d"| B["后继 pos+1, next_rem, next_tight"]
    B -->|"DFS：需要时递归求后继\n递推：先填好后继这一层"| C["取回结果，累加到当前状态"]
```

### 先比较状态句，才能比较中间值

上表保持了“从当前状态出发，剩余有多少填法”的含义，所以递归返回值与数组项可以逐项对应。

也可定义前向 DP：“已经填完 pos 位，到达 rem、tight 的前缀有多少个”，按 pos 递增传播。**它统计到达当前的前缀，DFS 统计从当前出发的后缀，中间值通常不相同。** 两者最终答案可以相同，但初值、转移方向和答案位置要各自配套，不能只把递归名字改成 dp。

## 如何选择

| 题目中最明显的结构 | 优先考虑 | 理由与代价 |
| --- | --- | --- |
| 数位选择，上界、前导零、上一位等条件较多 | 记忆化 DFS | 一层放一位，合法性、下一状态、结束判断可放在一起；改条件较直接 |
| 规则网格、背包、序列，依赖顺序容易写清 | 数组递推 | 循环直接体现顺序，常可滚动压缩，也没有调用栈 |
| 高度严格下降等隐式 DAG，依赖不按坐标排列 | 记忆化 DFS | 可顺着依赖按需计算，省去另排状态顺序；仍需保证无环 |
| 长链树或很深的依赖 | 显式顺序递推／显式栈 | 避免递归栈过深；先获得顺序，再按依赖计算 |
| 绝大多数状态都会用到、层数规则，或需多次复用整张表 | 数组递推 | 建表范围清楚；复用仍需核对上界、参数和状态含义是否一致 |

数位 DP 的数组版并不天然更难：简单计数状态往往直接用“位置、条件、tight”三维。困难主要在于**必须明确循环范围、初值、依赖方向，以及压缩后哪些值已经更新**；条件增加时还要继续表达对应维度。DFS 把一部分计算顺序交给调用关系，但没有免除状态设计。

两者时间通常都可按“可计算的状态数 × 每个状态的转移数”估算。DFS 能按需访问状态，但若仍预先创建完整二维表，内存并不会只按实际访问数计算；数组递推也可以跳过不可达状态或压缩层。

## 转换时的检查顺序

1. 用完整句固定状态含义，确认保留的信息足以决定后续问题。
2. 把 DFS 参数对应到数组下标；缓存省略的量，要说明是否固定、可推导或不参与缓存。
3. 把递归结束判断变成边界，把“选择下一步”的循环原样保留为转移循环。
4. 根据依赖确定遍历方向，再决定是否滚动压缩；不要先省维度再补语义。
5. 分别估算表容量、转移次数、递归深度；缓存与输入参数的生命周期也要一致。
