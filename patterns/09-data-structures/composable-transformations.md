# 统一变换，按顺序复合

[本章范式索引](README.md) · [全部范式](../README.md)

来源：[9.7 懒标记的乘加与翻转复盘](../../notes/09-data-structures/07-lazy-segment-tree.md#9-典题与复盘)。本篇保留通用推导，完整线段树实现与题目边界留在原笔记。

> **多种操作交替发生，顺序又影响结果时，尝试把它们写成同一类变换，再维护复合后的少量参数。**

## 1. 识别：难点是操作顺序与历史变长

区间加可以累加增量，但乘法一出现，先前累计的加数也会改变。若逐条保存历史，再在查询时重放，操作越积越多，不能保证单次处理仍然快。

**需要保存的是历史操作合起来的效果，不一定是操作列表本身。**

## 2. 先给复合代码，再推导它为何成立

下面只演示**模意义下的两参数复合**，不是完整线段树。参数均已规范到 `[0,mod)`，`1≤mod≤10⁹+9`，乘加可用 ll 安全计算。

```cpp
using ll = long long;

struct Transform {
    ll mul;
    ll add;
};

// 先做 old，再做 next：next(old(x))。
Transform compose(const Transform& old, const Transform& next, ll mod) {
    return {
        next.mul * old.mul % mod,
        (next.mul * old.add + next.add) % mod
    };
}
```

取模只限制数值，不改变“新操作作用于旧结果”的顺序。复合的第一个参数是旧操作，第二个是新操作；使用其他库时先核对接口，不能只凭函数名猜方向。数学上的恒等参数为 `(1,0)`，若按本函数契约存成模内代表元，则使用 `(1%mod,0)`。

### 例子：顺序改变，加法部分也会改变

$$
\text{先加 3 再乘 2}:\quad 2(x+3)=2x+6.
$$

$$
\text{先乘 2 再加 3}:\quad 2x+3.
$$

**结果不同，但都能表示为 ax+b。** 关键不是分类讨论所有相邻操作组合，而是先找到统一表达。

```mermaid
flowchart LR
    X["原值 x"] --> F["旧变换 f：ax+b"]
    F --> G["新变换 g：cx+d"]
    G --> R["合成：ca·x + cb+d"]
```

## 3. 统一表示，再证明复合后仍能表示

| 操作 | 变换 | 参数 |
| --- | --- | --- |
| 加 d | x+d | `(1,d)` |
| 乘 k | kx | `(k,0)` |
| 赋值 c | 0x+c | `(0,c)` |
| 不操作 | x | `(1,0)` |

旧变换与新变换分别是：

$$
f(x)=ax+b,\qquad g(x)=cx+d.
$$

按实际顺序复合：

$$
g(f(x))=c(ax+b)+d.
$$

展开得到：

$$
g(f(x))=(ca)x+(cb+d).
$$

**复合后仍是同样的两参数形式**，所以无论经历多少次操作，都能压缩成一对参数。这叫对复合封闭；赋值时旧历史被新常量覆盖，也由系数 0 自然实现。

函数复合满足结合律，可以逐步合并；**通常不满足交换律**，所以不能随意排序操作。

## 4. 用于区间维护，还要推导聚合值如何改变

能压缩单个元素的修改，还不足以保证能做懒标记。节点摘要也必须支持快速更新。

设一段长度为 L、总和为 S，每项都做 `cx+d`：

$$
S'=cS+dL.
$$

**总和与长度已足够，无须逐项读取。** 更新摘要、复合标记分别负责当前节点正确与后续下传正确，不能只做其中一件。

而且更新与合并要一致：两段分别更新后相加，应当等于先合并再更新。具体检查与 push 时间顺序见 [P3373 复盘](../../notes/09-data-structures/07-lazy-segment-tree.md#91-洛谷-p3373线段树-2)。

## 5. 同一思路，不一定最终保留两个参数

01 值翻转写为 `1-x`。连续翻两次：

$$
1-(1-x)=x.
$$

因此所有翻转历史只有“恒等／翻一次”两种效果，保存奇偶即可；没有必要为了统一表示，强行保留通用乘加结构。完整计数更新见 [P2574 复盘](../../notes/09-data-structures/07-lazy-segment-tree.md#92-洛谷-p2574xor-的艺术)。

线段树之外，连续坐标变换、重复执行一组操作、顺序处理修改指令，也可以先检查是否能维护复合效果；**只是在这里，合成结果保存于懒标记**。

### 翻转历史的奇偶性，也能用异或差分维护

[P10722 子树翻转](../../notes/06-graph-and-tree/07-dfs-order.md#92-p10722子树区间上的异或差分)先把子树映为数组区间，再在两个端点记录异或标记，全部操作后统一还原。

核心仍是**历史效果可以压缩为一个奇偶位**。翻转两次回到原状态，所以相同边界标记再次出现，也会相互抵消：

$$
1\oplus1=0,\qquad x\oplus0=x.
$$

左端切换一次，右端之后再切换一次；前缀异或让影响只留在区间内。真值表与还原图在原题维护，不复制完整代码。

**压缩操作历史，与如何组织这些效果，是两层选择。** 即时区间计数可用懒标记；最终统一输出可用异或差分，单次记录 O(1)、还原 O(n)。异或可交换且每个标记是自己的逆；不要据此推断普通乘加等有序复合也能直接做同样的两个端点标记。

## 6. 迁移时的检查顺序

1. **列操作与顺序。** 哪些操作会改变此前积累的效果？
2. **找统一表示。** 函数、矩阵或少量参数，是否能覆盖所有允许操作？
3. **推导新接旧。** 复合后是否仍能用同一类表示？计算是否足够快？
4. **检查摘要。** 整段结果能否直接更新？所需长度或其他信息是否已保留？
5. **核对边界。** 恒等操作、清空／覆盖、抵消、取模与溢出分别怎样处理？

并非所有操作都属于 `ax+b`，也不是所有函数复合都能压成常数个参数。**真正可迁移的是寻找可快速复合的变换表示，再验证它能否更新所需信息。**
