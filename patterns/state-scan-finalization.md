# 状态扫描：变化时结算与尾状态处理

## 什么时候想到

遍历中维护“当前尚未结算的一段”，只有数值变化、区间断开或读到分隔符时才把结果写出。这时要检查：**输入结束是否会留下没有被触发结算的状态？**

典型场景包括连续段统计、游程编码、合并相交区间，以及逐字符读取最后一个没有分隔符的字段。

## 核心模型

```text
读入元素 → 扩展当前状态
遇到变化 → 结算旧状态，再开启新状态
正常结束 → 结算仍未处理的最后状态
```

例如 `1 1 2 2 2`，读到第一个 `2` 时会结算两个 `1`；但最后三个 `2` 后面没有新元素，不能等下一次变化。

## 写法一：显式结算最后一段

下面统计相邻相同元素的连续段。若目标是全局频率，需要先排序或使用频率表；不能把一般序列中的连续段长度当成全局出现次数。

```cpp
vector<pair<int, int>> runs(const vector<int>& a) {
    vector<pair<int, int>> result;
    if (a.empty()) return result;  // 初始化前处理空输入

    int value = a[0], count = 1;
    for (size_t i = 1; i < a.size(); ++i) {
        if (a[i] == value) {
            ++count;
        } else {
            result.emplace_back(value, count);  // 结算旧段
            value = a[i];
            count = 1;
        }
    }
    result.emplace_back(value, count);  // 正常结束，结算最后一段
    return result;
}
```

不变量：处理完当前元素后，`value、count` 描述唯一尚未写入结果的末尾连续段。循环外的结算对应的正是这一段。

## 写法二：在每轮内部找到完整段

```cpp
vector<pair<int, int>> runs(const vector<int>& a) {
    vector<pair<int, int>> result;
    for (size_t i = 0; i < a.size(); ) {
        size_t j = i;
        while (j < a.size() && a[j] == a[i]) ++j;
        result.emplace_back(a[i], static_cast<int>(j - i));
        i = j;
    }
    return result;
}
```

这里每一轮都会结算完整的 `[i,j)`，包括最后一段，**不应再在循环外重复结算**。两种写法时间均为 `O(n)`，输出占用 `O(段数)` 空间，除输出外辅助空间为 `O(1)`。

## 检查清单与适用边界

- 空输入：不能直接读 `a[0]` 或 `back()`。
- 单元素、所有元素相同：完全没有变化事件，仍须生成一个结果。
- 每个元素都不同：每段恰好结算一次。
- 提前 `break`：区分“已找到结果”和“正常到达末尾”，避免补结算覆盖答案。
- 使用哨兵：必须保证哨兵不会与合法数据混淆，且不能为触发分支而越界读取。
- 滑动窗口、双指针只是实现手段，不代表必然需要尾结算；判断依据是循环结束后是否仍有待提交状态。

## 在 MEX Game 中的经验

[CF MEX Game](../problems/CF_MEX_Game.md) 的编写过程带来了尾状态处理经验，但提供的 WA 版本已包含尾段判断。它实际错在漏查未出现整数，见 [MEX 分析](mex-analysis.md)。

连续段扫描只能告诉我们已有元素如何分段；即使每一段都正确结算，也不能自动检查不在数组中的 `0` 或中间空缺。

## 触发器

> 只在变化时提交状态，就检查正常结束时还有没有待提交状态；每段已经在循环内完整处理，就不要重复补结算。
