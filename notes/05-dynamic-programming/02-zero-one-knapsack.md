# 5.2 0/1 背包：每件最多选一次

前置：[DP 入门](01-dp-basics.md)。上节已经区分了合法方案与不可达状态，这节增加一个限制：**每件物品最多只能选一次**。

“0/1”指每件物品只有**不选、选一次**两种决定，与位运算无关。

## 1. 解决什么问题

有 $n$ 件物品，第 $i$ 件占用容量 $w_i$，提供价值 $v_i$。总容量为 $C$，可以不选物品，求**总占用不超过 $C$ 时的最大总价值**。

这里的“容量”也可以是预算、时间等限制；先看清每件能选几次，再判断是否属于本模型。

> **选价值最大、最便宜或单位容量价值最高的物品，都不能直接代替证明。** 物品不能拆开时，当前选择可能占掉后面更合适的组合所需的容量。

例如容量为 4，两件物品的“占用、价值”为 $(2,3)$、$(3,4)$。优先选更便宜、单位容量价值更高的第一件，只能得到 3；选择第二件则得到 4。

这与[按便宜顺序最大化件数](../04-greedy-and-construction/01-sorting-greedy.md#5-怎样检验一个贪心想法)不同：**目标从件数变成价值，原贪心依据就不能照搬**。

## 2. 为什么要记录“已经处理了哪些物品”

如果只说“容量为 $j$ 时的最大价值”，还没有交代**允许从哪些物品中选择**。

每件最多选一次，因此按固定顺序处理物品。计算第 $i$ 件时，先只考虑前 $i-1$ 件的结果，再决定是否加入这一件。

定义：

$$
dp[i][j]=\text{只从前 }i\text{ 件物品中选择，总占用不超过 }j\text{ 的最大价值。}
$$

两个下标分别保留不同的信息：

- **`i` 限定能用哪些物品**：只用前 `i` 件；之后还没处理的物品留给后面的计算。
- **`j` 限定能用多少容量**：允许少用，不要求用满。

这样第 $i$ 件只在这一轮决定选或不选，不能在同一轮反复加入。

### 变量、容器与范围

| 变量 | 含义与范围 |
| --- | --- |
| `items` | 原物品数组，**0-based**；每个数组位置是一件物品 |
| `items[i - 1]` | DP 第 `i` 轮处理的物品；轮次为 $1\ldots n$ |
| `cost`、`value` | 该物品的容量占用与价值；占用为正整数，价值非负 |
| `capacity` | 总容量 $C$，为非负整数 |
| `dp[i][j]` | 已处理前 `i` 件、容量上限为 `j` 的最大价值 |
| 第 0 行、第 0 列 | 不使用任何物品；或容量为 0，均可取空方案 |

二维表需要 **`n + 1` 行、`C + 1` 列**，按物品件数与容量上限分配，不按物品价值大小分配。

教学实现约定 $n\le200$、$C\le5000$，每件占用可用正 `int` 表示、价值不超过 $10^9$。总价值用 `ll`，避免累计后超过 `int`；实际题目要重新核对范围。

## 3. 按最后一件物品分类，推出转移

计算 $dp[i][j]$，只需讨论第 $i$ 件选不选。

### 不选第 i 件

仍然只能从前 $i-1$ 件里选，容量上限不变，候选值为：

$$
dp[i-1][j].
$$

### 选第 i 件

必须先留出 $w_i$ 的容量，所以只有 $j\ge w_i$ 才能选择。

剩下的容量上限是 $j-w_i$，其余物品只能从前 $i-1$ 件里选，候选值为：

$$
dp[i-1][j-w_i]+v_i.
$$

两类覆盖所有合法方案，取较大值：

$$
dp[i][j]=\max\bigl(dp[i-1][j],dp[i-1][j-w_i]+v_i\bigr)
\qquad(j\ge w_i).
$$

若容量不足，只能不选。

**两个来源都必须来自上一行。** 如果选取的来源已经用过第 $i$ 件，再加一次就违反了“每件最多一次”。

### 初值与答案

- `dp[0][j] = 0`：没有物品时，可以选空方案，最大价值为 0。
- `dp[i][0] = 0`：物品占用都为正，容量为 0 时只能不选。
- 返回 `dp[n][C]`：允许使用全部物品，总占用不超过总容量。

这里**每个容量上限都存在空方案**，所以填 0 合法。它与[恰好拼出彩带长度](01-dp-basics.md#8-典题与复盘)的初始化不同。

## 4. 先写二维，直接对应状态定义

```cpp
using ll = long long;

struct Item {
    int cost; // 占用的容量，必须为正
    ll value; // 选择这件物品得到的价值
};

// 采用本节范围，允许空数组和容量 0
// 返回总占用不超过 capacity 的最大价值，不修改输入
// 每次调用重新初始化，物品编号为 0-based，DP 轮次为 1-based
ll knapsack01_2d(const vector<Item>& items, int capacity) {
    int n = static_cast<int>(items.size());
    vector<vector<ll>> dp(n + 1, vector<ll>(capacity + 1, 0));

    for (int i = 1; i <= n; ++i) {
        const auto& cur = items[i - 1];

        for (int j = 0; j <= capacity; ++j) {
            dp[i][j] = dp[i - 1][j]; // 不选当前物品

            if (j >= cur.cost) {
                // 留出当前物品的容量，其余只从前 i - 1 件中选
                dp[i][j] = max(dp[i][j],
                               dp[i - 1][j - cur.cost] + cur.value);
            }
        }
    }

    return dp[n][capacity];
}
```

执行流程：

1. 建立全为 0 的表，表示当前只能选空方案。
2. 外层依次处理每件物品，内层枚举容量上限。
3. 先保留不选的结果，再比较选当前物品的结果。
4. 完成这一行后，下一件物品才能使用这一行的结果。
5. 全部物品处理完，读取最大容量对应的状态。

由于**读上一行、写当前行**，二维实现中容量从小到大或从大到小都可以；重要的是来源行没有改变。

### 小例子：每行多开放一件物品

容量为 4，物品依次为 $(2,3)$、$(3,4)$：

| 已处理物品 | 容量 0 | 容量 1 | 容量 2 | 容量 3 | 容量 4 |
| --- | --- | --- | --- | --- | --- |
| 0 件 | 0 | 0 | 0 | 0 | 0 |
| 第一件后 | 0 | 0 | 3 | 3 | 3 |
| 第二件后 | 0 | 0 | 3 | 4 | 4 |

容量为 4 不一定要用满，所以最后一个 4 来自只选第二件；两件一起需要容量 5，不合法。

**正确性**：第 0 行符合定义。若上一行已正确，当前方案要么不包含第 $i$ 件，要么包含它且其余选择来自前 $i-1$ 件；分别取各类最优值，再比较即可得到当前最优值。

时间复杂度 $O(nC)$，空间复杂度 $O(nC)$。

## 5. 压成一维：为什么容量必须倒序

每一行只依赖上一行，不需要一直保存所有旧行。用一个数组复用空间：

- 一轮开始前，`dp[j]` 保存**只用前 `i - 1` 件物品**的结果。
- 这一轮结束后，`dp[j]` 保存**只用前 `i` 件物品**的结果。

**省略的是存储中的行号，不是“已处理哪些物品”的含义。** 外层物品循环仍然负责这层限制。

### 正序为什么会重复使用当前物品

只有一件物品 $(2,3)$，容量为 4。若从小到大更新：

1. 容量 2 读取旧 `dp[0]`，写成 `dp[2] = 3`。
2. 容量 4 随后读取**这一轮刚改过的 `dp[2]`**，写成 `dp[4] = 6`。

只有一件物品，却取了两次。问题发生在**读取了当前轮的结果**。

### 倒序怎样保证只使用上一轮

从大容量往小容量更新时，$j-w_i<j$。当前还没处理到更小的容量，所以**读取的 `dp[j - w_i]` 仍然来自上一轮**。

同一个例子，先处理容量 4，此时 `dp[2]` 仍是 0，因此得到 3；之后再更新容量 2，不会反过来改变已经算完的容量 4。

> **物品在外层，容量从大到小：让本轮每次选取都接在“还没用过当前物品”的旧结果后面。** 先理解读取哪个阶段的值，再记循环方向。

```cpp
// 复用上面的 Item；输入范围、返回值与二维实现相同
// 主写法：每件最多选一次，总占用不超过 capacity
ll knapsack01(const vector<Item>& items, int capacity) {
    vector<ll> dp(capacity + 1, 0);

    for (const auto& cur : items) {
        for (int j = capacity; j >= cur.cost; --j) {
            // dp[j] 原值是不选；较小容量尚未更新，仍是上一轮结果
            dp[j] = max(dp[j], dp[j - cur.cost] + cur.value);
        }
    }

    return dp[capacity];
}
```

每件物品访问的容量不超过 $C$ 个，时间复杂度 $O(nC)$，空间降为 $O(C)$。每次调用新建数组，不保留上一组数据。

本节推荐先手推二维，再独立写一维；以后熟悉后直接使用一维主写法。

## 6. “不超过容量”与“恰好装满”别混用

| 状态要求 | 空方案在哪些状态合法 | 非起点的初始化 | 最后读取什么 |
| --- | --- | --- | --- |
| 总占用不超过 `j`，求最大价值 | 每个容量上限都可以不选 | 可以填 0 | 总容量上限对应的最优值 |
| 总占用恰好为 `j`，求最大价值 | 只有总占用 0 时合法 | 不可达标记；前驱可达后才更新 | 恰好总容量对应的值，可能无解 |

同样的转移外形，**状态中的“不超过”或“恰好”不同，初值含义就不同**。

后一种若价值非负，可用 `-1` 表示不可达；允许负价值时需另选表示。具体判断见[合法零值与不可达](01-dp-basics.md#6-初值不只是填一个数组)。

是否要求恰好装满，与每件能用几次是两项独立条件。**改成恰好装满，并不会让 0/1 背包变成完全背包**；每件仍然只能用一次，容量仍需倒序。

### 容量是上限，不代表一定会用满

固定已经处理的物品，按“不超过容量”的定义，有：

$$
dp[j]\ge dp[j-1]\qquad(j\ge1).
$$

**容量多给一点，原来能选的方案仍然能选，所以最优价值不会变小。** 但价值也不一定增加，更不代表实际占用等于容量。

例如只有一件占用 3、价值 3 的物品，容量为 4 时，`dp[4] = 3` 完全合法，剩下 1 不使用即可。无需先找到“恰好能用完”的容量再查询。

这个结论仅针对**同一批物品、容量不超过上限**的状态。恰好装满的状态可能在更大容量处不可达，不能照搬；上限也必须符合原题约束，不能随意放大。进一步说明见[背包识别范式](../../patterns/05-dynamic-programming/resource-limited-selection.md#4-容量上限与实际选择)。

## 7. 范围与易错点

- **容量不能太大。** 复杂度取决于容量数值 $C$，而不只是物品件数。若 $C$ 达到 $10^9$，不能照搬按容量开表；后续按值域和题目性质选择其他状态或方法。
- **超过容量的物品可以自然跳过。** 一维内层循环不会进入，无须据此判整题无解。
- **不需要先排序。** 按输入顺序逐件处理即可，DP 会比较所有合法选择。
- **相同物品不一定是同一件。** 输入有两件相同占用、相同价值的物品时，两件各能用一次，不应随意去重。
- **不要沿用彩带题的重复选择含义。** 彩带的三种长度可以反复使用；本题输入的每一件只能选一次。[完全背包](03-complete-knapsack.md#3-压成一维为什么改为正序)进一步对照循环方向。
- **容量是上限，不是实际占用。** 本节 `dp[C]` 已经允许没装满，无须另枚举所有容量再取最大值。
- **代码不返回选中的物品编号。** 要输出方案，需另行保存选择依据，不能只凭最终一维数组随意反推。

## 8. 典题与复盘

### 8.1 洛谷 P1048：采药

[题目链接：P1048 采药](https://www.luogu.com.cn/problem/P1048)

**收录原因**：把“限制总资源、最大化收益”的文字描述对应到背包状态，落实每件只用一次与容量上限的含义。

#### 模型与原实现

总时间 $1\le T\le1000$，草药数量 $1\le M\le100$，单株采摘时间、价值均在 $[1,100]$。每株最多采一次，总时间不超过上限，求最大总价值。

原实现中：

- `v` 按草药数量分配，采用 **0-based**，`first` 是时间，`second` 是价值。
- `dp[i]` 是**总采摘时间不超过 `i` 时的最大价值**，下标为 $0\ldots T$，按时间上限分配 `T + 1` 项。
- 每株只处理一轮，时间倒序更新，避免重复采同一株。

以下只整理排版与注释，保留原逻辑；`pii` 等别名沿用[竞赛基础模板](../../templates/cpp-contest-template/README.md)。

```cpp
void solve() {
    int t, n;
    cin >> t >> n;

    vector<pii> v(n);
    for (auto& x : v)
        cin >> x.first >> x.second;

    vector<int> dp(t + 1);

    for (auto const& cur : v) {
        for (int i = t; i >= cur.first; --i) {
            // 不选当前草药，或从尚未使用它的结果中留出采摘时间
            dp[i] = max(dp[i], dp[i - cur.first] + cur.second);
        }
    }

    cout << dp[t] << '\n';
}
```

#### 核心依据与权衡

**每株不可重复采摘 → 每轮只决定当前草药选不选 → 倒序读取上一轮的结果。** 最终 `dp[t]` 已经包含没用满时间的方案，无须另取所有容量的最大值。

总价值不超过 $100\times100=10000$，`int` 足够。时间复杂度 $O(MT)$，额外空间 $O(M+T)$，其中状态数组为 $O(T)$。

原方案已经是合适的一维写法，推荐保留；不为增加第二份代码改成更重的封装。

**核验与状态**：原实现本地核验通过，复盘完成；平台评测结果未单独记录。

### 8.2 洛谷 P2392：kkksc03 考前临时抱佛脚

[题目链接：P2392 kkksc03 考前临时抱佛脚](https://www.luogu.com.cn/problem/P2392)

**收录原因**：把“让两边尽量均衡”转成“在合法上限内尽量多选”，理解成本与收益可以来自同一个数，以及上限不必恰好可达。

#### 题目与思路来源

四科分别有 $1\ldots20$ 道题，每题耗时 $1\ldots60$。两个大脑可以同时处理**同一科**的不同题目，各科必须依次复习，求全部完成的最短时间。

每道题必须完整交给其中一个大脑。思路来源：参考讨论中的第一份解答，再按理解完成原实现；平台 AC 依据为个人反馈。

#### 第一步：先排除“直接均分”与局部均衡

如果任务能任意拆开，两边各分一半就好。但题目不能拆分：总时间相同，不代表能拼出一半。

例如耗时为 $3,3,3$，总和是 9。理想下界为：

$$
\left\lceil\frac{9}{2}\right\rceil=5.
$$

实际只能分成 3 和 6，最短完成时间为 6。**除以 2 得到的是理论下界，不一定是可实现的答案。**

“每次把下一题交给当前较空的一侧”也不能保证最优。讨论中的序列 $4,3,3,2,2$，这样依次分配会得到 8 和 6；实际可以分成 $4+3=7$ 与 $3+2+2=7$。

这些反例说明需要保留不同组合，不能只维护一组当前分配。**不可拆是识别线索，但仅凭不可拆还不能断言必须使用 DP。** 接下来还要检查选择次数、目标转化与数据规模。

#### 第二步：先把目标写成式子

固定一科，总耗时为 $S$，两个大脑承担的时间为 $L,R$：

$$
L+R=S.
$$

两个大脑并行工作，完成这一科要等较忙的一侧结束，耗时为 $\max(L,R)$。

左右大脑可以互换，不妨让 $L$ 表示较轻的一侧，则：

$$
L\le R
\quad\Longrightarrow\quad
2L\le S
\quad\Longrightarrow\quad
L\le\left\lfloor\frac{S}{2}\right\rfloor.
$$

另一侧承担剩下的任务，所以：

$$
\max(L,R)=R=S-L.
$$

$S$ 已固定，**最小化完成时间，就变成在不超过一半总耗时的条件下，最大化较轻一侧的实际耗时**。

#### 第三步：把“最多能分担多少”对应到背包

给较轻一侧挑选一个任务子集：

| 背包含义 | 本题对应 |
| --- | --- |
| 一件物品 | 一道完整题目 |
| 最多选一次 | 一道题只能交给一个大脑，不能重复分配 |
| `cost` | 这道题占用较轻一侧的时间 $t$ |
| `value` | 选择后，较轻一侧多分担的时间 $t$ |
| 容量上限 | $\lfloor S/2\rfloor$ |
| 优化目标 | 较轻一侧实际承担的时间尽量多 |

因此 **`cost = value = t`**。两者扮演不同角色：一个限制能不能放，另一个衡量放进去以后有多好；数值不必不同。

每道题只选一次，得到 0/1 背包。每科最多 20 道题、总时间最多 1200，容量最多 600，枚举规模足够小。

#### 第四步：为什么查询上限就够，不必恰好达到一半

状态定义为：**已处理题目中，总耗时不超过 `i` 的子集，最多能承担多少时间**。

仍以 $3,3,3$ 为例，背包上限是 $\lfloor9/2\rfloor=4$：

| 容量上限 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 最多能承担的时间 | 0 | 0 | 0 | 3 | 3 |

虽然拼不出 4，但容量 4 允许选择实际耗时 3 的方案，因此 `dp[4] = 3`。本科答案自然为 $9-3=6$。

> **`dp[cap]` 回答的是“最多给这么多资源，最好能做到多少”，不是“必须刚好用这么多”。** 上限可以有剩余，不必先调整成某个可达值。

这里的一半是由“较轻一侧”推导出的**合法上限**，并非随意估计。若擅自放大到超过一半，选出的任务可能已属于较重一侧，原先直接用 $S-dp[cap]$ 的答案关系就不再成立。

#### 原 AC 实现

以下只调整排版与注释，保留函数签名、变量和原逻辑。

```cpp
// t 存单科每道题的耗时；cap 是较轻一侧的合法时间上限
// dp[i]：已处理题目中，总耗时不超过 i 时最多能承担多少时间
// 返回值可能小于 cap；函数不修改 t，每次调用重新建立状态
int gett(vector<int>& t, int cap) {
    vector<int> dp(cap + 1);

    for (int cur : t) {
        for (int i = cap; i >= cur; --i) {
            // cur 同时是占用与收益；倒序保证每题只选一次
            dp[i] = max(dp[i], dp[i - cur] + cur);
        }
    }

    return dp[cap];
}

void solve() {
    int s[4];
    for (int& x : s) cin >> x;

    vector<int> t;
    int ans = 0;

    for (int cnt : s) {
        t.clear(); // 各科独立，不能把上一科题目混入这一科

        int cap = 0;
        while (cnt--) {
            int x;
            cin >> x;
            t.push_back(x);
            cap += x;
        }

        // 这里的 cap 实际保存本科总时间 S；传入函数的才是容量 S / 2
        ans += cap - gett(t, cap / 2);
    }

    cout << ans << '\n';
}
```

原实现中，外层 `cap` 存总时间 $S$，而 `gett` 的参数 `cap` 存 $\lfloor S/2\rfloor$，两者作用域不同。逻辑正确，但以后可分别命名为 `sum`、`capacity`，减少读代码时的混淆。`gett` 不修改输入，也可将形参改为常量引用；原实现在此保留，不另造一份完整代码。

#### 正确性、复杂度与迁移

任何分配都可以把较轻一侧看成一个耗时不超过 $\lfloor S/2\rfloor$ 的子集。反过来，任何这样的子集都能交给一侧，其余题目交给另一侧，得到合法分配。

所以找出其中**实际耗时最大的子集**，就能让较忙一侧的耗时 $S-L$ 最小。各科不能同时复习，本科选择也不影响其他科，因此四科最短时间分别求出后相加。

第 $k$ 科有 $s_k$ 道题、总耗时 $S_k$，总时间复杂度 $O(\sum_k s_k S_k)$，额外空间 $O(\max_k S_k)$。单科总耗时不超过 1200，四科答案不超过 4800，`int` 足够。

**如何想到**：任务不可拆且只能分配一次 → 局部均衡不能保证最优 → 写出两边负载与完成时间 → 用较轻一侧消除对称 → 将最小完成时间转成有限容量内的最大分担量 → 0/1 背包。

这类识别过程已整理为[背包建模：使用次数、状态边界与优化目标](../../patterns/05-dynamic-programming/resource-limited-selection.md)。完整转化、原实现与复盘仍保留在本节。
