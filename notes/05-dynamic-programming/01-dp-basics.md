# 5.1 DP 入门：状态、初值、转移与计算顺序

动态规划（Dynamic Programming，DP）把问题拆成相互依赖的子问题，保存已经求出的结果，再用于后续计算。

> **重点不是写出一个 `dp` 数组，而是说明：一个状态代表什么，为什么这些信息足够，答案如何由更小的状态得到。**

前置：[DFS 与回溯](../03-search/01-dfs-backtracking.md)、[贪心与交换论证](../04-greedy-and-construction/01-sorting-greedy.md)。数组和循环沿用已有 STL 基础。

## 1. 从枚举所有路线，到合并相同子问题

设有位置 $0,1,\ldots,n$，从位置 $0$ 出发，每次向前走 **1 格或 2 格**，必须恰好到达位置 $n$。

落到位置 $i$ 时支付 $c_i$，经过的位置才付费，起点不付费。求**总代价最小值**，暂不要求输出路线。

直接 DFS 可以枚举所有合法路线，但不同路线经常到达同一位置，之后又重复探索相同的后续选择。

例如，到达位置 $3$ 可以走 $0\to1\to3$，也可以走 $0\to2\to3$。如果两条路线的累计代价分别为 $10$、$4$：

- **后续选择相同**：都可以从位置 $3$ 向前走 1 格或 2 格。
- **追加代价相同**：接上同一条后续路线，两者增加的费用一样。
- 因而原来花费 $10$ 的路线不可能反超花费 $4$ 的路线。

所以，求最小值时，**到达同一位置只需保留最小累计代价**，无须保留所有历史路线。

这既说明了为什么能合并状态，也说明了边界：若后续还受剩余跳跃次数、上一种动作等影响，仅记录位置就不够，必须保留这些会改变后续选择的信息。

## 2. 变量含义、容量与下标

定义：

$$
dp[i]=\text{从位置 0 出发，恰好到达位置 }i\text{ 的最小累计代价。}
$$

**“恰好到达”是状态定义的一部分**，不能理解成“前 $i$ 个位置中随便停在哪里的最小值”。

| 变量 | 含义与范围 |
| --- | --- |
| `n` | 终点编号；教学实现允许 $0\le n\le 200000$ |
| `cost[i]` | 落到位置 $i$ 的费用；位置为 **1-based**，$0\le cost[i]\le10^9$ |
| `cost[0]` | 占位，不参与计费；输入容器长度为 `n + 1` |
| `dp[i]` | 恰好到达位置 $i$ 的最小代价；状态下标为 $0\ldots n$ |
| `dp[0]` | 什么都没走的起点状态，代价为 0 |

两个容器均按**位置数量**分配 `n + 1` 个元素，不按费用最大值分配。

费用可能累计到 $2\times10^{14}$，因此费用与最优值使用 `ll`。位置编号使用 `int` 即可。

## 3. 怎样推出转移，而不是猜公式

### 3.1 先看最后一步从哪里来

要恰好到达位置 $i$，最后一步只有两种来源：

1. 从 $i-1$ 走 1 格。
2. 从 $i-2$ 走 2 格；只有 $i\ge2$ 时合法。

若最后一步来自 $i-1$，到达之前的最小代价是 $dp[i-1]$，落到 $i$ 再付 $c_i$，候选值就是：

$$
dp[i-1]+c_i.
$$

来自 $i-2$ 时，同理得到 $dp[i-2]+c_i$。两种来源覆盖了所有路线，取较小者：

$$
dp[i]=\min\bigl(dp[i-1],dp[i-2]\bigr)+c_i\qquad(i\ge2).
$$

**这不是只选眼前更便宜的位置，而是比较两类完整前缀路线的最优总代价。**

### 3.2 初值与顺序由定义决定

- $dp[0]=0$：不移动，没有费用。
- $dp[1]=c_1$：只能从位置 0 走来，不能访问 $dp[-1]$。
- 按 $i=1,2,\ldots,n$ 计算：需要的前驱状态都已求出。
- 最终取 $dp[n]$：目标是**恰好到达终点**，不能取整个数组的最小值。

这里存在明确的前后依赖顺序。有环且可能反复改变的状态，不能未经分析就套一次从小到大的循环。

## 4. 实现与执行流程

下面保留完整数组，先看清每个状态；空间压缩以后再讨论。

```cpp
using ll = long long;

// cost 长度为 n + 1，cost[1..n] 是落点费用，cost[0] 不使用
// 允许 n = 0；范围采用本节约定，所有位置均可到达
// 返回恰好到达 n 的最小代价；不修改 cost，每次调用重新建立状态
ll min_cost(const vector<ll>& cost) {
    int n = static_cast<int>(cost.size()) - 1;
    vector<ll> dp(n + 1, 0);

    dp[0] = 0; // 起点不付费，是所有后续状态的计算起点

    for (int i = 1; i <= n; ++i) {
        // 先考虑从 i - 1 走来；在本模型中，这个前驱始终可达
        dp[i] = dp[i - 1] + cost[i];

        // i >= 2 才存在第二种来源，避免读到负下标
        if (i >= 2) {
            dp[i] = min(dp[i], dp[i - 2] + cost[i]);
        }
    }

    return dp[n];
}
```

执行流程：

1. 准备 `cost[1..n]`，建立包含起点状态的 `dp`。
2. 按位置递增，先计算走 1 格的候选值。
3. 如果还能从前两格走来，再比较第二个候选值。
4. 保存当前位置的最优结果，供后面的位置使用。
5. 返回终点状态；`n = 0` 时直接得到 0。

这里初始化数组为 0 是安全的，因为**每个正位置都会在使用前被重新赋值，而且每个位置确实可达**；不能据此推广成“所有 DP 都全填 0”。

### 小例子：看状态怎样逐个确定

设费用依次为 $5,1,8,2$：

| 位置 $i$ | 本次落点费用 | 最优值的来源 | $dp[i]$ |
| --- | --- | --- | --- |
| 0 | 不计费 | 起点 | 0 |
| 1 | 5 | $dp[0]+5$ | 5 |
| 2 | 1 | $\min(5,0)+1$ | 1 |
| 3 | 8 | $\min(1,5)+8$ | 9 |
| 4 | 2 | $\min(9,1)+2$ | 3 |

位置 $3$ 的最优值比位置 $2$ 大并不矛盾：它们要求停在不同位置。最终路线可以是 $0\to2\to4$，总代价为 3。

### 正确性与复杂度

起点和位置 1 的结果符合定义。假设更小位置的最优值都已正确求出，到达 $i$ 的路线必来自上述两种合法前驱；每类中取最优前缀，再取两类的较小值，便得到 $dp[i]$。

**状态数为 $n+1$，每个状态最多检查两个前驱**，时间复杂度 $O(n)$，额外空间 $O(n)$。

如果需要具体路线，还要记录本次选用了哪个前驱；**最优值数组本身不等于完整路线记录**。

## 5. 与 DFS、记忆化、贪心的关系

### 递归先问需求，递推先排顺序

1. 若递归求“到达位置 $i$ 的最小代价”，它会继续询问位置 $i-1$、$i-2$；两个分支又可能重复询问更小的位置。**记忆化搜索**把每个子问题的结果保存下来，同一状态再次被询问时直接返回，避免重复展开。

2. **递推**则先安排依赖顺序，从初值逐个算到目标。本节使用递推，避免了递归深度随 $n$ 增长的问题。

两者可以计算同一组状态，但缓存的语义必须明确：

- 回溯中的路径标记，表示当前位置是否在**当前路线**里。
- 记忆化中的完成标记，表示这个**子问题的答案已经算好**，还需保存并返回答案。
- 不能只写一个 `visited` 就把后续访问丢弃，否则可能丢掉结果；有环时，“正在计算”也不等于“已经完成”。

关联：[搜索中的访问标记](../03-search/01-dfs-backtracking.md#7-访问标记含义决定是否撤销)；后续在 [记忆化搜索](../03-search/03-memoized-search.md#1-从两条路线的共同后半段入手)中展开共享子问题、缓存实现与无环依赖。

### DP 不需要先证明某个局部选择永远最好

费用为 $1,2,100,1$ 时，每次只走向眼前费用较低的位置，会走 $0\to1\to2\to4$，总费用为 4；而 $0\to2\to4$ 只花 3。

**贪心需要证明可以直接排除其他选择；DP 保留不同子问题的最优结果，再比较合法转移。**

DP 不能只看当前位置是否相同。只有当后续能做的选择和收益都相同时，才可以只保留当前最优的方案。 如果两条路线剩余的资源不同，即使走到同一位置，也可能需要分别考虑。

## 6. 初值不只是填一个数组

初始化要先回答：**这个状态有没有合法方案？如果有，方案的最优值是多少？**

这两个问题不能混在一起。例如剪彩带：

- 长度为 0，不用剪，**确实有一种合法方案，段数为 0**。
- 长度为 1，但只允许剪 2 或 5，**根本没有合法方案**。

如果两者都填 0，后面的代码就无法分清“可以从这里继续”还是“这里根本拼不出来”。

### 6.1 标记先区分存在，再比较数值

当数组同时记录可达性与最优值时，**不可达状态必须与合法答案区分开**。本题段数一定非负，所以可以约定：

- `-1`：没有合法方案，不能用它继续转移。
- `0`：存在合法方案，只是当前段数为 0。
- 正数：存在合法方案，记录最多段数。

> **先检查能不能从这个状态接着做，再比较接着做之后的答案。** 初始化不是实现细节，它决定了哪些中间结果会被当成真实方案。

`-1` 不是固定规则：若合法答案可能是负数，`-1` 就可能与真实答案冲突，需要换用安全的哨兵，或单独保存是否可达。

### 6.2 同类思想可以用在哪里

| 场景 | 合法的 0 表示什么 | 不存在或未知如何区分 | 更新时注意什么 |
| --- | --- | --- | --- |
| 恰好凑出长度，求最多段数 | 总长度 0，可以选 0 段 | 段数非负时用 `-1` | 只从可达长度继续添加 |
| 恰好凑出金额，求最少硬币数 | 金额 0，可以用 0 枚 | 用足够大的 `INF` | 前驱可达后再加 1 |
| 恰好装满容量，求最大价值 | 容量 0 的空方案价值为 0 | 用 `-INF`，或独立的可达标记 | 不能把未装满当成价值为 0 的合法完成 |
| 网格路径，可能含负分或障碍 | 有一条总分恰好为 0 的合法路径 | 用可达标记，或范围外的哨兵 | 只比较真正能走来的位置 |
| 无权最短路 | 起点到自己的距离为 0 | 距离非负时用 `-1` | 未发现与距离为 0 含义不同 |
| 记忆化搜索 | 子问题的答案确实等于 0 | 另设 `done`，表示是否已经计算完成 | 不能用答案为 0 判断“还没算” |
| 模意义下统计方案数 | 余数为 0；可能没有方案，也可能方案数是模数的倍数 | 若还需要判断有无方案，另设可达标记 | 模后的计数为 0，不能直接断言不可达 |

后几类只作语义对照，背包与硬币的具体转移留到后续模型。最短路已有类似约定，见 [BFS 与无权最短路](../03-search/02-bfs-shortest-path.md)。

### 6.3 不要把这条经验扩大成“DP 一律不能填 0”

- **本节最小落点代价模型**：每个位置都可达，而且每项在使用前会重新赋值，初始填 0 没有问题。
- **允许不选、只要求不超过容量**：空方案可能在每个容量上都合法，填 0 要结合状态定义判断。
- **统计方案数**：0 种方案本来就表示没有方案，不需要机械地改成 `-1`。

使用 `INF` 或 `-INF` 时，先检查前驱是否合法，再做加法，避免无效状态参与更新或造成溢出。数值范围要覆盖**中间运算**，不能只看最终答案。

## 7. 建模时先回答这五个问题

1. **状态**：一句话说清 `dp[...]` 代表哪一类子问题，是否要求恰好完成。
2. **初值**：哪些状态已经合法，哪些还不可达。
3. **转移**：最后一步或最后一个决策有哪些来源，是否完整且不重不漏；计数问题尤其要检查重复计算。
4. **顺序**：更新时依赖项是否已经确定，会不会错误使用本轮刚修改的数据。
5. **答案**：取一个指定状态，还是从一组合法终态中取最优值或求和。

再估算 **状态数 × 每个状态检查的转移数**，判断规模是否可行。数组只是保存状态的工具，不能仅凭出现递推式或数组就认定已经正确建模。

## 8. 典题与复盘

### 8.1 洛谷 P1216：数字三角形

[题目链接：P1216 数字三角形](https://www.luogu.com.cn/problem/P1216)

**收录原因**：从“枚举一条完整路线”转向“保存到达每个位置的最优结果”，同时练习边界、依赖顺序与最终答案的对应关系。

#### 题目与状态

从三角形顶部出发，每步走到左下或右下，求到最后一行任意位置的最大路径和。共有 $1\le n\le1000$ 行，数字在 $[0,100]$。

原实现采用 **0-based**：第 $i$ 行的有效列为 $0\ldots i$。

- 输入的 `x` 是当前格子的数字。
- `dp[i][j]` 是**从顶部走到第 $i$ 行、第 $j$ 列的最大路径和**，不再是原始数字。
- `dp` 有 `n` 行，第 $i$ 行实际存 `i + 1` 个格子，总容量为 $n(n+1)/2$。

同一格子的后续走法不受此前路线影响，所以只保留到达这里的最大路径和。

#### 原实现：读入时直接更新

以下只整理排版与注释，保留原逻辑；通用框架沿用[竞赛基础模板](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)。

```cpp
void solve() {
    int n;
    cin >> n;

    vector<vector<int>> dp(n);

    for (int i = 0; i < n; ++i) {
        for (int j = 0; j <= i; ++j) {
            int x;
            cin >> x;
            dp[i].push_back(x);

            if (i > 0) {
                // 最左侧只能从正上方走来，不能访问 j - 1
                if (j == 0) dp[i][j] += dp[i - 1][j];
                // 最右侧只能从左上方走来，上一行没有第 j 列
                else if (j == i) dp[i][j] += dp[i - 1][j - 1];
                // 中间格有两个合法前驱，保留路径和更大的那个
                else dp[i][j] += max(dp[i - 1][j - 1], dp[i - 1][j]);
            }
        }
    }

    // 终点可以是最后一行的任意格子，不能只取某个固定列
    int maxx = 0;
    for (int x : dp[n - 1])
        maxx = max(maxx, x);

    cout << maxx << '\n';
}
```

#### 转移、顺序与边界

顶部没有前驱，直接保留输入值。对于其余行的中间格，到达它的最后一步只有两个来源：

$$
dp[i][j]=x_{i,j}+\max\bigl(dp[i-1][j-1],dp[i-1][j]\bigr).
$$

两侧只能取存在的那个前驱，代码分别判断。**先完成上一行，再计算下一行**，所以读入时就能更新，无须另存原三角形。

最终答案是最后一行的最大值。每条路线经过 $n$ 个数字，路径和不超过 $100000$，`int` 足够；由于原题数字非负，`maxx = 0` 也安全。若扩展到负数，应从最后一行的真实值开始取最大值，不能让不存在的 0 分方案胜出。

时间复杂度 $O(n^2)$，空间复杂度 $O(n^2)$。

#### 如何想到与进步空间

**要最大路径和 → 同一格可能被多条路线到达 → 到达后的选择相同 → 保存每格最大路径和。** 再反过来看最后一步来自哪里，就得到转移。

原实现已经适合本题，推荐保留，不另造一份“优化解”。因为只依赖上一行，以后可再练习压到 $O(n)$ 空间；当前完整保留每格状态更方便检查，且满足原题范围。

**核验与状态**：原实现已完成本地核验，复盘完成；平台评测结果未单独记录，不补记平台 AC。

### 8.2 Codeforces 189A：Cut Ribbon

[题目链接：CF 189A Cut Ribbon](https://codeforces.com/problemset/problem/189/A)

**收录原因**：建立“先判断方案是否存在，再比较方案数值”的习惯，理解状态定义中的“恰好”会直接决定初始化与合法转移。

#### 题目与建模起点

长度为 $n$ 的彩带切成若干段，每段长度只能为 $a,b,c$，求最多段数；**不能留下没有使用的长度**。

范围为 $1\le n,a,b,c\le4000$，三种长度允许相同，保证至少存在一种合法切法。

**本题在知识链中的位置**：入门先用一维总长度练习“恰好、不可达与最后一步”，不必同时引入完整的物品轮次模型。它本来就属于**完全背包的恰好型**：段长可以重复使用，每取一段使目标值加 1，最终求最多段数。先练状态再学习分类，是为了分开理解负担；专题建立后，应将两者联系起来，见[与最少硬币的统一对照](03-complete-knapsack.md#62-与剪彩带统一理解)。

这里不是要求 $n$ 能被某一种长度整除：长度 7 可以由 5 和 2 共同拼出。需要逐个考虑不同长度能否拼出，以及最多能有几段。

定义：

$$
dp[i]=\text{恰好用完长度 }i\text{ 时，最多可以分成的段数。}
$$

- `len` 只记录 3 种可选长度，按**选择种数**分配。
- `dp` 按**总长度上限 `n`**分配 `n + 1` 项，下标为 $0\ldots n$，包含空长度 0。
- `-1` 表示拼不出，合法段数为 $0\ldots n$，两者不会冲突。

#### 第一版 WA：把“不能分”也记成了 0 段

最初的理解是“长度为 $i$，最多能分几段”，没有严格区分**恰好用完**与**允许剩下一点**。

第一版把 `dp` 全部初始化为 0，先排序长度，再分情况访问前驱。其中有这样的处理：

```cpp
// 错误片段：数组默认填 0，无法分清“可达且为 0”与“不可达”
vector<int> dp(n + 1);

// 第一版先将 a <= b <= c 排序，以下位于逐长度计算的循环中
if (i >= c) {
    dp[i] = max(dp[i - a], max(dp[i - b], dp[i - c])) + 1;
} else if (i >= b) {
    dp[i] = max(dp[i - a], dp[i - b]) + 1;
} else if (i >= a) {
    dp[i] = dp[i - a] + 1;
} else {
    dp[i] = dp[i - 1]; // 留下这部分长度，却仍将它当成合法前驱
}
```

当时认为：小于最短段长时不能剪，记 0 段只是初始化，不会影响后面。

问题是，**0 不只会作为当前答案输出，还会被后面的长度接着使用**。代码因此把“这一段长度根本无法拼出”当成了“这一段长度已经合法处理，只剪了 0 段”。

以原题样例 `7 5 5 2` 为例：

| 长度 $i$ | 第一版记录 | 恰好用完时应记录 |
| --- | --- | --- |
| 0 | 0 | 0，合法空方案 |
| 1 | 0 | -1，不可达 |
| 2 | 1 | 1 |
| 3 | 1 | -1，不可达 |
| 4 | 2 | 2 |
| 5 | 2 | 1 |
| 6 | 3 | 3 |
| 7 | 3 | 2 |

错误逐步传播：

1. `dp[3]` 从 `dp[1] + 1` 得到 1，但长度 3 不能恰好拼出。
2. `dp[5]` 又从这个错误的 `dp[3] + 1` 得到 2。
3. `dp[7]` 继续沿用错误的 `dp[5]`，得到 3；实际只能拼成 $5+2$，答案为 2。

**不只是最后那个 `else` 要改。** 即使删除继承语句，只要不可达项仍是 0，后面无条件取它加 1，错误仍然存在。

也不能为了记 0 段，直接继承前一长度：从 $i-1$ 到 $i$ 没有添加一段允许的长度，不能凭空“补上 1”。

#### 修正：只从确实能拼出的长度继续

先把所有长度设为不可达，仅将 `dp[0]` 设为 0：空彩带可以用 0 段完成。

如果最后一段选择长度 $x$，前面必须**恰好拼出 $i-x$**。只有前驱可达时，才能形成候选值：

$$
dp[i-x]+1.
$$

依次尝试三种长度，取最多段数。候选条件是 $i\ge x$ 且 $dp[i-x]\ne-1$；如果一个合法前驱都没有，当前项继续保持 -1。

长度都为正，前驱必然小于当前长度，按 $i=1,2,\ldots,n$ 计算就能保证先求出前驱。

#### 修正后个人 AC：保留这一版作为主写法

以下只调整排版与注释，保留修正后的逻辑。平台 AC 依据为个人反馈，本地另行核验。

```cpp
void solve() {
    int n;
    cin >> n;

    vector<int> len(3);
    for (int& x : len) cin >> x;

    vector<int> dp(n + 1, -1); // 先表示所有长度都还拼不出
    dp[0] = 0;                // 长度 0 可以恰好用 0 段完成

    for (int i = 1; i <= n; ++i) {
        for (int x : len) {
            // 既要放得下最后一段，前面的长度也必须确实能拼出
            if (i >= x && dp[i - x] != -1) {
                dp[i] = max(dp[i], dp[i - x] + 1);
            }
        }
    }

    cout << dp[n] << '\n';
}
```

每种最后一段都被尝试；可达前驱接上它就是合法方案，而所有合法方案也都有这样的最后一段，所以不会遗漏最优解。

**每个长度只检查 3 个选择**，时间复杂度 $O(3n)=O(n)$，空间复杂度 $O(n)$。段数不超过 $n\le4000$，`int` 足够；原题保证有解，因此最终 `dp[n]` 一定不是 -1。

重复长度只会重复比较相同候选，**求最大值不会因此重复计数**。不需要排序，也不必按三种长度的大小关系分别写分支。

#### 这类题的发现过程

**用若干种合法长度拼出目标 → 同一总长度可能有多种拼法 → 后续只需知道已用总长度与当前最多段数 → 枚举最后一段，并检查剩余长度能否恰好拼出。**

这是一类“可重复选择，恰好达到总量，求最优个数”的基础模型；后续完全背包会继续讨论。并不是所有凑长度题都能直接照搬：如果每种长度只能用有限次，必须额外处理数量限制。

本次最重要的改进不是少写几个分支，而是让**状态定义、初始化、合法转移、最终答案**表达同一件事。
