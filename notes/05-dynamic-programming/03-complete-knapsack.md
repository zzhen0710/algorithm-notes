# 5.3 完全背包：可重复选择与容量正序

前置：[0/1 背包](02-zero-one-knapsack.md)。状态设计仍从资源上限和收益出发，本节改变的是**同一种物品可以选择任意次**。

> **循环方向是在控制“能否再次使用当前物品”。** 先确定题意允许几次，再决定转移读取上一轮还是当前轮。

0/1 背包与完全背包按**使用次数**区分，是背包问题的不同基本模型；“不超过、恰好、至少”和“最大、最小”是另两项条件。不能把所有变式都称为 0/1 背包，统一识别见[背包建模范式](../../patterns/resource-limited-selection.md)。

## 1. 题目条件与状态

有 $n$ 种物品，第 $i$ 种每件占用 $w_i$、提供价值 $v_i$，货源无限。总容量为 $C$，求**总占用不超过 $C$ 的最大价值**。

每次选择必须付出正的容量；没有规定必须用满，可以不选。

| 变量 | 含义与范围 |
| --- | --- |
| `items` | 物品种类数组，**0-based**，每个位置表示一种可重复选择的物品 |
| `cost` | 每选一件的容量占用，为正 `int` |
| `value` | 每选一件的价值，非负，使用 `ll` |
| `capacity` | 容量上限 $C$，状态范围为 $0\ldots C$ |
| $F_i(j)$ | 只用前 $i$ 种物品，总占用不超过 $j$ 的最大价值 |
| `dp[j]` | 压缩后的容量状态，具体属于哪一轮由外层循环决定 |

数组按 **`C + 1` 个容量上限**分配，不按种类数或价值上限分配。

教学实现约定 $C\le10^7$、单件价值不超过 $10^9$，且 $nC$ 在题目允许的计算量内。占用至少为 1，所以总价值不超过 $C$ 乘最大单件价值，采用 `ll`。

同样的输入结构不代表同样的使用次数：0/1 背包一行是一件，完全背包一行是一种，必须按题意判断。

## 2. 不必枚举当前物品选多少件

直接考虑当前种类选 $k$ 件，可以写出：

$$
F_i(j)=\max_{0\le k\le\lfloor j/w_i\rfloor}
\bigl(F_{i-1}(j-kw_i)+kv_i\bigr).
$$

这式子说明了所有可能，但每个容量还要枚举件数，会多出一层循环。

换一个分类方法：只问**当前种类是否至少选了一件**。

### 一件也不选

只用前 $i-1$ 种，候选值为：

$$
F_{i-1}(j).
$$

### 至少选了一件

先拿出当前种类的一件，占用 $w_i$、价值 $v_i$。剩下的容量上限为 $j-w_i$。

剩余部分**仍然允许选当前种类**，因此用的是 $F_i(j-w_i)$，不是 $F_{i-1}(j-w_i)$。

$$
F_i(j)=\max\bigl(F_{i-1}(j),F_i(j-w_i)+v_i\bigr)
\qquad(j\ge w_i).
$$

- 不选第 $i$ 种： 这一种物品完全不参与，所以只能从前 $i-1$ 种中选，得到 $F_{i-1}(j)$。

- 至少选一件第 $i$ 种： 先拿出一件，剩余容量为 $j-w_i$。剩余部分仍可选前 $i$ 种，因此是 $F_i(j-w_i)+v_i$。

**少掉的件数枚举，交给更小容量的同一行状态继续处理。** 例如当前种类已经在 $F_i(j-w_i)$ 中选了两件，再加这一件，就覆盖了选三件的情况。

占用为正，$j-w_i<j$，所以这一行从小容量算到大容量，就能先得到所需前驱。

## 3. 压成一维：为什么改为正序

一轮开始前，`dp[j]` 只使用此前的种类。处理当前种类时，从它的占用开始，**按容量递增**：

- `dp[j]` 的原值表示不选当前种类。
- `dp[j - cost]` 已经算过，允许包含当前种类。
- 再加一件，便能继续使用当前种类。

| 模型 | 选择当前物品时，前驱属于哪一轮 | 一维容量方向 |
| --- | --- | --- |
| 0/1 背包 | 上一轮，尚未使用当前这一件 | 从大到小 |
| 完全背包 | 当前轮，允许已使用当前种类 | 从小到大 |

这里对照的是**物品在外层、容量在内层**的写法。不能离开循环含义，只机械记“背包正序或倒序”。

```cpp
using ll = long long;

struct Item {
    int cost; // 每件占用为正，避免零占用反复取用
    ll value;
};

// 采用本节范围，每种可重复选择，总占用不超过 capacity
// 返回最大价值；允许空数组和容量 0，不修改输入
// 每次调用重新建立状态，无多测残留
ll complete_knapsack(const vector<Item>& items, int capacity) {
    vector<ll> dp(capacity + 1, 0);

    for (const auto& cur : items) {
        for (int j = cur.cost; j <= capacity; ++j) {
            // 较小容量已处理，可以包含当前种类，再取一件仍然合法
            dp[j] = max(dp[j], dp[j - cur.cost] + cur.value);
        }
    }

    return dp[capacity];
}
```

执行流程：

1. 按容量建立全 0 数组，每个上限都允许选择空方案。
2. 依次开放一种物品，容量从它的占用开始递增。
3. 比较“不取”与“在较小容量的本轮结果上再取一件”。
4. 本轮结束后，数组已允许当前种类使用任意次。
5. 返回总容量对应的最优值，实际占用可以少于容量。

每种最多访问 $C$ 个容量，时间复杂度 $O(nC)$，额外空间 $O(C)$。

### 为什么两个 `dp` 分别代表两轮？

核心原因：**一维 DP 把两行状态压缩到同一个数组中，而遍历顺序决定了每个位置是否已经被本轮更新**。

- 当前的 `dp[j]`：上一轮。 遍历到容量 `j` 之前，本轮还没有处理过这个位置，所以它仍是 $F_{i-1}(j)$。
- 前驱 `dp[j-w]`：当前轮。 因为从小到大遍历，容量 `j-w` 比 `j` 小，通常已经在本轮更新过，所以它是 $F_i(j-w)$。

补充边界：如果 `j-w < w`，这个小容量本轮没有执行更新，但它本来就装不下当前种类，$F_i(j-w)=F_{i-1}(j-w)$，所以仍可直接作为本轮状态使用。

## 4. 一个物品就能看清区别

只有一种物品，占用为 2、价值为 3，容量上限为 6：

| 模型完成后的状态 | 容量 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 最多选一次 | 0 | 0 | 3 | 3 | 3 | 3 | 3 |
| 允许重复选择 | 0 | 0 | 3 | 3 | 6 | 6 | 9 |

完全背包正序处理时：

1. 容量 2 从 `dp[0] + 3` 得到 3。
2. 容量 4 从**本轮的 `dp[2] + 3`**得到 6，已经选择两件。
3. 容量 6 再从本轮 `dp[4] + 3` 得到 9，选择三件。

这正是上一节正序会出错的地方；题目允许重复后，同样的读取行为变成了正确转移。

容量为 5 时，只能选两件，`dp[5] = 6`。这里 5 是容量上限，6 是价值，两者单位不同，不要求价值小于容量。

## 5. 为什么这个转移不会漏掉最优方案

1. **不选当前种类**： 方案只使用前 $i-1$ 种物品，由 $F_{i-1}(j)$ 覆盖。
2. **至少选一件当前种类**：  从方案中拿出一件重量为 $w_i$ 的物品，剩下物品的总重量最多为 $j-w_i$，且仍可使用前 $i$ 种物品。因此，剩余方案由 $F_i(j-w_i)$ 覆盖，再加上拿出的这件物品的价值 $v_i$。反之，从合法前驱再加一件，先考虑容量上限为 $j-w_i$、允许使用前 $i$ 种物品的子问题 $F_i(j-w_i)$，再追加一件第 $i$ 种物品，得到 $F_i(j-w_i)+v_i$。

**两种情况覆盖了所有可能，取最大值即可**。

注意：这里的 $j$ 是**背包容量上限**，不代表背包一定装满。

初始化时没有物品也可以选择空方案，因此第 0 轮所有容量都为 0。每种按容量递增计算，前驱已经完成，逐轮便能得到最终答案。

## 6. 背包问题扩展

### 6.1 最少硬币

每种面额的硬币可以无限使用，要求**恰好凑出金额 `target`，并让硬币总枚数最少**。

这里按状态轴对应，**`cost` 是硬币面额，目标的每次增量是常量 1**，表示多用一枚。若沿用 `cost / value` 的叫法，`value = 1`，但这次要最小化它，并不表示要最大化钱的价值。

这仍是可重复选择，但与上面的“容量内最大价值”有两处变化：

- **金额必须恰好凑出，所以不能让所有初值都为 0**。
- 目标是最少枚数，**选一枚的代价为 1，更新时取最小值**。

#### 状态、初值与前驱

`dp[j]` 表示用已经处理的面额，**恰好凑出金额 `j` 的最少枚数**。

- `coins` 按面额种数保存，**0-based**，每个面额为正整数。
- `dp` 按目标金额分配 `target + 1` 项，下标为 $0\ldots target$。
- `dp[0] = 0`：不选硬币，可以合法凑出金额 0。
- 其余为 `INF`：目前无法恰好凑出，不能当成用了 0 枚的方案。

若当前面额为 $x$，必须先能凑出 $j-x$，才能再加一枚：

$$
dp[j]=\min\bigl(dp[j],dp[j-x]+1\bigr).
$$

允许重复使用当前面额，金额仍然正序。**是否重复决定读取顺序，是否恰好决定状态与初始化，这两个条件要分别判断。**

```cpp
// 面额均为正 int，0 <= target <= 1000000
// 时间为 O(coins.size() * target)，须符合题目规模
// 返回恰好凑出的最少枚数；无解返回 -1，不修改 coins
int min_coins(const vector<int>& coins, int target) {
    // 成功时每枚至少贡献 1，枚数不会超过 target
    // target + 1 足够与所有合法答案区分，且在本节范围内不会溢出
    const int INF = target + 1;
    vector<int> dp(target + 1, INF);
    dp[0] = 0;

    for (int coin : coins) {
        for (int j = coin; j <= target; ++j) {
            if (dp[j - coin] == INF)
                continue; // 前面的金额还凑不出，不能从这里接上一枚

            dp[j] = min(dp[j], dp[j - coin] + 1);
        }
    }

    return dp[target] == INF ? -1 : dp[target];
}
```

这里的 `INF = target + 1` 有范围依据，不能移到任意最小费用问题中照用。若每次付出不同且很大的费用，应按费用范围重新选类型与哨兵。

时间复杂度 $O(n\times target)$，额外空间 $O(target)$。空面额表仅能凑出金额 0，函数对目标 0 返回 0。

#### 小例子：可重复，也仍可能凑不出

面额为 3、4，目标金额为 6，表中的 `INF` 表示不可达：

| 已处理面额 | 金额 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 无 | 0 | INF | INF | INF | INF | INF | INF |
| 加入 3 | 0 | INF | INF | 1 | INF | INF | 2 |
| 再加入 4 | 0 | INF | INF | 1 | 1 | INF | 2 |

金额 6 可以用两枚 3，金额 5 则始终不可达。不能把 `dp[5]` 改成 `dp[4]`，因为那会漏掉必须补出的金额 1。

面额为 1、3、4，目标为 6 时，本模型能得到两枚 3；这也说明[优先选大硬币](../04-greedy-and-construction/01-sorting-greedy.md#5-怎样检验一个贪心想法)不能保证最少枚数。

### 6.2 与剪彩带统一理解

[CF 189A 剪彩带](01-dp-basics.md#82-codeforces-189acut-ribbon)与最少硬币都允许反复选择，而且必须恰好达到总量，**都属于完全背包的恰好型**。

| 对照项 | 最少硬币 | 剪彩带 |
| --- | --- | --- |
| 状态下标 | 已凑出的金额 | 已使用的长度 |
| 每次推进多少 | 一枚硬币的面额 | 一段彩带的长度 |
| 目标每次增加多少 | 1 枚 | 1 段 |
| 每种能选几次 | 无限次 | 无限次 |
| 优化方向 | 最小化枚数，取 `min` | 最大化段数，取 `max` |
| 不可达状态 | `INF` | `-1`，段数非负时可与合法答案区分 |
| 合法起点 | 金额 0 用 0 枚 | 长度 0 用 0 段 |

**相同的是：从一个确实存在的较小总量方案出发，再接一次选择。** 区别在于接上以后比较最小值还是最大值，以及用什么初值表达“尚无方案”。

哨兵不是让程序少算几个位置的技巧，而是阻止不存在的中间方案继续参与转移。取 `max` 或 `min` 之前，先保证前驱合法。

更一般地，按顺序分别检查：**使用次数 → 总量是不超过、恰好还是至少 → 目标及每次增量 → 初始化、转移与答案位置**。各项可以组合，不必把每个组合当成毫无关系的新算法。

## 7. 和 CF 189A 的外层顺序对照

[剪彩带的原 AC](01-dp-basics.md#82-codeforces-189acut-ribbon)按长度递增，内层尝试三种最后一段，也允许重复使用段长。

两种组织方式各有清晰含义：

- **种类在外层**：逐步开放种类，同一轮正序推进容量，读取当前种类可以重复使用的结果。
- **长度在外层**：直接问最后一段选哪个长度，较小长度的最优值已经求出，可以继续接上任意合法段长。

因此，可重复选择的最大值、最小值模型可以有不同的循环组织。关键是说明**前驱代表什么，为什么已经求好，能否继续使用当前选择**。

若目标改成统计方案数，循环层次还可能改变是否区分排列顺序，不能据此随意互换；计数模型后续单独整理。

## 8. 边界与适用条件

- **占用或面额必须为正。** 零占用且正价值的物品可以无限取，使最大价值没有有限答案；通用实现不处理这种输入。
- **重复选择不代表没有资源限制。** 物品数量不限，但总占用仍受容量限制。
- **相同面额重复出现**：求最大值、最小值时通常只会重复比较；计数时则要重新检查是否被当成不同选择。
- **不能忽略容量数值与内存。** `ll` 数组每项通常为 8 字节，容量为 $10^7$ 时仅状态数组就约 80 MB；同时检查时间和内存限制。
- **不超过、恰好、至少是三种目标。** 购买干草采用恰好重量的状态，再比较所有至少满足需求的终态；不能把原上限状态的含义直接照搬。
- **无解与目标 0**：最少硬币的目标 0 有空方案，不是无解；正目标可能拼不出，需要保留不可达状态。

## 9. 典题与复盘

### 9.1 洛谷 P1616：疯狂的采药

[题目链接：P1616 疯狂的采药](https://www.luogu.com.cn/problem/P1616)

**收录原因**：从“每件一次”迁移到“每种无限次”，同时把数值范围检查落实到状态数组与运算过程。

#### 原实现与使用次数

总时间 $t\le10^7$，种类数 $m\le10^4$，且 $mt\le10^7$；每次采摘时间、价值在 $[1,10^4]$。每种草药可无限采摘，总用时不超过上限，求最大价值。

以下只调整排版与注释，保留原逻辑；别名和框架沿用[竞赛基础模板](../../templates/cpp-contest-template/README.md)。

```cpp
void solve() {
    int cost, n;
    cin >> cost >> n;

    vector<pii> a(n);
    for (auto& x : a)
        cin >> x.first >> x.second;

    vector<ll> dp(cost + 1);
    for (auto& item : a) {
        for (int i = item.first; i <= cost; ++i) {
            // 容量正序，较小用时的状态可以已经采过当前种类
            dp[i] = max(dp[i], dp[i - item.first] + item.second);
        }
    }

    cout << dp[cost] << '\n';
}
```

`cost` 在这里是**总时间上限**，`a` 按种类数分配；`dp[i]` 是只用已处理种类、总用时不超过 `i` 的最大价值，下标为 $0\ldots t$。

相比[采药原题](02-zero-one-knapsack.md#81-洛谷-p1048采药)，选择限制改成无限次，因此容量递增，让同一种草药可以接着取。

#### 踩坑：单个价值很小，累计结果却很大

曾因状态采用 `int` 而 WA。若只有一种草药，采一次花 1 个时间、价值为 $10^4$，总时间为 $10^7$，总价值可以达到：

$$
10^7\times10^4=10^{11}.
$$

所以**`dp` 必须用 `ll`**，不能只把最后的答案变量改为 `ll`。原实现中 `dp[i - item.first]` 已是 `ll`，加上输入价值时也会按 `ll` 计算。

习惯上先检查累计值、乘积和中间结果的范围。容量下标与单个输入在本题范围内可用 `int`；涉及大数的整条运算路径优先使用 `ll`，写乘法时也要保证乘法本身已提升类型。

时间复杂度 $O(mt)$，额外空间 $O(m+t)$，状态数组为 $O(t)$。联合条件 $mt\le10^7$ 限制了实际循环规模；`ll` 状态数组最大约 80 MB，时间和内存都需核对。

原方案已合适，推荐保留。**核验与状态**：原实现本地核验通过，复盘完成；保留个人反馈的溢出 WA 经历，修正后的平台结果未单独记录。

### 9.2 洛谷 P2918：Buying Hay

[题目链接：P2918 Buying Hay](https://www.luogu.com.cn/problem/P2918)

**收录原因**：把“至少满足需求”拆成多个恰好重量的状态，用最优性证明有限上界，并区分“最先可达”与“目标值最小”。

#### 模型：状态可以恰好，最终目标仍是至少

公司数 $N\le100$，需求 $1\le H\le50000$，每包重量与价格均在 $[1,5000]$，供应无限。

定义 `dp[i]` 为：**使用已处理公司的干草包，恰好买到 `i` 磅时的最小花费**。`dp[0]=0`，其余不可达。

最终需要的是“至少 $H$ 磅”，所以答案要从所有 $i\ge H$ 的合法状态中**取最小费用**，并不是寻找第一个有方案的重量。

这里按重量推进状态，累加的是价格。原结构体却将重量叫作 `value`、价格叫作 `cost`，只是字段命名，不代表必须按名为 `cost` 的字段开表。**模型角色由状态定义和更新式决定，不能只看变量名。**

#### 坑一：最小重量，不等于最小价格

第一版从需求往后找，找到第一个可达状态就退出：

```cpp
// 错误片段：按重量递增，只找到了最早可达的位置
ll ans = 0;
for (int i = val; i < maxx; ++i) {
    if (dp[i] != LLONG_MAX) {
        ans = dp[i];
        break;
    }
}
```

反例：需求为 10，有两种包，重量、价格分别为 $(10,100)$、$(6,1)$。

- 恰好买到 10，最少花 100。
- 买两包重量 6 的，总重 12，只花 2。

**重量增加时，恰好重量的最小费用不保证递增。** 第一种状态最早达到需求，第二种状态却更便宜。

因此要扫描所有合法答案状态取 `min`。这段线性扫描的代价也小于主要背包转移，不能在没有单调性证明时，为少算一点就提前退出。

#### 坑二：转移中的提前 break 也会漏状态

第一版还在每种包的转移中写了 `if (i >= val) break;`。即使把最终查询改成取全局最小值，这个截断也仍可能出错。

需求为 5，依次处理 $(3,100)$、$(4,1)$：第一种包产生重量 6、费用 200；处理第二种时，重量 7 可以由重量 3 接上一包得到，费用 101，于是提前退出，漏掉重量 8、费用 2 的更好方案。

**某个重量已经满足需求，不代表更大重量没有更便宜的组合。** 正确做法是按已证明的状态范围完成转移，再在合法终态中选答案。

#### 坑三：固定上界与末端遗漏

固定 `maxx = 50000 + 5` 没有充分依据。例如需求为 50000，只有重量 4999、价格 1 的包：10 包还差一点，必须买 11 包，总重 54989，已超过旧上界。

原查询还使用 `i < maxx`，也可能遗漏已分配的最后一个状态；转移和答案扫描都要与有效闭区间一致。

#### 用最优性证明上界

记最大单包重量为 $W_{\max}$。每包价格为正，若某方案总重已达到 $H+W_{\max}$，删去任意一包后仍不少于 $H$，费用却更低，因此它不可能最优。

所以只需保留：

$$
H\le S\le H+W_{\max}-1
$$

这一范围内的候选答案；DP 状态仍需从 0 建到上界，才能计算各候选的前驱。完整的一般条件与反证推导见[从最优性推出状态上界](../../patterns/optimality-state-bound.md)。

#### 原 AC：保留完整逻辑与哨兵差异

下面只整理排版和注释，保留最终原稿。平台 AC 依据为个人反馈。

```cpp
struct Item {
    int cost; // 本题原命名：价格，属于要最小化的目标增量
    ll value; // 本题原命名：重量，属于状态下标的推进量
};

void solve() {
    int n, val;
    cin >> n >> val;

    vector<Item> a(n);
    ll maxw = 0;
    for (auto& x : a) {
        cin >> x.value >> x.cost;
        maxw = max(maxw, x.value); // 最大单包重量，用于证明最优状态上界
    }

    const int maxx = val + maxw - 1;
    const ll INF = LLONG_MAX / 4; // 为加法留余量，仍应先过滤不可达
    vector<ll> dp(maxx + 1, INF); // 恰好买到 i 磅干草的最少花费
    dp[0] = 0;

    for (auto& x : a) {
        for (int i = x.value; i <= maxx; ++i) {
            // 原意：前面不可达，本次达到方式不存在；比较值应与 INF 统一
            if (dp[i - x.value] == LLONG_MAX) continue;

            dp[i] = min(dp[i], dp[i - x.value] + x.cost);
        }
    }

    ll ans = INF;
    for (ll i = val; i <= maxx; ++i)
        ans = min(ans, dp[i]); // 扫描所有满足需求的重量，比较的是费用

    cout << ans << '\n';
}
```

这份原稿初始化为 `INF`，过滤时仍比较 `LLONG_MAX`，所以未真正跳过不可达前驱。在本题正费用且数值较小的范围内，`INF + cost` 不会小于 `INF`，也不会溢出，因而这处不一致不改变最小值；但注释中的保护并未生效，整理时应统一：

```cpp
// 修正片段：其余原逻辑不变
if (dp[i - x.value] == INF) continue;
```

`INF` 是同一个“不可达”的约定，初始化、判定与最终无解处理不能分别用不同数值。`LLONG_MAX / 4` 只是留出算术余量，不是取消前驱检查的理由。

#### 流程、范围与进步空间

1. 读入每包重量和价格，记录最大单包重量。
2. 用最优性确定上界，建立 `0..maxx` 的恰好重量状态。
3. 逐种处理，重量正序，允许同种包重复购买；只从可达前驱继续。
4. 扫描 `H..maxx`，取最小费用。

上界最多为 54999；每种包正重量、正价格，原题保证有供应且允许重复购买，因此一定能买够。

时间复杂度 $O(N(H+W_{\max}))$，状态空间 $O(H+W_{\max})$，另存 $O(N)$ 种包。原命名容易让重量与价格混淆，以后可写成 `weight / price`，但不为改名重写原解。
