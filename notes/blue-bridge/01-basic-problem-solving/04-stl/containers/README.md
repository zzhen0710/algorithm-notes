# Containers：STL 容器与竞赛常用工具

本目录整理 C++11 中常用的 STL 容器、容器适配器及相关工具类型，结合 Codeforces、洛谷代表题，重点掌握：

- 常用 API、参数与返回类型
- 时间复杂度与空间复杂度
- 迭代器特性、边界条件及常见陷阱
- 数据结构选型与可复用的解题思想

除标准容器外，本目录也收录 `string`、`pair`、`tuple`、`bitset` 等竞赛常用工具。

## 二、竞赛选型速查

| 需求                            | 优先考虑                          |
| ------------------------------- | --------------------------------- |
| 动态数组、按下标访问            | `vector`                          |
| 长度编译期固定                  | `array`                           |
| 两端高效插入删除                | `deque`                           |
| 后进先出                        | `stack`                           |
| 先进先出                        | `queue`                           |
| 动态获取最大值或最小值          | `priority_queue`                  |
| 有序去重、查前驱后继            | `set`                             |
| 有序且允许重复                  | `multiset`                        |
| 快速判重、不要求排序            | `unordered_set`                   |
| 按 key 维护 value，需要有序性   | `map`                             |
| 按 key 维护 value，不要求有序性 | `unordered_map`                   |
| 一个 key 对应多个 value         | `map<K, vector<V>>` 或 `multimap` |
| 两个字段绑定、多关键字排序      | `pair`                            |
| 多个固定字段绑定与排序          | `tuple`                           |
| 固定长度的二进制位操作          | `bitset`                          |

关联容器的完整分类、复杂度和接口区别，参见 [**八大关联容器总结**](app://-/14-associative-containers-summary.md)。

## 三、值得复用的解题思想

学习容器不只是掌握接口，还应理解它们如何帮助简化问题。

**1. 不同操作可以由不同结构承担**

例如，保留元素首次出现的顺序时，可以按输入顺序遍历，并使用 `unordered_set` 负责判重；不需要集合本身支持有序遍历。

**2. 先识别决定答案的关键状态**

例如，多个区间的交集由最大左端点和最小右端点决定。明确这两个极值后，可以使用 `multiset` 动态维护，或在静态数据中使用前后缀预处理。

**3. 改变状态表示，避免重复搜索**

例如，在用户名注册问题中，思路最初受到空间换时间的启发，但最终并非机械地增加存储，而是利用输入约束，只记录足以决定下一次生成结果的信息。

**4. 利用排序与传递性简化全局判断**

例如，先按价格排序，再检查质量序列是否出现相邻下降，就能判断是否存在价格更低、质量却更高的商品。

**5. 利用数据表示，让通用工具自然解决问题**

例如，将降序关键字转换为取负后的升序关键字，利用 `pair`、`tuple` 的默认字典序排序；或将倍增过程转化为二进制表示，再利用 `bitset` 统计置位数量。

## 四、学习说明

- 代码以 **C++11** 为兼容基准。
- 容器操作的平均、最坏或均摊复杂度需要区分，尤其是哈希容器。
- 同名 API 在不同容器中可能有不同的返回类型与删除语义。
- 先根据问题需要的操作和数据性质选型，而不是先确定容器再套用。
