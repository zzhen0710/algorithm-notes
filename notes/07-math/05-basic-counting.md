# 7.5 基础计数：分类、分步与排列组合

[CF 584B 的复盘](03-binary-exponentiation.md#82-cf-584bkolya-and-tanya)已经用过“总数减去不满足的方案”。本节先建立通用判断：**数的是什么、顺序是否重要、能否重复，再决定分类相加还是分步相乘。**

使用 C++11，沿用[竞赛基础框架](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)。先掌握基础模型；模意义组合数、逆元、一般容斥等后续再补，不在本节堆公式。

## 1. 先明确：怎样才算不同方案

同样是“选两个”，计数对象可能不同：

- **选人：** 甲和乙组成一组，与乙和甲是同一组。
- **分配职位：** 甲任队长、乙任副队长，与交换职位是不同方案。
- **选下标：** 数组中两个相同数值可能来自不同位置，不能因值相同就去重。

这与[枚举中的值和位置](../01-basic-problem-solving/02-enumeration.md#33-分清值不同和位置不同)一致。公式不会自动判断题目想数哪一种对象。

> **先确认对象、顺序、重复与限制，再选公式。** 不能看到“选”就直接套组合数。

## 2. 加法与乘法：分类相加，分步相乘

### 加法原理：互斥类别覆盖全部方案

若一种方案只能属于某一类，且各类合起来恰好覆盖全部情况，则总数为各类数量之和。

例如任选一种交通方式，公交有 2 条路线、地铁有 3 条路线，一共 $2+3=5$ 种。**这里是在两类方案之间选一种，不是两种交通工具都要使用。**

分类要同时满足：

- **不重：** 一个方案不能被多类重复统计。
- **不漏：** 每个合法方案都落在某一类。

“会 C++ 的人”和“会 Python 的人”可能重叠，直接将两类人数相加就会重复。可改成互斥分类；一般重叠计数见 [7.7 容斥原理](07-inclusion-exclusion.md)。

### 乘法原理：按步骤形成一个完整方案

若第一步有 $a$ 种选择，且**第一步的每种选择之后，第二步都恰好有 $b$ 种选择**，则完整方案有 $ab$ 种。

例如从 5 个不同的人中，依次选队长、副队长、记录员，不允许一人兼任：

$$
5\times4\times3=60
$$

后一步不能再选前面的人，选择显然有关联；但每个前缀对应的后续选择数相同，所以仍能相乘。

**完全独立是方便相乘的一种情况，不是乘法原理的必要条件。** 真正要检查的是各阶段的可选数量，能否对所有对应前缀统一计算。

若不同前缀的后续数量不同，就不能随意选一个数量相乘；应分类后累加，或进一步保存状态。后续 DP 会处理这类需要记录前缀影响的问题。

分步计数也要满足**一个完整选择过程恰好对应一个方案**。如果同一最终方案能由多个过程产生，还需检查是否重复计数。

## 3. 排列与组合：差一个“顺序是否重要”

以下默认 $n$ 个对象彼此不同，且 $0\le k\le n$。

### 排列：不重复地选 k 个，顺序重要

依次有 $n,n-1,\ldots,n-k+1$ 种选择，因此：

$$
A_n^k=n(n-1)\cdots(n-k+1)=\frac{n!}{(n-k)!}
$$

当 $k=n$，得到全部对象的排列数 $n!$。约定 $0!=1$，选 0 个对象也只有一个空方案。

### 组合：不重复地选 k 个，顺序不重要

同一组 $k$ 个不同对象，在排列计数中会因顺序不同被统计 $k!$ 次。例如选甲、乙时，`甲乙` 和 `乙甲` 是同一组的两种排列。

每组被重复统计的次数**恰好相同**，所以可以除去这份重复：

$$
\binom{n}{k}=C_n^k=\frac{A_n^k}{k!}=\frac{n!}{k!(n-k)!}
$$

例如 5 人选 2 人，排列有 $5\times4=20$ 种，组合则有 $20/2!=10$ 种。

**能除以某个数的依据是“每个最终方案都恰好被重复数这么多次”**，不是觉得结果偏大，就随手除一下。

### 与允许重复的选择对照

| 条件 | 计数 |
| --- | --- |
| 选 $k$ 次，顺序重要，每次可重复选 $n$ 个对象之一 | $n^k$ |
| 选 $k$ 个，顺序重要，不重复 | $A_n^k$ |
| 选 $k$ 个，顺序不重要，不重复 | $\binom{n}{k}$ |

**允许重复时，`k` 可以大于 `n`；不重复时，`k>n` 才表示无法完成选择。**

允许重复而顺序不重要时，**不能直接将 $n^k$ 除以 $k!$**。例如从 `A、B` 中重复选两次，无序结果为 `AA、AB、BB`；`AB` 对应两个有序过程，而 `AA、BB` 各只有一个，重复次数不统一。

## 4. 常用小模型：无序两两配对

从 $t$ 个不同对象中选出一对，先选第一个有 $t$ 种，再选第二个有 $t-1$ 种；此时每对都被正反统计两次，因此：

$$
\binom{t}{2}=\frac{t(t-1)}2
$$

这统计的是**一对不同对象**，不包含自己与自己，也不区分先后。若数有方向的配对，就不能除以 2。

```cpp
using ll = long long;

// 0<=t<=10^9；返回无序对数，t=0 或 1 时自然为 0
ll choose_two(ll t) {
    return t * (t - 1) / 2; // 本范围内，除以 2 之前的乘积也能用 ll 表示
}
```

时间、空间均为 $O(1)$。`t=100000` 时结果已超过 `int`；**输入变量和乘法中间结果都要考虑范围，不能只把最终答案存为 `ll`。**

这只是计数工具。题目若还要求分组后的最小值或最大值，仍需额外分析怎样分组，公式本身不会自动决定最优方案。

## 5. 小范围组合数表：按选或不选递推

阶乘公式便于理解，但**不是任何范围都适合直接算阶乘**。`20!` 可用 `ll` 表示，`21!` 已经超出；有时组合数本身可表示，分子阶乘却早已溢出。

小范围可用只包含加法的递推计算。

### 为什么可以拆成两个较小问题

从 $n$ 个不同对象中选 $k$ 个，固定考察其中一个对象：

- **不选它：** 从其余 $n-1$ 个中选 $k$ 个，有 $\binom{n-1}{k}$ 种。
- **选它：** 它已占一个名额，再从其余 $n-1$ 个中选 $k-1$ 个，有 $\binom{n-1}{k-1}$ 种。

两类互斥且覆盖全部方案，用加法原理得到：

$$
\binom{n}{k}=\binom{n-1}{k-1}+\binom{n-1}{k}
$$

### 变量、容量与初始化

- `N`：需要计算到的最大对象数；**本例限定 `0<=N<=60`**，所有组合数和加法结果均能用 `ll` 表示，不取模。
- `c[n][k]`：**从 `n` 个不同对象中选 `k` 个的方案数**。两个维度分别记录**可选对象数**和**选取数**；只保留 `n`，无法区分同为 4 个对象时选 1 个与选 2 个的不同问题。
- 容器为 `(N+1)×(N+1)`，两个下标均为 **0-based，范围 `0..N`**。输入对象实际是什么，不影响表的容量。
- `c[n][0]=1`：不选任何对象只有一个空方案，包括 `c[0][0]=1`。
- `k>n` 的表格位置初始化为 0，表示选取不可能；访问表前仍需保证两个下标都在范围内。

本范围的最大值是 $\binom{60}{30}=118264581564861424$，可用 `ll` 表示。更大范围必须重新分析，不能只改大 `N` 就继续沿用数值契约。

### 执行流程与实现

1. 建立全零表，初始化所有 `c[n][0]=1`。
2. 按 `n` 从小到大计算；当前行只依赖上一行，所需值已经算好。
3. 对 `1<=k<=n`，将选与不选两类数量相加。
4. 计算后按 `c[n][k]` 查询，不需要重新枚举具体组合。

```cpp
// 0<=N<=60；返回精确组合数表，无共享状态，每次调用独立
vector<vector<ll>> build_comb(int N) {
    vector<vector<ll>> c(N + 1, vector<ll>(N + 1, 0));

    for (int n = 0; n <= N; ++n)
        c[n][0] = 1;

    for (int n = 1; n <= N; ++n) {
        for (int k = 1; k <= n; ++k) {
            c[n][k] = c[n - 1][k - 1] + c[n - 1][k];
        }
    }

    return c;
}
```

预处理时间和空间均为 $O(N^2)$，之后单次查询 $O(1)$；`N=0` 为常数处理。每次返回新表，多测无需清理；多次查询同一范围时，可在调用处复用表。

例如只看 `k=0、1、2`：

| `n` | `c[n][0]` | `c[n][1]` | `c[n][2]` |
| --- | --- | --- | --- |
| 0 | 1 | 0 | 0 |
| 1 | 1 | 1 | 0 |
| 2 | 1 | 2 | 1 |
| 3 | 1 | 3 | 3 |
| 4 | 1 | 4 | 6 |

其中 `c[4][2]=c[3][1]+c[3][2]=3+3=6`。**把较小问题的答案保存下来，再按依赖顺序计算更大问题**，也是后续 DP 的一个基本思路。

这张表用于理解一般组合数，不代表每道计数题都要建表；能用简单表达式完成的计数，无须增加二维容器。

### 单次查询：乘除递推

只问一个组合数，且选取数较小时，可直接相乘并逐步整除，不必建表。下面保留 CF 478B 原稿的 `C`，仅整理排版与注释；可复用版本见[精确组合数模板](../../templates/07-math/combinations/README.md)。

先利用 $\binom{n}{m}=\binom{n}{n-m}$，将 `m` 改为两边较小者。记 $d=n-m$，循环进行到第 $i$ 步时：

$$
\mathrm{ans}=\binom{d+i}{i}
$$

因为：

$$
\binom{d+i}{i}=\binom{d+i-1}{i-1}\times\frac{d+i}{i}
$$

所以每轮将已有答案乘上 `n-m+i`，再除以 `i`；最后 $i=m$，得到的就是 $\binom{n}{m}$。

```cpp
// n>=0；合法参数还要求每轮乘法中间值可用 ll 表示，不取模
ll C(ll n, ll m) {
    if (m < 0 || m > n) {
        return 0;
    }

    m = min(m, n - m); // 利用对称性，减少循环次数
    ll ans = 1;

    for (ll i = 1; i <= m; ++i) {
        ans = ans * (n - m + i) / i;
    }

    return ans;
}
```

- `n`：原对象总数，循环中不改变。
- `m`：对称化后的较小选取数，决定循环次数，不是数组容量。
- `i`：当前递推步数；`ans` 保存的是 $\binom{n-m+i}{i}$，不是始终保存 $\binom{n}{i}$。
- 初始 `ans=1` 对应空选取；非法 `m` 返回 0，`m=0` 时不进入循环，返回 1。

例如 `C(5,2)`：第 1 步得到 $1\times4/1=4$，第 2 步得到 $4\times5/2=10$。

**每步的完整乘积能被 i 整除，不代表 ans 本身就能被 i 整除。** 例如 `C(6,2)` 的最后一步是 $5\times6/2=15$，若先算 `5/2` 就会截断，得到错误的 12。

设 $k=\min(m,n-m)$，时间 $O(k+1)$、空间 $O(1)$。输入按值接收，每次调用独立，不影响调用处变量。

**原函数要检查中间乘法，不能只看最终结果。** $\binom{62}{31}$ 约为 $4.65\times10^{17}$，本身可表示；但最后一步乘完、除以 31 之前约为 $1.44\times10^{19}$，已经超过 `ll`。

两个方便使用的充分范围是：`n<=60` 的任意合法选取数，或 `n<=10^9` 且 `k<=2`。本节 CF 478B 只调用选 2 个的情况，满足后者；**不能据此把同样大的 n 直接推广到任意 m**。更一般的安全约分与模意义组合数留到后续，不在短函数中悄悄放宽契约。

## 6. 直接计数、补集与数值边界

**直接数合法方案难，而不合法方案容易描述时，可用“总数减去不合法数”。** 前提是反面条件写得准确，并且统计范围一致。

[CF 584B](03-binary-exponentiation.md#82-cf-584bkolya-and-tanya)已经说明：“至少一组不等于 6”的反面是“所有组都等于 6”，不是“至少一组等于 6”。沿用已有完整推导，不重复维护一份题解。

写代码时再检查：

- **空方案：** 选 0 个通常有 1 种；要求非空时，再按题意排除，不能统一初始化成 0。
- **不可能的选择：** 对非负 `n、k`，`k>n` 的不重复选择数为 0；不要继续计算负数阶乘或访问负下标。
- **先溢出再取模无效：** 加乘之前就要保证中间值可表示，不是最后多写 `%p` 就安全。
- **整数除法不能直接搬进模运算：** 例如 $\binom{3}{2}=6/2=3$，但 `(6%5)/2` 得到 0。需要模意义除法时，参考[前文的限制](02-congruence-modulo.md#5-不能照搬的规则除法约分与大小比较)，逆元后续再讲。

## 7. 典题与复盘

以下按实际实现整理。P1866 原逻辑保留；CF 478B 的重复计数另列错误片段与最小修正版，不将修正版冒充原实现。通用 `C` 已在前文维护，不重复粘贴。

### 7.1 P1866：编号

题目：[洛谷 P1866](https://www.luogu.com.cn/problem/P1866)。

- **题意：** 给不同兔子分配互不相同的编号，第 $i$ 只可接受 `1..M_i`；求合法编号方案数，模 $10^9+7$，无解输出 0。
- **条件：** $1\le N\le50$，$1\le M_i\le1000$。
- **练习目的：** 带限制、不允许重复的分配计数；区分对象身份、每步可选数量与最终方案数。
- **状态：复盘完成（本地核验），平台结果未单独记录。**

#### 原实现：先处理上限较小的对象

```cpp
void solve() {
    ll n;
    cin >> n;

    vector<ll> a(n);
    for (ll& x : a) cin >> x;
    sort(a.begin(), a.end());

    const int q = 1e9 + 7;
    ll ans = 1;
    ll cur = -1;

    for (ll x : a) {
        ++cur; // 处理当前兔子前，已有 cur 个编号被占用
        if (x <= cur) {
            ans = 0;
            break;
        }

        x -= cur;
        ans = ans * x % q;
    }

    cout << ans << '\n';
}
```

原代码只改排版与注释。`cur` 初始为 -1，每次进入循环先加 1，因此它在计算贡献时恰好是**之前已经分配编号的兔子数**。

`for (ll x : a)` 按值取出上限，`x-=cur` 只将当前局部变量改为可选数量，不改变数组。

#### 为什么排序后每步都能直接相乘

处理当前上限 `x` 时，之前所有对象的上限都不超过 `x`，所以此前占用的 `cur` 个编号必然全部落在 `1..x` 中。

不论之前具体用了哪些编号，当前可选数量都恰好是：

$$
x-\mathrm{cur}
$$

**前面的选择会影响哪些编号可用，但不会影响可用编号的数量。** 这正是有关联的选择仍能使用乘法原理的条件。

若不按上限递增处理，之前用掉的编号可能超出当前 `1..x`，就不能一律减去已分配数量。例如上限为 `3、1`，先处理上限 3 时，选编号 1 和选编号 2 会给后一只留下不同的可选数，无法统一相乘。

排序只固定处理次序，不改变兔子的可区分性。**相同上限的兔子仍作为不同对象依次处理，不能去重，也不用再除以阶乘。** 例如两只上限均为 2 的兔子，编号分别为 `(1,2)` 与 `(2,1)` 是两个方案。

若 `x<=cur`，则当前无可用编号，方案数为 0；初始化 `ans=1` 是乘法的空前缀单位元，不是预先多算了一个最终方案。

#### 范围、代价与发现过程

每轮取模后 `ans<q`，当前因子不超过 1000，因此乘法中间值可用 `ll` 表示。排序与扫描时间为 $O(n\log n)$，数组占 $O(n)$ 空间。

**各对象上限不同 → 原顺序下后续数量依赖具体编号 → 先固定从小上限到大上限的处理次序 → 已占用编号必落在当前范围内 → 每步数量统一为上限减已用数。**

原方案已合适，推荐沿用同一实现；本地已核验重复上限、无解与题目范围边界，平台结果未单独记录。

### 7.2 CF 478B：Random Teams

题目：[Codeforces 478B](https://codeforces.com/problemset/problem/478/B)。

- **题意：** 将 $n$ 人分进 $m$ 个非空队伍，每队内部的每对人成为朋友；求可能产生的朋友对数的最小值和最大值。
- **条件：** $1\le m\le n\le10^9$，输出最小值、最大值。
- **练习目的：** 将局部计数与整体最值目标结合，区分“某个分配方案的计数”和“所有方案中的最优值”，检查 64 位中间运算。
- **状态：待修正。原最小值公式重复计数；最小修正版已本地核验，平台结果待确认。**

#### 原思路与错误片段：均匀分组正确，贡献替换有误

设 `base=n/m`，`cnt=n%m`。尽量均匀分组时：

- `m-cnt` 个队伍各有 `base` 人。
- `cnt` 个队伍各有 `base+1` 人。

原式为：

```cpp
// 错误片段：cnt 个较大队伍同时计入了两项
ll minn = m * C(base, 2) + cnt * C(base + 1, 2);
ll maxx = C(n - m + 1, 2);
```

第一项已经给全部 `m` 个队伍算过基值贡献，第二项却又加上较大队伍的**完整贡献**，不是只加增加一人带来的增量。

反例 `n=5、m=2`：均匀分成 2 人、3 人，两队贡献为 $1+3=4$；原式却算成 $2\times1+1\times3=5$。最大值仍为 6，原程序输出 `5 6`，正确应为 `4 6`。

**三组官方样例恰好没有暴露它：** `5 1`、`6 3` 的余数为 0；`3 2` 的 `base=1`，原基值贡献为 0。主动构造 `base>=2` 且 `cnt>0` 的输入，才能检验这两项是否重复。

#### 最小值：为什么各队人数最多相差 1

若两个队伍人数为 $x\ge y+2$，从大队移一人到小队，朋友对数减少：

$$
\left[\binom{x}{2}+\binom{y}{2}\right]
-\left[\binom{x-1}{2}+\binom{y+1}{2}\right]
=x-y-1\gt 0
$$

两队仍然非空，且总人数不变。只要人数相差至少 2，就能继续改进，因此最优分组中各队人数只能是 `base` 或 `base+1`。

按两类队伍分别计算：

$$
\text{最小值}=(m-\mathrm{cnt})\binom{\mathrm{base}}2
+\mathrm{cnt}\binom{\mathrm{base}+1}2
$$

也可全部先按基值计算，再只补增量。因为增加一人会与原来的 `base` 人分别形成一对：

$$
\binom{\mathrm{base}+1}2-\binom{\mathrm{base}}2=\mathrm{base}
$$

所以等价写法是 $m\binom{\mathrm{base}}2+\mathrm{cnt}\times\mathrm{base}$。

**“分两类算完整贡献”和“先算基值再补增量”都可以，不能把两种方式混用。**

#### 最大值：其余队伍各留一人

若两个队伍都至少有 2 人，取 $x\ge y\ge2$，从小队移一人到大队，朋友对数增加 $x-(y-1)\gt 0$，同时小队仍非空。

不断集中后，除一个队伍外，其余 `m-1` 队各留 1 人，大队人数为 `n-m+1`。因此原最大值公式正确：

$$
\text{最大值}=\binom{n-m+1}2
$$

#### 最小修正版：只调整最小值的队伍数量

```cpp
// 复用前文 C；相较原稿，只修正 minn 的第一项系数
void solve() {
    ll n, m;
    cin >> n >> m;

    if (n < m) {
        cout << "0 0\n";
        return;
    }

    ll base = n / m;
    ll cnt = n % m;

    ll minn = (m - cnt) * C(base, 2) + cnt * C(base + 1, 2);
    ll maxx = C(n - m + 1, 2);

    cout << minn << ' ' << maxx << '\n';
}
```

题面保证 `1<=m<=n`，原稿的 `n<m` 保护不会在合法输入触发，保留它不影响本次修正。`C` 只求选 2 人，时间和空间均为 $O(1)$，也可直接复用第 4 节的 `choose_two`。

在 $n\le10^9$ 内，组合数函数先乘后除的中间值安全；分组总对数不超过 $\binom n2$，`ll` 可表示。**组内人数、组合数返回值与总贡献均按 64 位处理。**

**先计算给定分组的局部贡献 → 用移动一人的变化判断均匀或集中 → 根据整除与余数确定队伍数量 → 将“整份贡献”和“增量”分开列式。**

修正版已通过官方样例、反例与本地小范围所有非空人数分配核验；原稿最小值待按上式修正，修正后的平台结果仍待确认。
