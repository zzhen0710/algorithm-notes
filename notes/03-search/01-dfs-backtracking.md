# 3.1 DFS 与回溯基础

## 1. 解决什么问题

有些问题需要连续作出多个选择，后面的可选项又依赖前面的决定。例如生成合法方案、尝试路线、判断某种安排是否存在。

固定几层循环可以处理固定步数；当选择步数由输入决定，或者每条路线长度不同，可以用递归组织枚举。

**DFS（Depth-First Search，深度优先搜索）先沿当前分支深入，处理完后返回，再尝试其他分支。**

> **回溯的关键是撤销本层选择带来的修改，使共享状态回到选择之前。** 例如删除本层追加的字符，或将本层设为 `true` 的路径标记改回 `false`；不是清空整条路径，也不是把所有变量都清零。

本节先建立隐式搜索树模型，不要求先掌握图的存储；图上的 DFS 与 BFS 在后续衔接。沿用 [C++ 竞赛基础框架](../../templates/cpp-contest-template/README.md)，使用 C++11，不重复 `main`。

下标约定：导引中的字符串与组合题的 `a` 使用 **0-based**，组合候选值为 $1\ldots n$；迷宫坐标使用 **1-based**。候选值从 `1` 开始，不等于方案数组也要从 `1` 开始。

## 2. 把方案看成一棵搜索树

以生成长度为 $n$、字符只含 `A` 或 `B`、不允许连续两个 `B` 的字符串为导引。

- **节点**：已经确定的前缀，也就是当前状态。
- **边**：在末尾添加一个合法字符。
- **根**：空前缀。
- **叶子**：长度已经达到 $n$ 的完整方案。

例如 $n=3$ 时，从空前缀先尝试 `A`，继续深入，依次得到 `AAA`、`AAB`；返回前缀 `A` 后，再尝试 `AB`，得到 `ABA`。随后才处理首字符为 `B` 的分支。

```text
空前缀
├── A
│   ├── AA → AAA、AAB
│   └── AB → ABA
└── B
    └── BA → BAA、BAB
```

搜索树可以只存在于思考中，**不必先创建所有节点**。递归过程中，当前前缀和下一步选择就能描述它。

与[枚举](../01-basic-problem-solving/02-enumeration.md)的联系：DFS 仍然是系统枚举，只是用递归表达随状态展开的多层选择。

## 3. 变量、容器与范围

- `n`：需要生成的字符串长度。演示约定 $0\le n\le20$，避免输出规模过大；不是字符值域。
- `pos`：已经填好的字符数，也是下一个待填位置，范围为 $0\ldots n$。
- `path`：当前前缀，使用 `string`，长度始终等于 `pos`。只保存当前分支，最多占 $n$ 个字符空间。
- `c`：本层尝试的字符，依次为 `A`、`B`。

**进入 `dfs(pos, n, path)` 时，约定 `path` 是长度为 `pos` 的合法前缀；函数返回时，`path` 与调用前完全相同。** 本次调用追加的字符由本次调用逐一删除，调用前已有的字符不删除。

这个约定同时说明了递归参数的含义和函数的副作用，比单独记住函数名更重要。

## 4. 执行流程

1. 从空前缀和 `pos = 0` 开始。
2. 如果 `pos == n`，记录完整方案并返回。
3. 依次尝试本层的字符，检查添加后是否仍然合法。
4. 将字符加入 `path`，递归处理下一位置。
5. 递归返回后用 `pop_back()` 删除本层刚加入的字符，回到选择前的前缀，继续尝试本层下一选择。

> **一次递归调用处理当前前缀下的全部后续方案。** 调用返回表示这条子分支处理完毕，父层的循环随后继续。

## 5. 通用导引实现

以下是教学模型的完整辅助函数与 `solve()`，不是配套题的专属题解。

```cpp
void dfs(int pos, int n, string& path) {
    if (pos == n) {
        cout << path << '\n'; // 到达叶子，记录一个完整方案
        return;
    }

    for (char c : {'A', 'B'}) {
        // 只有末尾字符会与新字符相邻，不必重新检查整个前缀
        if (c == 'B' && !path.empty() && path.back() == 'B') {
            continue;
        }

        path.push_back(c); // 做选择：修改当前前缀

        dfs(pos + 1, n, path); // 处理这个选择下的全部后续分支

        path.pop_back(); // 撤销本层选择，让下一分支共享同一个前缀
    }
}

void solve() {
    int n; cin >> n;

    string path; // 每次求解重新初始化，避免多测残留
    dfs(0, n, path);
}
```

$n=3$ 时，输出依次为 `AAA`、`AAB`、`ABA`、`BAA`、`BAB`。$n=0$ 时，空字符串本身是一种方案，输出一个空行。

>这里在加入字符前排除不合法分支，属于**可行性剪枝**：已经出现连续两个 `B`，后面再补字符也无法修复，因此没有必要继续深入。

## 6. 递归返回了，为什么还要撤销共享状态的修改

`pos` 按值传入，每次调用有自己的参数；调用 `dfs(pos + 1, ...)` 不会修改父层的 `pos`，因此不需要手动减一。

`path` 按引用传入，各层修改的是同一个字符串。**函数返回只结束本次调用，不会自动撤销对共享对象的修改。**

以父层前缀 `A` 为例：

```text
进入本层：A
选择 A：AA
递归处理 AA 下的全部方案，返回时仍为 AA
撤销本层选择：A
选择 B：AB
```

每一层只负责删除自己追加的字符；更深层也遵守同一约定，因此处理完一个分支后，父层的前缀能回到该分支开始之前。

**是否撤销，要逐个变量说明具体操作：**

- 当前字符串路径：删除本层追加的字符；当前方案或路径的使用标记：将本层从 `false` 改成的 `true` 设回 `false`。
- 总方案数、全局最优答案：跨分支累计贡献或更新最优值，分支结束后不减去本次贡献、不退回旧答案。
- 按值传递的参数：调用之间独立，父层参数没有被子层修改，不需要手动做相反运算。
- 为某个位置赋值的方案数组：若后续访问前一定重新赋值，可以覆盖复用；有效长度以递归层数为准。

按值复制整个路径也能隔离分支，但会增加复制成本。**共享引用采用“修改后再撤销”时，需要检查具体配对操作，如 `push_back()` 与 `pop_back()`。**

## 7. 访问标记：含义决定是否撤销

遇到 `vis` 或 `used` 时，先说明它记录的是什么，而不是一律写“标记 → 递归 → 取消”。

| 标记含义 | 本轮搜索中的具体操作 | 原因 |
| --- | --- | --- |
| 某元素已经在当前方案中使用 | 选入时设为 `true`，分支结束后改回 `false` | 下一方案仍然可以选择它 |
| 某位置已经在当前路径中经过 | 进入前设为 `true`，递归返回后改回 `false` | 位置退出当前路径，其他路径仍可使用 |
| 图遍历中某顶点已发现，目标是遍历可达点 | 首次进入前设为 `true`，返回后不改回 `false` | 本轮已发现的顶点不重复展开，避免沿环无限访问 |

**这里“撤销标记”是把本层设为 `true` 的项改回原来的 `false`，不是重新设为 `true`。** “不撤销”是让已发现状态的标记在本轮搜索中持续有效；新一轮独立搜索仍需重新初始化。

**同一个位置可以对应不同搜索状态。** 若问题还依赖钥匙、剩余资源或已选集合，仅用位置标记可能合并本应区分的状态。何时能够复用位置对应的答案，见 [记忆化搜索的状态判断](03-memoized-search.md#2-为什么只用位置作为状态)。

本节字符串模型没有环，且长度每次增加，因而不需要访问标记。图遍历中标记的时机与 BFS 的距离含义在后续具体模型中说明。

## 8. 正确性、复杂度与边界

对于任意合法前缀，循环尝试所有合法的下一字符，递归继续生成后缀。不同分支在本层字符上不同，不会重复；任何合法完整字符串都能按其字符顺序到达对应叶子，不会遗漏。

终止条件来自 `pos` 每次增加，最多到达 $n$；剪掉的分支不可能再扩展成合法答案。

**复杂度按搜索状态数估计，不能因为只有一层 `for` 就判为线性。**

本例每层最多两个选择、深度为 $n$，搜索节点数上界为 $O(2^n)$；每个完整字符串输出 $n$ 个字符，含输出的时间上界为 $O((n+1)2^n)$。剪枝减少实际节点数；当前路径与递归栈各为 $O(n)$，不保存全部答案。

常见边界：

- 先检查完成条件，再访问下一位置；记录方案后及时 `return`。
- 访问 `path.back()` 前确认非空；实际数组访问前先检查边界。
- 撤销的必须是本层实际做过的修改，不能误删父层状态。
- 判断存在性时可以找到一个答案就结束；**枚举或计数全部方案时，不能找到第一个答案就停止。** 若提前返回，要保证仍遵守约定的恢复规则。
- 搜索能写出来不代表能跑完。排列可能达到 $n!$，路径搜索也可能指数增长；先估规模再决定是否需要其他方法。
- 递归过深可能耗尽调用栈；本节浅层方案搜索可用递归，大规模图遍历应按数据深度考虑显式栈。

### 9.1 洛谷 P1157：组合的输出

[题目链接](https://www.luogu.com.cn/problem/P1157)。从 $1\ldots n$ 中取 $r$ 个数，输出全部组合；$1<n<21$，$0\le r\le n$。

每组内升序，组合之间按字典顺序输出，每个数字占 **3 个字符宽度**。可使用 `<iomanip>` 中的 `setw(3)`；它只作用于紧随其后的一个输出项。

#### 我的思路与原实现

用 `p` 表示已经确定的元素数，`start` 表示本层允许选择的最小值。选择 `i` 后，下一层从 `i + 1` 开始，整个方案始终严格递增。

- `a`：长度为 `r` 的方案数组，**按所选元素数分配**，不是按 `n` 分配。
- `a[0..p-1]`：当前已经确定的有效前缀。
- `start`：控制下一步可选范围；不同层之间按值传递。
- `p == r`：方案完整，可以输出整个数组。

```cpp
int n, r;
vector<int> a; // 等输入 r 后再调整大小

void dfs(int start, int p) {
    if (p == r) {
        for (int x : a)
            cout << setw(3) << x; // 每个输出项都要设置场宽
        cout << '\n';

        return;
    }

    for (int i = start; i <= n; ++i) {
        a[p] = i; // 当前槽位直接覆盖，有效前缀长度由 p 决定

        dfs(i + 1, p + 1); // 后续只能选更大的数
    }
}

void solve() {
    cin >> n >> r;
    a.resize(r); // 容量依赖输入，必须在读取之后设置

    dfs(1, 0);
}
```

**这是组合，不是全排列。** 同一组数换顺序仍是同一个组合，因此只生成严格递增的表示。

递增范围同时做到：元素不会再次使用，同一组元素不会以不同顺序重复输出。每个合法组合都有唯一递增序列，递归能沿它依次选择；本层按从小到大尝试，又保证字典顺序。

这里不需要 `visited`，也不需要在返回后把 `a[p]` 清零。递归返回后，`p` 仍属于父层；下一分支会覆盖当前槽位，所有槽位都填好后才输出。旧后缀虽然还在内存中，**不属于当前有效前缀，也不会被当成有效结果读取。**

#### 踩坑：容器大小必须跟随输入初始化

若在全局直接写 `vector<int> a(r)`，全局 `r` 此时会被零初始化，因此创建的是空容器；后续读入新的 `r` 不会自动改变 `a` 的长度。随后直接访问 `a[p]` 会越界。

问题不在于全局 `r` 是随机值，而在于**容器创建早于输入，大小不会随变量后续变化自动同步**。原实现先输入再 `resize(r)`，处理正确；`r=0` 时也能直接输出空组合对应的空行。

#### 推荐调整：把“剩余数量够不够”放进循环边界

原实现正确，可以保留。可进一步减少不能凑满 `r` 个数的分支。

当前位置及之后还需选择 $r-p$ 个数，若本层选 `i`，可用候选总数为 $n-i+1$，因此必须满足：

$$
n-i+1\ge r-p
\quad\Longleftrightarrow\quad
i\le n-(r-p)+1
$$

**只替换原 `dfs` 的循环上界，其他代码保持一致：**

```cpp
// 包括当前槽位，还需 r-p 个数；候选不足时不进入分支
for (int i = start; i <= n - (r - p) + 1; ++i) {
    a[p] = i;

    dfs(i + 1, p + 1);
}
```

例如 $n=5,r=4,p=0$，首项最多选 $2$；从 $3$ 开始已经不可能凑齐四个数。这是由剩余容量推出的可行性剪枝，不改变合法结果和顺序。

设 $C(n,k)$ 为从 $n$ 个数中选 $k$ 个的组合数。原实现会生成长度不超过 `r` 的所有递增前缀，搜索时间为 $O(\sum_{k=0}^{r}C(n,k))$，另有输出成本 $O((r+1)C(n,r))$。加上候选数量剪枝后，每个进入的前缀都能扩展成答案，总时间可界为 $O((r+1)C(n,r))$；两者空间均为 $O(r+1)$。

**改进收益来自少搜无效前缀，不是减少答案本身的输出量。** 发现方向是“还要选几个 → 后面还剩几个 → 能否提前缩小范围”。

### 9.2 洛谷 P1605：迷宫

[题目链接](https://www.luogu.com.cn/problem/P1605)。上下左右移动，避开障碍，每格最多经过一次，统计起点到终点的路线数；$1\le N,M\le5$，$1\le T\le10$，起点保证无障碍。

#### 我的思路与原实现

从当前位置尝试四个方向，在本层排除越界、障碍和当前路径中已经经过的位置；到达终点时增加方案数并返回。

- `g`：地图，原实现用 `0` 表示空地、`1` 表示障碍、`2` 表示终点。固定大小 `10 × 10` 覆盖题目最大 `5 × 5` 的 1 下标区域。
- `v`：当前路径的访问状态，**不是所有历史路径共同的访问记录**。
- `dx、dy`：同一方向的行、列变化，按相同下标配对使用。
- `ans`：通过引用让各分支累计到同一个计数器；发现路线后增加，递归返回时不减回原值。

```cpp
int dx[] = {1, -1, 0, 0};
int dy[] = {0, 0, -1, 1};
int g[10][10];
bool v[10][10];
int n, m, t;
int sx, sy, fx, fy;

void dfs(int x, int y, int& ans) {
    if (g[x][y] == 2) {
        ++ans;
        return; // 本条路线已完成，不继续从终点扩展
    }

    for (int i = 0; i < 4; ++i) {
        int nx = x + dx[i];
        int ny = y + dy[i];

        bool check = nx >= 1 && nx <= n &&
                     ny >= 1 && ny <= m;

        // || 从左到右短路：越界时不读取后面的地图与标记
        if (!check || g[nx][ny] == 1 || v[nx][ny])
            continue;

        v[nx][ny] = true; // 进入分支前，记录这一步经过的位置

        dfs(nx, ny, ans);

        v[nx][ny] = false; // 返回后释放位置，供其他路径使用
    }
}

void solve() {
    cin >> n >> m >> t;
    cin >> sx >> sy >> fx >> fy;

    while (t--) {
        int x, y;
        cin >> x >> y;
        g[x][y] = 1;
    }

    if (g[fx][fy] == 1) {
        cout << 0 << '\n';
        return; // 先处理障碍，再写入终点标记
    }

    g[fx][fy] = 2;

    int ans = 0;
    v[sx][sy] = true; // 起点也已经属于当前路径
    dfs(sx, sy, ans);

    cout << ans << '\n';
}
```

进入 `dfs` 时，当前位置的 `v` 已经为 `true`，当前路径没有重复格；下一步只进入未访问的合法格，递归返回后将该下一格的 `v` 改回 `false`。由此，每个递归分支对应一条合法路径，所有合法下一步均被枚举，不同方向序列对应不同路线。

标记的设置和取消由**调用者**成对完成：先将 `v[nx][ny]` 设为 `true`，调用 `dfs(nx, ny, ans)`，返回后再设为 `false`。终点处的 `return` 只是结束子调用，父层仍会继续执行取消标记的那一行。

推荐沿用这份实现，重点完善状态含义与边界，无需为了“双解”再造一份相同搜索。地图同时编码障碍和终点可行，也可以用坐标判断终点；选择原写法时必须保留先检查障碍的顺序。

#### 两处真实踩坑

**1. 起点也必须标记。**

起点不是循环中的“下一格”，因此不会由原循环自动补上标记。如果首次调用前不标记，后续可以走回起点，产生违反“每格最多经过一次”的路线。

初始状态本身也要满足递归约定，不能只检查后续转移是否正确。

例如 $2\times3$ 地图，起点 $(1,1)$、终点 $(1,3)$，障碍为 $(2,3)$，正确路线数为 $2$。漏标起点会额外接受“起点 → $(2,1)$ → 起点 → $(1,2)$ → 终点”，错误得到 $3$。

**2. 终点可能被障碍阻挡。**

原题只保证起点无障碍，不能推广成终点也无障碍。若直接将 `g[fx][fy]` 写成 `2`，会覆盖障碍信息，把不可到达的终点当作空地。

最小反例为 $1\times2$ 地图，从 $(1,1)$ 到 $(1,2)$，唯一障碍就是终点；正确答案为 $0$，覆盖障碍后会错误计为 $1$。

> **题目只保证了哪个对象，就只对那个对象免检。** 用同一数组编码多种含义时，先判断原信息，再覆盖或转换状态。

#### 搜索规模与其他边界

令 $V=NM$。当前路径最多包含 $V$ 个格子，起步最多四个方向，此后由于不能回到上一格，最多三个方向，搜索节点数可粗略上界为 $O(3^V)$；障碍与其他已访问格会继续削减分支。递归栈和按地图规模分配的访问状态为 $O(V)$，原代码的固定数组在本题范围内足够。

这里记录的是**路线数**，不是可达格子数，也不是最短距离。同一个格子可被不同路线分别经过，因此退出当前路径时要将对应标记从 `true` 改回 `false`。只做可达性遍历时，已发现顶点的标记在本轮中不再改回 `false`。

- 起点等于终点且无障碍时，初始调用就记录一种零步路线。
- 每个候选先判断边界，避免把非法坐标用于数组访问。
- 原程序仅处理一组输入，全局数组初始为零，符合原题。若改成多测，应在每组开始清空 `g` 与 `v`；原代码返回后起点标记仍保留，地图也未自动清空。
- 更大范围的路径计数需重新评估时间与答案类型，不能直接把本题实现推广到大地图。

## 10. 两题形成的共同认识

**先确定本层的职责：入口检查完成状态，循环筛选合法下一步，做选择后递归，再按状态含义执行具体撤销操作。** 字符串删除本层追加项，路径访问标记改回 `false`，累计答案不回退。

终点处 `if (...) { 记录结果; return; }` 表示当前方案完成；循环中的 `continue` 表示仅排除当前候选，其他分支继续探索。终止判断是搜索语义，可行性剪枝是减少无效分支，两者作用需分清。

提前排除错误分支可以避免无效深入，但**不保证递归栈一定浅**。组合的最大深度由 `r` 决定，迷宫的最大深度由一条合法路径的长度决定，仍要单独检查调用栈风险。

| 模型 | 如何限制重复使用 | 分支结束时的具体操作 |
| --- | --- | --- |
| 递增生成组合 | 下一层只能选择更大的值 | 参数按值传递，方案槽位覆盖复用 |
| 枚举互异元素的全排列 | 通常用 `used` 记录当前排列中已选元素 | 将本层设为 `true` 的项改回 `false`；交换生成时则交换回原位置 |
| 枚举每格至多经过一次的路线 | 用访问标记记录当前路径占用的位置 | 将退出当前路径的位置从 `true` 改回 `false` |
| 遍历图中全部可达顶点 | 用访问标记记录已发现顶点 | 本轮已发现的顶点继续为 `true`，不重复展开 |

> **需要表达的是“哪些选择仍然合法”；访问数组、递增参数或交换位置，都是表达约束的方式。** 是否需要 `visited` 不能仅凭“是不是枚举搜索”判断。
