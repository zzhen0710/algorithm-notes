# 4.2 区间贪心：最多选择互不冲突的区间

## 1. 解决什么问题

给定若干活动，每个活动必须完整参加，只能同时参加一个。可以放弃部分活动，求**最多能参加多少个**。

本节只讨论**每个区间贡献相同，目标是数量最多**的模型。若目标改成总收益最大、覆盖长度最大或覆盖全部时间，不能直接沿用结论。

前置：[排序贪心与交换论证](01-sorting-greedy.md#3-为什么先选便宜的不会吃亏)。采用 C++11，沿用[竞赛基础框架](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)。

> **优先结束早，是为了让后面尽早重新可用；不是因为当前活动短，也不是因为它开始早。**

## 2. 先确定端点是否允许相接

同样写成起点 `l`、终点 `r`，含义可能不同。设上一个选中区间结束于 `last_r`：

| 区间含义 | 下一段可以接入的条件 | 相接示例 |
| --- | --- | --- |
| 时间段 $[l,r)$，结束时刻已空闲 | $l\ge\mathrm{last\_end}$ | $[1,3)$ 与 $[3,5)$ 可以相接 |
| 闭区间 $[l,r]$，共享端点也冲突 | $l\gt \mathrm{last\_end}$ | $[1,3]$ 与 $[3,5]$ 不能同时选 |

**本节主实现采用非空半开区间，要求 `l < r`，允许首尾相接。** 闭区间版本则可允许 `l == r`，此时它占用一个时刻，不是空区间。

边界来自题意，不能因为两题都叫“区间选择”就照抄 `>` 或 `>=`。也不要随意用 `r+1` 转换：时间未必是整数，整数端点也可能溢出。

## 3. 为什么按结束时间排序

### 开始早，不代表早腾出位置

半开区间为 $[0,10)$、$[1,3)$、$[3,5)$、$[5,7)$。

若先选开始最早的一段，只能选 `1` 段；后三段却可以连续选择，共 `3` 段。

### 长度短，也可能同时挡住两侧

半开区间为 $[0,3)$、$[3,6)$、$[2,4)$。

中间的 $[2,4)$ 最短，却与另外两段都冲突。先选它只能得到 `1` 段，而另外两段可以一起选，得到 `2` 段。

**当前长度短不等于对未来限制小。** 还必须考虑它处于什么位置。

### 结束早，可以保留更多后续候选

在当前能够接入的区间中，设结束最早的一段为 `g`。取任意一个最优后续方案，其第一段为 `o`。

由于 `g` 结束不晚于 `o`：

$$
r_g\le r_o
$$

把 `o` 换成 `g` 后：

1. **当前仍然合法：** `g` 是从能够接入的候选中选出的。
2. **数量不变：** 一段替换一段。
3. **后续仍可接入：** 原来在 `o` 之后的区间，其起点不小于 $r_o$，也就不小于 $r_g$。

因此，至少存在一个最优方案先选 `g`。确定它后，把结束边界更新成 $r_g$，剩下仍是同一种问题，可以继续选择。

闭区间模型中，后续起点原本满足 $l\gt r_o$，同样可推出 $l\gt r_g$，因此**端点规则改变判断条件，但不改变交换论证的方向**。

### 总结：用不更差的边界替换最优选择

**若最优后续方案的第一段是 `o`，候选 `g` 同样能接在已选前缀之后，且 $r_g\le r_o$，则用 `g` 替换 `o`，仍能得到一个最优方案。**

半开模型中，两种选择给后续留下的候选集合满足：

$$
\{I:l_I\ge r_o\}\subseteq\{I:l_I\ge r_g\}
$$

**较早结束留下的可行集合包含较晚结束的可行集合。** 替换保留相同数量，又没有排除原方案的后续区间，这才是选择安全的原因。

这里不能把 `o` 说成最优方案中的任意一段：还需保证 `g` 不与该段之前的选择冲突。也不能只比较右端点，就忽略 `g` 自身是否满足当前边界。

> **思考方向：找到候选对后续施加的限制，证明当前选择的限制不更强，再把它换进某个最优方案。** 仍需同时核对当前合法性和目标贡献，不是仅凭一个不等式就能使用贪心。

## 4. 导引模型的状态与流程

### 变量、容器与范围

- `Interval`：一段活动，`l、r` 是类型为 `int` 的坐标，主实现要求 `l < r`。
- `a`：保存全部区间，长度按**区间条数 `n`**分配，与最大时间无关；位置为 `0..n-1`，条数可用 `int` 表示。
- `last_r`：**最后一段已选区间的结束时间**，不是最后一段已扫描区间的结束时间。
- `noempty`：是否已经选择过区间；首段之前不存在限制边界，不能随意假设从时间 `0` 开始。
- `ans`：已确定选择的区间数量。

**为什么只记最后一段就够了？** 已选区间按时间依次排列，当前起点只要不早于最后结束时间，就不会与更早选中的区间冲突；完整已选列表无需参与后续判断。

若要输出具体方案，应另存原编号；本函数只返回数量。

### 执行流程

1. 按结束时间非降序排序；相同结束时间再按起点排序，便于确定处理顺序。
2. 尚未选入任何区间时，直接选入第一段。
3. 已有选择时，检查当前起点是否能接在 `last_r` 之后。
4. 冲突就跳过，**不修改已选状态**；不冲突才增加数量并更新结束边界。

结束时间相同的合法候选，对后续留下的边界一样。**本模型不要求稳定排序，次关键字也不是最优性的来源。**

**顺便按 `l` 排序没有必要性。** 只比较 `x.r < y.r` 也正确；当前写法保留第二关键字，只是让同结束时间的扫描顺序明确。

若同结束时间的某段起点太早，跳过即可，后面的同结束时间候选仍会接受检查。不能因为第一段冲突，就把整个同终点分组一起丢弃。比较器也不能用 `<=` 代替 `<`。

## 5. 注释实现与手推

下方结构体与函数采用 P1803 提供的原实现，**仅整理排版与注释，保留变量名和逻辑**；典题部分只补 `solve()`，CF 题只展示边界差异，不重复整套代码。可复用接口见 [Templates 索引](../../templates/README.md)。

```cpp
#include <algorithm>
#include <vector>

using namespace std;
using ll = long long;

struct Interval {
    int l;
    int r;
};
```

```cpp
// 区间为非空 [l,r)，允许首尾相接；条数可用 int 表示
// 坐标可为负数，且可用 int 表示；只比较坐标，不做端点加减
// 返回最多选择条数；按值传参，排序不修改调用方的输入
int max_nonoverlap(vector<Interval> a) {
    sort(a.begin(), a.end(), [](const Interval& x, const Interval& y) {
        if (x.r != y.r) return x.r < y.r;
        return x.l < y.l; // 同结束时间时固定处理顺序
    });

    bool noempty = false;
    int last_r = 0; // noempty 为 false 时，此值不参与判断
    int ans = 0;

    for (const auto& cur : a) {
        if (noempty && cur.l < last_r) {
            continue; // 只跳过冲突候选，不改变已选边界
        }

        last_r = cur.r; // 确定选入，才更新下一段需要满足的条件
        noempty = true;
        ++ans;
    }

    return ans;
}
```

假设有五段活动：`A=[0,6)`、`B=[1,3)`、`C=[3,5)`、`D=[4,7)`、`E=[5,8)`。

按结束时间排序后为 `B、C、A、D、E`：

| 当前活动 | 操作前 last_r | 判断与动作 | 操作后 ans / last_r |
| --- | --- | --- | --- |
| B：$[1,3)$ | 尚无已选段 | 选入 | 1 / 3 |
| C：$[3,5)$ | 3 | 允许相接，选入 | 2 / 5 |
| A：$[0,6)$ | 5 | 起点过早，跳过 | 2 / 5 |
| D：$[4,7)$ | 5 | 起点过早，跳过 | 2 / 5 |
| E：$[5,8)$ | 5 | 允许相接，选入 | 3 / 8 |

```cpp
vector<Interval> a = {{0, 6}, {1, 3}, {3, 5}, {4, 7}, {5, 8}};
int ans = max_nonoverlap(a); // 结果为 3，选择 B、C、E；原 a 不变
```

**状态错误的典型后果：** 若跳过 `A` 后仍把 `last_r` 改成 `6`，就会错误挡住本来可以接入的 `E`。这与上一节 [CF 545D 只累计已选前缀](01-sorting-greedy.md#状态只维护已经选入的满意前缀)的原则相同。

### 改成闭区间时

若题目明确**共享一个端点也冲突**，则改为接纳 `cur.l > last_r`；对应的排除条件为：

```cpp
// 闭区间版本的替换片段：输入契约同时改为 l <= r
if (noempty && cur.l <= last_r) {
    continue;
}
```

这里变的是端点语义，不是排序方向。不要只改比较符号，却仍把零长度时间段当成半开模型中的普通活动。

### 怎么想到：维护前缀，优化留给右侧的边界

从左向右构造方案时，**已选区间本来就是一个固定前缀**；接下来所有区间都需要满足“起点不早于最后结束时间”。因此，对未来直接起作用的是当前右端点，应该尽量让它小。

而“开始最早”只说明当前区间左边占得早，不说明右边何时空出来。即使固定了相同的起点，也可能有结束很早和结束很晚的活动，**较小的左端点不能推出对右侧的限制更弱**。

所以问题不在于“固定前缀不行、固定后缀才行”，也不是要让限制更强。**正确方向是让限制不更强，让可接入的选择不更少。**

从右向左也能对称地构造：先选**开始最晚**的一段，再选择结束不晚于该起点的区间。此时固定的是已选后缀，优化的是留给左侧的边界；无需另背一套本质不同的策略。

**题目线索 → 状态 → 规则：** 每段收益相同 → 只需保留最大数量 → 下一段只受已选结束边界约束 → 更早结束不会排除原方案后续 → 按结束时间排序并选择。

## 6. 正确性、复杂度与适用边界

**可行性：** 首段直接选入，之后每段都满足与最后一段不冲突的条件，所以整个已选序列合法。

**最优性：** 每一步都选择当前可接入区间中结束最早的一个，交换论证保证不会减少最优数量。按结束时间顺序扫描正好实现这一选择；已跳过的区间起点太早，后续边界只会增大，不会重新变得可接入。

**复杂度：** 排序 $O(n\log n)$，扫描 $O(n)$，总时间 $O(n\log n)$；按值接收输入会额外复制 $O(n)$ 个区间。每次调用独立初始化，不残留上次的结束边界。

需要特别核对：

- **空输入返回 `0`。** 首段不受虚构的初始时间限制，因此也支持负坐标。
- **相同区间不是自动去重的对象。** 本模型中非空重复区间互相冲突，选择一个即可，由判断自然处理。
- **不能用长度作主排序关键字。** 还可能涉及坐标相减溢出；本实现只比较端点。
- **不能只按起点排序后直接见到就选。** 反例见[开始早的误区](#开始早不代表早腾出位置)。
- **收益不同会破坏“替换后目标不变”。** 例如 $[0,1)$、$[1,2)$ 各收益 `1`，$[0,2)$ 收益 `10`，数量最多的方案不再是收益最大的方案。

最后一种情况可考虑**带权区间调度 DP**。此处保留文字关联，序列 DP 正文整理后再补具体链接，不在当前节提前展开转移。

## 7. 与区间合并的区别

| 方法（Key） | 问题目标 | 对重叠区间的处理 | 需要维护的信息 |
| --- | --- | --- | --- |
| **区间选择贪心** | 最多选多少个互不冲突区间 | 放弃冲突候选 | 最后已选区间的结束边界 |
| **区间合并** | 全部区间的并集长度 | 保留覆盖，合并重叠部分 | 当前合并段的左右边界 |

区间合并通常按起点排序，便于把相邻覆盖接起来；本节按结束时间排序，便于尽早确定一个不会吃亏的选择。

**输入都长成 `(l,r)`，不代表解决的是同一问题。** 已有[离散化 P1496 的区间合并解法](../02-sequence-techniques/03-discretization.md#另一种做法排序合并区间)保留全部覆盖，不是在挑选不冲突活动。

## 8. 典题与复盘

两题是**同一选择模型在不同端点语义下的复用**，不需要分别背两套算法。结构体、排序和状态维护只展示一次。

### 洛谷 P1803 — 凌乱的yyy / 线段覆盖

题目：[P1803 凌乱的yyy / 线段覆盖](https://www.luogu.com.cn/problem/P1803)。

- 给出各场比赛的开始、结束时间；参加就必须完整参加，不能同时参加多场，求最多参加的场数。
- 范围：$1\le n\le10^6$，$0\le a_i\lt b_i\le10^6$。
- **练习目的：** 实现区间选择模型，确认交接时刻的含义，并检查大输入下的排序、扫描和存储成本。
- **状态：复盘完成（本地核验）。** 已提供实际实现，平台评测结果未单独记录，不据代码正确推断平台 AC。

**收录原因：** 将交换论证落实成可复用的边界状态，区分“接纳当前候选”与“扫描到当前候选”，并用首段标记避免虚构初始约束。

#### 原实现与接口

复用第 5 节的 `Interval` 和 `max_nonoverlap`，下方只补原 `solve()`；只改排版和注释，不改变逻辑。

```cpp
void solve() {
    int n;
    cin >> n;

    vector<Interval> a(n);
    for (auto& x : a) cin >> x.l >> x.r;

    cout << max_nonoverlap(a) << '\n';
}
```

**边界：** 本题允许前一场结束后接着参加下一场，起点等于已选终点时可以接入；`noempty` 表示已选序列是否非空，并不是输入数组是否非空。所有时间在 `int` 范围内，排序只比较端点，不需要计算长度。

**实现权衡：** 原函数按值接收数组，保留调用方原顺序，代价是复制一份 $O(n)$ 的空间；若明确允许修改原输入，可以改成引用接收。数量目标与当前状态已经清晰，不另写重复的优化版。

### CF 597B — Restaurant

题目：[CF 597B Restaurant](https://codeforces.com/problemset/problem/597/B)。

- 每份订单占用餐厅一段连续时间，可以拒绝部分订单，求最多接纳多少份。原题明确：**两份订单即使只共享一个时刻，也不能同时接纳**。
- 范围：$1\le n\le5\times10^5$，$1\le l_i\le r_i\le10^9$。
- **练习目的：** 在相近模型中重新核对比较符号，处理允许 `l==r` 的订单，而不是照抄上一题边界。
- **状态：复盘完成（本地核验）。** 提供的实现与 P1803 相同，仅冲突条件改为 `<=`；平台评测结果未单独记录。

**收录原因：** 模板复用前先检查契约；即使排序和扫描完全相同，端点的包含关系仍会改变合法判断。

#### 与上一题只差端点规则

原结构体、排序、其余扫描过程及 `solve()` 全部复用，只改：

```cpp
// CF 597B：共享一个时刻也冲突，包括起点恰好等于上个终点
if (noempty && cur.l <= last_r) {
    continue;
}
```

原题第一组样例的两段为 $[7,11]$ 和 $[4,7]$。它们共享时刻 `7`，只能接受 `1` 份；若错误沿用上一题的 `<` 排除条件，就会接受 `2` 份。

**另一个边界是 `l==r`：** 在本题中，这份订单占用一个时刻，仍然可以单独接纳；同一时刻的两份订单不能同时接纳。两题复杂度均为 $O(n\log n)$，差异来自模型契约，不是算法层级。
