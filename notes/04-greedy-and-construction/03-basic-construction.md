# 4.3 基础构造：必要条件、充分性与不变量

## 1. 构造题要求什么

前两节主要计算最多能选多少个对象；构造题通常还要求**输出一个真正满足条件的方案**，或者说明不存在。

**知道答案存在，不等于已经给出构造；写出一个例子，也不等于覆盖了全部合法输入。** 需要把判断条件、生成方法和正确性连起来。

> **先从约束推出必要条件，再给出满足条件时一定成功的构造。** 两边都证明后，才能把条件作为完整的有解判定。

前置：[贪心中的交换论证](01-sorting-greedy.md#3-为什么先选便宜的不会吃亏)、[DFS 与回溯](../03-search/01-dfs-backtracking.md)。使用 C++11，沿用[竞赛基础框架](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)。

## 2. 导引模型：相邻位置不能同时放 1

构造一个只含 `0、1` 的字符串，要求：

- 长度恰好为 `n`。
- 恰好有 `k` 个 `1`。
- **不能出现相邻的两个 `1`**。
- **首尾不是相邻位置**，这是普通线性字符串，不是环。

例如 `n=7、k=3` 时，`1010100` 是合法方案。答案不要求唯一，也不要求字典序最小。

### 必要条件：先算最少需要多少位置

若 $k>0$，放下 $k$ 个 `1` 至少需要在它们之间留出 $k-1$ 个 `0`，因此：

$$
n\ge k+(k-1)=2k-1
$$

等价地，对于非负整数 `n、k`：

$$
k\le\left\lceil\frac n2\right\rceil
$$

**只检查 `k<=n` 不够。** 例如 `n=3、k=3`，虽然位置数量足以容纳三个 `1`，但无法满足间隔要求。

`k=0` 时无需分隔，全部填 `0`；`n=0、k=0` 时空字符串也合法。后面的统一条件和实现同时覆盖这些情况。

### 充分性：把 1 放在固定间隔的位置

若上述条件成立，将 `1` 放在 **0-based 下标 `0、2、4、...、2(k-1)`**，其余位置填 `0`。

这样得到：

1. **数量正确：** 写入的是 `k` 个不同位置。
2. **相邻条件正确：** 任意两个 `1` 的下标至少相差 `2`。
3. **位置合法：** 最后一个下标不超过 `n-1`，正是必要条件保证的范围。

因此，该条件不仅能排除无解输入，还保证这套构造可以完成。

**不是条件看起来足够，而是构造证明了它足够。** 构造时无需搜索所有字符串，也不必每放一个位置都回头尝试。

**如何想到：** 只需一个合法方案 → 先处理必须相互隔开的 `1` → 用 `0` 留出最少间隔 → 将其余位置补成 `0`。额外的 `0` 不会破坏已满足的间隔，构造便可以直接完成。

## 3. 状态、容量与执行流程

### 变量与范围

- `n`：最终字符串长度，**容量由位置数决定**，不是由 `k` 或字符值决定；有效下标为 `0..n-1`。
- `k`：需要的 `1` 的数量，与字符串下标不是同一个量。
- `s`：输出参数，调用开始先清空；成功时保存合法方案，失败时保持为空。
- `i`：已经写入的 `1` 的数量；第 `i` 次要写的位置是 `2*i`。
- 返回值：`true` 表示构造成功，`false` 表示输入不合法或不存在满足要求的字符串。

`n、k` 使用 `int`。非负长度必须适合实际内存；本节函数不处理内存分配失败。字符使用 `'0'、'1'`，不是数值 `0、1`。

### 执行流程

1. 清空上一次输出，拒绝负长度或负数量。
2. 检查数量是否超过最多可放的 `1` 的个数；失败则返回。
3. 建立长度为 `n`、全部为 `0` 的字符串。
4. 依次将前 `k` 个偶数下标改成 `1`，返回成功。

**先检查可行性，再按已证明的布局填入。** 生成位置时不需要反复判断左右邻居，因为布局本身已经保证间隔。

## 4. 注释实现与不变量

以下是导引模型的教学实现，不是后面典题的专属解法。

```cpp
#include <string>

using namespace std;
```

```cpp
// 线性字符串，不要求首尾分隔；n、k 为非负时按题目条件判断有解
// 成功覆盖 s，失败清空 s；空串也可能是成功结果，必须看 bool
bool build_binary(int n, int k, string& s) {
    s.clear(); // 防止失败后误用上一组的方案

    if (n < 0 || k < 0) return false;

    // ceil(n/2)；用除法和余数，避免先计算 n+1 或 2*k 时溢出
    if (k > n / 2 + n % 2) return false;

    s.assign(n, '0');

    for (int i = 0; i < k; ++i) {
        s[2 * i] = '1'; // 条件保证下标合法，固定间隔保证不相邻
    }

    return true;
}
```

### 不变量到底说明什么

**每次循环开始前：** 字符串长度仍为 `n`，恰好放了 `i` 个 `1`，它们位于 `0、2、...、2(i-1)`，其余位置仍为 `0`。

- 初始 `i=0`，没有放 `1`，全部为 `0`，条件成立。
- 写入 `2*i` 后，多一个 `1`，位置没有重复，也不与已放的 `1` 相邻。
- 循环结束时 `i=k`，数量和间隔要求同时满足。

**还要说明下一步做得下去。** 当前结果暂时合法，不代表一定能补完；本模型提前验证了总长度，所有预定位置都在范围内，因此不会走到最后才发现缺位置。

例如 `n=7、k=3`：

| 阶段 | 本次写入位置 | 字符串 | 已放 1 的数量 |
| --- | --- | --- | --- |
| 初始化 | 无 | `0000000` | 0 |
| 第 1 次 | 0 | `1000000` | 1 |
| 第 2 次 | 2 | `1010000` | 2 |
| 第 3 次 | 4 | `1010100` | 3 |

```cpp
string s;
bool ok = build_binary(7, 3, s); // true，s 为 "1010100"
bool empty_ok = build_binary(0, 0, s); // true，s 为空
bool impossible = build_binary(3, 3, s); // false，s 仍为空
```

**不能用 `s.empty()` 判断是否无解**，因为空字符串本身可能是合法答案。调用结果与输出内容各有职责。

成功时建立输出需要 $O(n)$ 时间，构造循环为 $O(k)$，由可行性知总时间为 $O(n)$；输出占 $O(n)$ 空间，除此之外只需常数状态。每次调用重置输出，无多测残留。

## 5. 奇偶与不变量：用来排除，不是替代完整证明

奇偶性常用来检查一个构造有没有可能。例如每次只给一个整数加 `2`，这个整数的奇偶性不会变化。

但从 `0` 出发，不能仅凭目标是偶数就声称可达：目标 `-2` 也是偶数，却无法只靠加 `2` 到达。

> **不变量给出必要条件，还需要考虑操作方向、范围和具体构造。**

同样，写出几组有规律的答案之后，还应检查：

- **覆盖全部合法输入了吗？** 小规模、临界值、奇偶长度是否需要不同处理？
- **每一步合法吗？** 除总数和总和外，位置关系、取值下限是否都满足？
- **结束时恰好满足要求吗？** 不能只做到“不超出”，却忘了补齐数量。

若过程同时修改“剩余数量”和“未填位置”，应明确二者之间必须一直保持的关系；不能只让计数变成 `0`，却不检查生成的对象。

## 6. 与贪心、搜索的区别

| 方法（Key） | 要解决的核心问题 | 正确性依据 |
| --- | --- | --- |
| **构造** | 直接生成满足要求的一个方案 | 条件足够、每步合法、终态满足全部要求 |
| **优化型贪心** | 确定当前选择，仍能得到最优目标 | 交换论证、边界比较或独立选择等性质 |
| **搜索** | 尝试多个候选并按状态回退 | 分支覆盖完整，剪枝不会误删合法方案 |

构造可以使用贪心或搜索，也可以像本节一样直接使用固定布局。**构造不一定有“最优”要求，因此不必给每种构造硬套交换论证。**

- 方案验证应分两部分：

1. **存在性判断：** 若输出无解，是否真的不存在？小输入可用枚举全部候选对照。
2. **结果验证：** 若输出方案，检查长度、数量、范围和全部关系条件，不能只与样例答案逐字比较。

这与 [CF 687A 的多解输出](../06-graph-and-tree/02-bipartite-coloring.md#整理实现全部染色只收集与边相连的点)中“加入或省略孤立点都可能合法”的检查原则相同。

### CF 1352B — Same Parity Summands

题目：[CF 1352B Same Parity Summands](https://codeforces.com/problemset/problem/1352/B)。

- 将正整数 `n` 拆成恰好 `k` 个正整数，要求所有项的奇偶性相同；有解输出任意一组，无解输出 `NO`。
- 范围：$1\le n\le10^9$，$1\le k\le100$，测试组数不超过 `1000`。
- **练习目的：** 同时核对数量、总和、正数范围与奇偶要求，区分必要条件和完整有解判定。
- **状态：复盘完成（本地核验）。** 平台评测结果未单独记录。

**收录原因：** 不再直接猜每个答案项，而是先铺出最小合法基值，再把总量差额转成可检查的剩余量；用构造证明分类条件充分，将零散边界归并到同一个模型。

#### 核心思路：必要条件筛选 → 基值分类 → 剩余量构造

每项必须为正，`k` 项至少需要总和 `k`。因此 **`n<k` 一定无解，但 `n>=k` 还不能保证有解**。

接着从答案入手：既然所有项奇偶性相同，只有**全奇数、全偶数**两类，分类已经穷尽，不需要猜其他组合。

| 分类 | 每项最小合法基值 base | 基线总和 | 剩余量 rest | 该类可行的完整条件 |
| --- | --- | --- | --- | --- |
| 全奇数 | 1 | `k` | `n-k` | `rest>=0` 且为偶数 |
| 全偶数 | 2 | `2*k` | `n-2*k` | `rest>=0` 且为偶数 |

**为什么只能补偶数？** 给奇数或偶数加 `2` 的整数倍，原奇偶性不会改变。

固定基值 $b\in\{1,2\}$ 后，每项都能写成：

$$
a_i=b+2x_i,\qquad x_i\in\mathbb{Z}_{\ge0}
$$

将总和条件改写为：

$$
\mathrm{rest}=n-kb=2\sum_{i=1}^{k}x_i
$$

所以剩余量非负且为偶数是**必要条件**。反过来，只要满足它，让前 `k-1` 项都等于 `b`，最后一项等于 `b+rest` 即可。

- **正数与奇偶合法：** 基值已经合法，增加非负偶数不会破坏它们。
- **数量合法：** 前 `k-1` 项加最后一项，恰好 `k` 项。
- **总和合法：** 基线总和 `k*b` 加剩余量，恰好为 `n`。

这同时证明条件**充分**。两类都失败才是真的无解；任意一类成功，就能直接生成答案。

> **重点不是记住两组公式，而是：先给每项一个最小合法基值，把所有待分配自由度压成剩余量，再证明剩余量可以怎样补入。**

例如 `n=10、k=3`，奇数基线剩 `7`，无法保持全奇数；偶数基线剩 `4`，可得到 `2、2、6`。这里的分类来自答案约束，构造来自基线与差额，不是试出一组数再猜规律。

#### 原实现

以下保留实际提供的逻辑，只调整排版与注释；`n<=10^9、k<=100`，原来的 `int` 和 `2*k` 在题目范围内安全。

```cpp
void get_ans(int n, int k) {
    if (n < k) { // 整体必要条件：k 个正整数至少需要总和 k
        cout << "NO\n";
        return;
    }

    bool ok1 = !((n - k) % 2); // 已知 n>=k，只需检查奇数基线的余量
    bool ok2 = (n >= 2 * k ? !((n - 2 * k) % 2) : false);
    if (!ok1 && !ok2) { // 两类均不可行，才说明不存在同奇偶拆分
        cout << "NO\n";
        return;
    }

    cout << "YES\n";
    if (ok1) {
        for (int i = 0; i < k - 1; ++i) cout << "1 ";
        cout << n - k + 1 << '\n'; // 最后一项 = 1 + (n-k)
    } else {
        for (int i = 0; i < k - 1; ++i) cout << "2 ";
        cout << n - 2 * k + 2 << '\n'; // 最后一项 = 2 + (n-2k)
    }
}

void solve() {
    int n, k;
    cin >> n >> k;

    get_ans(n, k);
}
```

#### 整理实现：枚举基值，合并重复分支

原实现已经正确。更易检查的写法是**只枚举两种基值，每种都计算同一个 `rest`**，避免同时维护 `ok1、ok2` 和两套输出公式。

```cpp
// 使用与原实现相同的题目范围；solve() 保持不变，选择此版本 get_ans 即可
void get_ans(int n, int k) {
    for (int base = 1; base <= 2; ++base) {
        int rest = n - base * k;
        if (rest < 0 || rest % 2 != 0) continue;

        cout << "YES\n";
        for (int i = 0; i < k - 1; ++i) cout << base << ' ';
        cout << base + rest << '\n'; // 基线不动，差额集中补到最后一项
        return;
    }

    cout << "NO\n";
}
```

不再单独写 `n<k`，是因为两种基线的 `rest<0` 已经统一覆盖该情况。**两版判断均为 $O(1)$，输出为 $O(k)$，额外空间为 $O(1)$；收益是减少重复逻辑，不是提高渐进复杂度。**

#### 边界怎样统一检查

| 边界 | 需要确认的含义 |
| --- | --- |
| `n<k` | 连全为 `1` 都不够，必定无解 |
| `k=1` | 前 `k-1` 项的循环为空，最后一项就是 `n`，总能构造 |
| `n=k` | 奇数基线余量为 `0`，全为 `1`，合法 |
| `k<=n<2*k` | 只能尝试全奇数；总量够正数，不代表够全偶数 |
| `rest=0` | 基线本身就是答案，不能把 `rest>0` 当条件 |
| `k` 为偶数、`n` 为奇数 | 全奇数求和也为偶数，两种分类都失败 |
| 两种分类都可行 | 输出任意一种即可；原实现和整理版都优先全奇数 |

**边界不必逐个新增分支。** 将它们代回“余量非负、余量为偶数”，再检查输出的正数、数量、总和与奇偶性即可。多解时不要求与样例数值相同。

#### 经验：用一般条件解释样例，少加孤立特判

**不要因为样例 `8 7` 无解，就先记住“`n=k+1` 时输出 `NO`”。** 应回到基值与剩余量，解释它为什么无解：奇数基线剩 `1`，奇偶不符；偶数基线剩 `-6`，总量不足。两个一般条件已经覆盖，不需要额外分支。

而且 `n=k+1` 并非一律无解：`n=2、k=1` 可以直接输出 `2`。当 `k>=2` 时，这类输入确实无解，但仍然由上述余量条件自然推出。

> **样例用于检验推导；构造规则从约束本质出发。** 读懂样例后，用同一套条件解释它和其他边界，避免排除了一个现象，却没有找到产生它的原因。

#### 如何想到与迁移

**固定项数且总和给定 → 每项有正数下限 → 同奇偶要求给出两种最小基值 → 超出基线的部分必须按步长 `2` 增加 → 用一项吸收全部合法余量。**

这里能把全部余量放到最后一项，依赖**没有单项上限、大小关系或相邻关系限制**。有额外约束时，不能照搬“最后一项兜底”。

这条思路提炼为[基值与剩余量：先铺合法基线，再补足总量](../../patterns/04-greedy-and-construction/baseline-residual-construction.md)，完整题解与实际代码仍留在本节。

### CF 1512C — A-B Palindrome

题目：[CF 1512C A-B Palindrome](https://codeforces.com/problemset/problem/1512/C)。

- 将字符串中的 `?` 替换成 `0` 或 `1`，保留已有字符，使结果为回文，且 `0、1` 的数量分别恰好为 `a、b`；无解输出 `-1`。
- 范围：$0\le a,b\le2\times10^5$，$a+b\ge1$；字符串长度为 `a+b`，所有测试的总长度不超过 $2\times10^5$。
- **练习目的：** 同时维护局部关系与全局数量，保证中间处理没有破坏已有约束，最后验证全部条件。
- **状态：复盘完成（本地核验）。** 平台评测结果未单独记录。

**收录原因：** 把局部对称关系与全局数量分开维护；先完成没有选择余地的约束，再对真正自由的位置分配资源，并识别“成对消耗”和“中心单点”的区别。

#### 原思路：镜像配对扣数量，自由位置暂存

使用 **0-based** 下标，镜像位置为 `l` 与 `r=n-1-l`。不能把所有 `?` 独立填入，因为左右两端必须相等。

| 镜像两端 | 处理 | 数量消耗 |
| --- | --- | --- |
| `00`、`11` | 保留已有字符 | 对应数量减 2 |
| `0?`、`?0` | 强制补成 `00` | `a` 减 2 |
| `1?`、`?1` | 强制补成 `11` | `b` 减 2 |
| `01`、`10` | 已有字符冲突，无法修改 | 无解 |
| `??` | 两端一起暂存，稍后选择字符 | 暂不消耗 |

奇数长度还存在中心位置。**已知中心只扣 `1`，未知中心也只需要一个字符，不能按普通镜像对扣 `2`。**

原实现中：

- `a、b`：完成强制部分后，剩余可填的 `0、1` 数量，已经不是初始目标数量。
- `pos`：长度最多为 `n`，**按位置数分配空间**；每两个相邻记录是一对 `??` 的镜像位置。
- `mid`：未知中心的下标，若不存在为 `-1`。未知中心在所有镜像对之后加入 `pos`，始终是最后一条记录。

因此，`pos` 不是可以随意重排的下标集合。若打乱它的顺序，之后按相邻两项配对就可能破坏镜像关系。

#### 原实现

以下只整理排版和注释，保留原逻辑，包括平铺的 `pos`、中心最后填入，以及全部原判断。

```cpp
void get_ans(int a, int b, string& s) {
    if (a + b != s.size()) { // 题目保证长度，此处额外防御不一致的输入
        cout << "-1\n";
        return;
    }

    vector<int> pos; // 成对保存双问号；未知中心若存在，最后加入
    int l = 0, r = s.size() - 1;

    while (l < r) {
        if (s[l] == s[r]) {
            a -= 2 * (s[l] == '0');
            b -= 2 * (s[l] == '1');

            if (s[l] == '?') {
                pos.push_back(l);
                pos.push_back(r);
            }
        } else {
            if (s[l] != '?' && s[r] != '?') {
                cout << "-1\n";
                return;
            }

            if (s[l] == '0' || s[r] == '0') {
                s[l] = s[r] = '0';
                a -= 2;
            } else {
                s[l] = s[r] = '1';
                b -= 2;
            }
        }

        ++l;
        --r;
    }

    int mid = -1;
    if (l == r) {
        if (s[l] == '?') {
            mid = l;
            pos.push_back(mid);
        } else if (s[l] == '0') {
            --a;
        } else {
            --b;
        }
    }

    if (a < 0 || b < 0 || a + b != pos.size()) {
        cout << "-1\n";
        return;
    }

    for (int i = 0; i + 1 < pos.size(); i += 2) {
        if (a >= 2) { // 当前处理镜像对；不足 2 的余额留给未知中心
            s[pos[i]] = s[pos[i + 1]] = '0';
            a -= 2;
        } else if (b >= 2) {
            s[pos[i]] = s[pos[i + 1]] = '1';
            b -= 2;
        } else {
            cout << "-1\n";
            return;
        }
    }

    if (mid != -1) {
        if (a == 1) {
            s[mid] = '0';
            --a;
        } else if (b == 1) {
            s[mid] = '1';
            --b;
        } else {
            cout << "-1\n";
            return;
        }
    }

    cout << s << '\n';
    return;
}

void solve() {
    int a, b;
    cin >> a >> b;

    string s;
    cin >> s;

    get_ans(a, b, s);
}
```

**类型提醒：** 原稿在 `int` 与 `size()` 的比较处存在有符号/无符号比较警告。本题长度最多 $2\times10^5$，可先转成 `int` 统一比较类型；原段保留实际写法，整理版采用明确长度。

#### 为什么原来的中心最后处理也正确

完成强制部分后，原实现保持：

$$
a+b=\text{剩余未填位置数}
$$

每填一对，就从位置数和对应数量中同时扣 `2`，且只在数量至少为 `2` 时填入，因此余额不为负。

- **没有未知中心：** `pos` 长度为偶数，全部配对完成后剩余位置为 `0`，非负的 `a、b` 只能都为 `0`。
- **有未知中心：** `pos` 长度为奇数，`i+1<pos.size()` 保证最后一个中心不进入配对循环。配对完成后余额之和为 `1`，恰好一个数量为 `1`，另一个为 `0`，可以填中心。

所以原版没有末尾 `a==0 && b==0` 检查，并不构成错误；这个结论依赖**数量与未填位置同步扣减**，不能脱离不变量单独省略判断。

#### 整理实现：强制传播 → 扣除已有数量 → 处理中心 → 填自由对

可以不保存 `pos`：先把单边已知的镜像对补齐，再统一统计已有字符，最后重新扫描剩余双问号。

>**强制传播后再扣数量**，可以让每个已知字符只参与一次统计，避免把原字符、被补齐字符和剩余额混在同一个分支，即实现**情况解耦**。

若中心也是 `?`，剩余位置数为 `2p+1`，因此 `a+b` 为奇数，**两类余额中恰好一个为奇数**；中心必须消耗这一类的 `1`，之后才能全部按镜像对消耗。若没有未知中心，两类余额就应直接为偶数。

```cpp
// 输入字符仅为 0、1、?，数量及长度遵循题目范围
// 成功原地填好 s；失败可能已做部分修改，不保证恢复原串
bool fill_palindrome(int a, int b, string& s) {
    int n = static_cast<int>(s.size());
    if (a + b != n) return false;

    for (int l = 0, r = n - 1; l < r; ++l, --r) {
        if (s[l] == '?' && s[r] != '?') s[l] = s[r];
        if (s[r] == '?' && s[l] != '?') s[r] = s[l];
        if (s[l] != s[r]) return false; // 两端已知却不同
    }

    for (char c : s) {
        a -= (c == '0');
        b -= (c == '1');
    }
    if (a < 0 || b < 0) return false;

    if (n % 2 == 1 && s[n / 2] == '?') {
        // 自由镜像对都消耗 2；剩余数量中为奇数的一类必须占中心
        if (a % 2 == 1) {
            s[n / 2] = '0';
            --a;
        } else if (b % 2 == 1) {
            s[n / 2] = '1';
            --b;
        } else {
            return false;
        }
    }
    if (a % 2 != 0 || b % 2 != 0) return false;

    for (int l = 0, r = n - 1; l < r; ++l, --r) {
        if (s[l] != '?') continue; // 剩下的问号必然成对

        if (a >= 2) {
            s[l] = s[r] = '0';
            a -= 2;
        } else if (b >= 2) {
            s[l] = s[r] = '1';
            b -= 2;
        } else {
            return false;
        }
    }

    return a == 0 && b == 0; // 明确检查终态，所有目标数量恰好用完
}
```

原 `solve()` 读取完输入后，将最后的调用替换为：

```cpp
if (fill_palindrome(a, b, s)) cout << s << '\n';
else cout << "-1\n";
```

**两版时间均为 $O(n)$。** 原版的 `pos` 最坏需要 $O(n)$ 辅助空间，整理版按阶段顺序扫描，除输入输出字符串外只需 $O(1)$ 辅助空间；代价是增加一次顺序扫描，换来状态拆分清楚、无需维护下标配对表。

#### 分阶段解耦：让每一步交出更简单的状态

**更一般的收获是：先消除能确定的情况，再统一核算资源；处理完特殊位置后，让普通部分使用同一种规则。** 这是一种组织解题过程的方法，可用于构造、模拟和预处理，不局限于回文题。

| 阶段 | 当前只负责什么 | 交给下一阶段的保证 |
| --- | --- | --- |
| **约束传播** | 由已知一端确定另一端，排除已有冲突 | 镜像对要么已知且相等，要么是 `??` |
| **资源核算** | 扫描全部已知字符，统一扣除目标数量 | `a、b` 只表示余额，其和等于未填位置数 |
| **特殊位置** | 单独确定未知中心，消耗一个字符 | 剩下全部按对填，两类余额都为偶数 |
| **统一构造** | 给同质自由对分配 `00` 或 `11` | 每次只按 `2` 消耗，不再区分中心与单边已知 |
| **终态检查** | 检查剩余数量是否恰好为零 | 整个方案满足精确数量要求 |

**字符如何确定，与数量如何扣减，可以分开处理。** 第一阶段只改变字符串，暂不修改 `a、b`；第二阶段只统计当前字符串，不再关心某个字符原本就有，还是刚刚传播补出的。每个已知字符统一扣一次，减少漏扣、重复扣以及分支间状态含义不一致的风险。

例如 `a=2、b=2、s="0???"`：先传播为 `0??0`，再统一统计得到余额 `a=0、b=2`，剩下一对直接填 `11`。后面无需继续区分左端原有的 `0` 和右端补出的 `0`。

**阶段顺序来自依赖关系。** 传播后的字符应参与统一计数；未知中心按单个消耗，提前处理它后，普通阶段就只面对成对位置。原版把中心留到最后也正确，整理版选择提前处理，是为了让后续规则统一。

> **每完成一个阶段，都明确“已经确定什么、还剩哪些自由度、下一阶段可以直接相信什么”。** 通过收敛情况减少后续判断，比同时维护所有情况更容易推理、实现和核验。

通用的识别线索、其他应用及传播顺序的限制，见[分阶段解耦范式](../../patterns/04-greedy-and-construction/staged-constraint-decoupling.md)；本节保留回文问题的具体阶段与实现。

#### 为什么先填 0 的自由对不会堵死后续

强制部分与中心处理完后，未填位置只剩相互独立的镜像对，每对可以任取 `00` 或 `11`。

**此时 `a、b` 均为非负偶数，且总和恰好等于剩余位置数。** 需要的零对数为 `a/2`，一对数为 `b/2`，两者之和正好等于自由对数。所有自由对没有区别，因此把前若干对填成 `00`，其余填成 `11` 就能完成，不需要搜索分配顺序。

这里的“先填 0”不依赖最优性，只因为**在真正自由且同质的槽位之间交换分配，不会改变可行性**。如果没有先完成强制传播，某个表面自由的位置可能已被另一端限制，提前分配就可能消耗必须留给它的数量。

#### 实现体会：边界多时，先把阶段和状态拆清楚

**本题边界较多，写到后面明显力竭。** 主要负担是同时顾及镜像关系、已有字符、两类剩余数量和中心位置，而不是循环本身复杂。

后续遇到类似构造，可以先列出检查顺序：**已有冲突 → 强制补齐 → 余额非负 → 中心奇偶 → 成对填充 → 终态校验**。每一阶段写清“已经确定什么、还剩什么”，将边界归入对应阶段，减少在一个大循环中同时记住所有情况的负担。

#### 中心与边界

| 情况 | 需要检查什么 |
| --- | --- |
| 已知两端不同 | 无法修改原字符，立即无解 |
| 强制补齐后某类超出数量 | 余额变负，不能用后续填充补救 |
| 没有未知中心 | 余下都按 2 消耗，两类余额都必须为偶数 |
| 存在未知中心 | 中心消耗 1，必须给剩余数量为奇数的一类 |
| 长度为 1 | 只有中心，没有镜像对；已知字符仍需核对数量 |
| `a=0` 或 `b=0` | 不能填入该类字符，也不能保留与目标冲突的已知字符 |
| 多个答案都合法 | 检查回文、已知字符、数量和是否还有 `?`，不逐字对比样例 |

例如 `a=3、b=2、s="?????"`，中心应为 `0`；其余两个自由对分别用 `00`、`11`，可以得到 `01010`。若 `a=3、b=3、s="??????"`，没有中心，两类数量都是奇数，无法只靠成对位置填完。

**如何想到：** 回文要求镜像相等 → 单边已知的位置没有选择余地 → 先扣掉这些强制消耗 → 剩下只有自由对和至多一个中心 → 用消耗单位 `2、1` 判断余量并完成构造。

与上一题相比，这里不能把差额直接放到一个位置：**每个位置容量只有一个字符，镜像关系又让普通位置成对消耗。** 可迁移的是“先处理固定部分，再识别剩余自由度”，不是照搬最后一项吸收全部余量的写法。
