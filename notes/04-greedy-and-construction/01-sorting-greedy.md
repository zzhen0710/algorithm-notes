# 4.1 排序贪心与交换论证

## 1. 贪心在做什么

面对多个合法选择，搜索可以逐个尝试、返回后再换一种；贪心则根据问题性质，**直接确定当前选择，不再枚举这一步的其他分支**。

例如预算有限，想买尽可能多的物品，可能想到先买便宜的。但“看起来更合适”只是候选策略，还需要回答：

> **确定这一步以后，是否仍然能得到原问题的最优答案？**

> 贪心不一定需要排序。排序只是让某种优先级变得容易维护；真正需要证明的是按这个优先级选择不会吃亏。

前置：[排序与比较器](../01-basic-problem-solving/04-stl/algorithms/15-lambda-comparators.md)。本节采用 C++11，沿用[竞赛基础框架](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)。

## 2. 导引模型：预算内最多选多少件

有若干件物品，每件最多选一次，价格非负。总花费不能超过预算，目标是**所选件数最多**。

**适用条件：** 所有物品的收益都只是“增加一件”，物品之间没有捆绑、互斥或先后依赖，可以任意选择。

### 变量、容器与范围

- `cost`：保存每件物品的价格，类型为 `vector<int>`；**长度按物品数 `n` 分配，与最大价格无关**。
- `n`：物品数，可用 `int` 表示；数组位置为 `0..n-1`。相同价格的不同物品仍分别计数。
- `budget`：总预算，类型为 `ll`，非负且不超过该类型上限。
- `used`：已经确定选入的物品总花费，始终满足 `0 <= used <= budget`。
- `ans`：已经选入的件数；它记录数量，不是总价值。
- `x`：当前物品的价格；排序后按从小到大的顺序读取。

**保存状态的理由：** 后续能否再选一件，只取决于剩余预算 `budget-used`；当前目标还需要单独记录已选件数。

### 执行流程

1. 将价格按非降序排列。
2. 从最便宜的物品开始检查，初始 `used=0、ans=0`。
3. 当前价格不超过剩余预算，就选入，更新花费与件数。
4. 若当前物品已经买不起，后面的价格只会更大，可以直接结束。

这里能 `break`，依赖的是**已经排序，后面也不会买得起**。不能把这个退出条件原样搬到未排序数组中。

## 3. 为什么先选便宜的不会吃亏

### 交换论证：把其他最优方案改成当前选择

假设某个最优方案选了 `k` 件，却没有选当前最便宜的物品 `x`。

只要 `k>0`，从该方案中取一件物品 `y`，用 `x` 替换它。由于 `x <= y`：

- **件数不变**：还是 `k` 件。
- **花费不增加**：原本不超预算，替换后仍合法。
- **其他条件不受影响**：本模型没有物品之间的额外关系。

因此，至少存在一个最优方案包含 `x`。确定选它之后，扣除相应预算，剩下仍是同一种问题，可以继续选择。

> **交换论证不要求所有最优方案都采用当前选择，只需证明至少有一个最优方案可以这样选择。**

### 排序前缀为什么足以判断答案

重复上述替换，可以把任意 `k` 件方案换成**最便宜的 `k` 件**，且花费不增加。

设排序后的价格为 $c_0\le c_1\le\cdots\le c_{n-1}$，最便宜的 $k$ 件总花费为：

$$
S_k=\sum_{i=0}^{k-1}c_i,\qquad S_0=0
$$

于是有：

$$
\text{存在合法的 }k\text{ 件方案}\iff S_k\le\mathrm{budget}
$$

扫描选到 `ans` 件时，若再加下一件就超预算，说明连最便宜的 `ans+1` 件都不可行，其他同样件数的方案更不可能可行。

这里的 `used` 就是在顺序维护 $S_k$，不需要为了只扫描一次，再建立完整前缀和数组。

## 4. 注释实现与小例子

下面是导引模型的通用代码，不是后面典题的专属解答。

```cpp
#include <algorithm>
#include <vector>

using namespace std;
using ll = long long;
```

```cpp
// cost 的价格非负，元素数可用 int 表示；budget 是非负 ll
// 每件最多选一次，所有物品收益相同且没有额外选择约束
// 返回最多件数；按值接收 cost，排序不会改变调用方的原数组
int max_count(vector<int> cost, ll budget) {
    sort(cost.begin(), cost.end());

    ll used = 0;
    int ans = 0;

    for (int x : cost) {
        // 先比较剩余预算，避免先计算 used+x 时可能溢出
        if (x > budget - used) break;

        used += x; // 已确定合法，再更新状态
        ++ans;
    }

    return ans;
}
```

例如价格为 `6、2、4、3`，预算为 `9`，排序后是 `2、3、4、6`：

| 当前价格 | 操作前剩余预算 | 决策 | 操作后 used / ans |
| --- | --- | --- | --- |
| 2 | 9 | 选入 | 2 / 1 |
| 3 | 7 | 选入 | 5 / 2 |
| 4 | 4 | 恰好够，选入 | 9 / 3 |
| 6 | 0 | 买不起，结束 | 9 / 3 |

```cpp
// 空数组也合法；这里展示普通调用
vector<int> cost = {6, 2, 4, 3};
int ans = max_count(cost, 9); // 结果为 3，cost 保持原顺序
```

排序为 $O(n\log n)$，扫描为 $O(n)$，总时间为 $O(n\log n)$。本写法复制输入，额外保存 $O(n)$ 个元素；每次调用独立初始化，无多测残留。

### 边界与前提

- **恰好用完预算仍合法**，所以超预算才退出，不能把 `>` 改成 `>=`。
- 空数组返回 `0`；预算为 `0` 时，价格为 `0` 的物品仍可选入。
- **相同价格不需要去重**，每个数组位置是一件物品。
- 负价格不属于此模型；若题目允许负数，需重新检查状态范围和退出依据。
- 若要输出原物品编号，应让价格与编号一起排序，不能排序后把新位置当成原编号。

## 5. 怎样检验一个贪心想法

### 先写清目标，再提出规则

**“件数最多”和“价值最大”不是同一个目标。** 例如预算 `2`，两件物品的“价格、价值”分别是 `(1,1)`、`(2,100)`，优先买便宜物品并不能得到最大价值。

**目标改变，原证明中的“替换后收益不变”就失效了。** 不是代码仍能运行，策略就仍然正确。

这类**每件最多选一次、不同物品有不同价值**的问题，可以考虑 **0/1 背包 DP**，保留不同容量下的最优价值，而不是直接确定唯一选择。

关联：[0/1 背包的状态与转移](../05-dynamic-programming/02-zero-one-knapsack.md#3-按最后一件物品分类推出转移)。仍需检查物品件数与容量数值是否适合枚举，不是贪心失败就一定能按容量开表。

### 主动找会破坏后续选择的情况

比如用面值 `1、3、4` 的硬币凑出金额 `6`，每种可以重复使用，若每次先选最大的可用面值，会得到 `4+1+1`，而 `3+3` 更少。

这说明“当前减少得最多”不自动等于“最终步骤最少”。**一个反例足以推翻策略；多个样例通过不能代替证明。**

这类**每种硬币可重复使用、恰好凑出金额并求最少数量**的问题，可以考虑 **完全背包 DP 的最少硬币模型**。

关联：[完全背包的最少硬币模型](../05-dynamic-programming/03-complete-knapsack.md#61-最少硬币)。两种容量 DP 都需检查容量或金额是否适合枚举，不能因贪心失败就忽略 DP 的规模代价。

常用检查顺序：

1. 明确每一步选择什么、合法条件是什么、最终优化什么。
2. 构造少量元素、相同值、恰好卡边界等小输入，尝试推翻规则。
3. 找一个采用不同选择的最优方案，说明怎样交换成当前选择。
4. 同时检查交换后的合法性和目标值，再说明后续为什么仍可继续。

小规模可以用[枚举](../01-basic-problem-solving/02-enumeration.md)或[DFS](../03-search/01-dfs-backtracking.md)求真正最优值，与候选贪心对照；这是发现错误的工具，通用正确性仍需论证。

## 6. 与已有模型的区别

| 模型 | 需要说明的依据 |
| --- | --- |
| 本节排序贪心 | 当前选择可以保留某个最优方案，再缩小剩余问题 |
| 双指针 | 当前端点或候选为什么可以安全排除，不漏解 |
| 二分答案中的贪心 check | 给定限制后，检查是否可行；外层再**根据单调性**寻找最优限制 |
| 连通块独立取小 | 各块之间没有约束，目标可相加，各块最优可以同时实现 |

这些思路可以组合，但不能只看循环外形来归类。对应正文：[双指针的移动依据](../02-sequence-techniques/04-two-pointers.md#3-相向双指针有序数组中的两数之和)、[二分答案](../02-sequence-techniques/06-binary-search-on-answer.md#1-解决什么问题)、[连通块独立选择](../06-graph-and-tree/02-bipartite-coloring.md#为什么逐块取小能得到全局最小)。

**排序前先确认允许交换对象的位置。** 若原顺序、方向或连接关系属于约束，不能把对应数值随意排序，再当成原问题求解。

## 7. 典题与复盘

两题分别练习**“先确定一端，再证明搭档选择”**与**“区分扫描范围和已选状态”**。

### 洛谷 P1094 — 纪念品分组

题目：[P1094 纪念品分组](https://www.luogu.com.cn/problem/P1094)。

- 每组最多两件，价格总和不超过上限 `w`；所有纪念品都要分组，求最少组数。
- 范围：$1\le n\le3\times10^4$，$80\le w\le200$，$5\le P_i\le w$。
- **练习目的：** 区分选入件数与分组数量两个目标，为每次决定补上“不影响最优性”的理由。
- **状态：复盘完成。** 平台 AC 依据本人反馈；以下原实现另经本地核验，未独立查询平台提交。

**收录原因：** 将选择顺序与交换论证结合，说明局部配对为什么可以保留某个最优方案，而不只是观察双指针移动方向。

#### 从最重的一件确定本组

排序后，`l、r` 指向**尚未分组的最轻、最重物品**，有效范围为闭区间 `[l,r]`。

- **若最轻与最重都超限：** 最重物品不可能与其他任何物品同组，只能单独占一组。
- **若二者不超限：** 可以把它们放在同一组，再处理剩下的物品。

第一种情况是被条件强制的；第二种情况还需要证明“现在配在一起不会减少后面的配对机会”。

#### 为什么轻重配对不会吃亏

设最轻物品为 `a`、最重物品为 `b`，且两者可以同组。考察一个未将它们配对的最优方案：

1. 若两者分别与 `x、y` 同组，即原来有 `(b,x)`、`(a,y)`，可改为 `(b,a)`、`(x,y)`。
2. 新的第一组已知合法；由于 `y <= b`，有 `x+y <= x+b <= w`，第二组也合法，**组数不增加**。
3. 若一方原本单独成组，改成轻重同组后，把另一方原来的搭档单独放即可，组数不增加；若两者都单独，合并还能少一组。

所以**至少存在一个最优方案让当前最轻与最重同组**。确定这一组后，剩下仍是相同的分组问题。

> **双指针负责定位候选，贪心论证负责说明为什么能直接确定这一组。** 有两个指针，不等于已经证明了选择正确。

#### 原 AC：每轮确定一组

以下仅调整排版与过程注释，保留原逻辑。代码中的 `k` 对应题面的价格上限 `w`，下标为 **0-based**。

```cpp
void solve() {
    int k, n;
    cin >> k >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;
    sort(a.begin(), a.end());

    int l = 0, r = n - 1;
    int cnt = 0;

    while (l < r) {
        int p = a[l] + a[r];
        if (p <= k) {
            ++l; // 能配对，最轻物品随最重物品一起离开候选区间
        }

        ++cnt; // 能否配对都确定一组，最重物品一定被处理
        --r;
    }

    if (l == r) ++cnt; // 只剩一件时，单独占一组

    cout << cnt << '\n';
}
```

**复杂度与边界：** 排序 $O(n\log n)$，扫描 $O(n)$；数组存储 $O(n)$，不另建配对表。价格和最多 `400`，`int` 足够。

每件物品都不超过上限，因此单独成组一定合法。恰好等于上限允许配对；`l>r` 表示全部处理完，只有 `l==r` 才补最后一组。

**原实现已经适合题目范围，不再重复制造一份“优化解”。** 需要保留的是每轮确定一组的状态含义，以及两种分支各自成立的理由。

### CF 545D — Queue

题目：[CF 545D Queue](https://codeforces.com/problemset/problem/545/D)。

- 可以重新排列全部人的服务顺序。等待时间是前面所有人的服务时间之和；等待时间大于自身服务时间才算不满意，求最多能有多少人满意。
- 范围：$1\le n\le10^5$，$1\le t_i\le10^9$。
- **练习目的：** 从条件判断当前状态怎样影响后续选择，分别论证计数目标与状态更新。
- **状态：复盘完成。** 修正后平台 AC 依据本人反馈；错误版本的反例已复现，以下原 AC 另经本地核验，未独立查询平台提交。

**收录原因：** 将“安排所有对象”转成“先构造满足目标的前缀”；区分扫描过的对象与真正进入状态的对象，避免无关决策持续污染后续判断。

#### 最初误区：排序以后仍让所有人影响后续

原先认为，服务时间短的人先处理就足够；即使某个人已经无法满意，也仍把他的服务时间加入等待总和：

```cpp
// 错误片段：sum 保存所有已扫描人的服务时间
for (int t : a) {
    if (sum <= 1LL * t) ++cnt;
    sum += 1LL * t; // 不满意的人仍留在前面，会阻碍后面的人满意
}
```

反例 `1、1、1、2`：直接按排序后的顺序服务，只能让前两人满意，错误答案为 `2`。

若改成 `1、1、2、1`，前三人的等待时间分别为 `0、1、2`，均不超过自身服务时间，正确答案为 `3`。

**允许重排意味着不必让当前不满意的人继续挡在前面。** 可以先安排选中的满意人群，其余人放到后面；这些人仍会被服务，并没有从题目中删除。

#### 第一层转化：满意的人可以集中在前面

取任意一个完整队列，将其中不满意的人移到最后，保持原本满意的人之间的相对顺序。

原本满意的人只会等待得更短，因此仍然满意。于是**至少存在一个最优方案，先安排全部满意的人，再安排其余人**。

后面要解决的是：选择一个尽可能长的满意前缀，而不是要求扫描顺序就是完整队列的最终顺序。

#### 第二层选择：优先尝试服务时间短的人

服务时间 `t` 同时有两种作用：

- **自身的满意门槛：** 等待时间不能超过 `t`；`t` 越小，容忍等待越少。
- **对后人的影响：** 一旦选入前缀，就让后面每个人多等 `t`；`t` 越小，影响越小。

这给出了升序尝试的方向，但仍需结合可行性证明：

1. **满意前缀中的服务时间必然非降序。** 后一人必须满足“自身服务时间不小于前面总和”，这个总和至少包含前一人的服务时间。
2. 设已确定前缀总时间为 `sum`，当前最小剩余时间为 `t`。若 `sum > t`，在**当前前缀之后**安排此人已经不满意；后续等待只会增加，因此跳过，不让他进入前缀状态。
3. 若 `sum <= t`，可以选入。一个最优后续方案若不含此人，用他替换该方案首人的时间 `y`，有 `t <= y`，自身满意且后续等待不增加；若此人原本也在后续方案中，由第 1 点他只可能排在同值的人之后，换到首位同样不改变可行性。

因此，每次选入都保留某个最优后续方案，跳过也不会漏掉当前前缀能够接纳的人。

> **可以理解为两层贪心思考：先整理方案形态，再确定选择顺序。** 实现上只有排序后的一次扫描，不需要机械拆成“两轮贪心”。

“必然不满”需要限定范围：**此人是在当前已确定的满意前缀后无法满意，不代表任何排列中都不能满意。** 反例中被跳过的第三个 `1`，放在队首当然也能满意。

#### 状态：只维护已经选入的满意前缀

- `a`：保存全部人的服务时间，长度按人数分配，**不是按最大时间分配**；排序后位置为 `0..n-1`。
- `sum`：只累计**已经选入满意前缀**的服务时间，不能理解成所有已扫描人的前缀和。
- `cnt`：满意前缀中的人数，也是当前已保证满意的人数。
- `t`：当前候选人的服务时间；未选入时不改变 `sum` 和 `cnt`。

扫描反例 `1、1、1、2`：

| 当前 t | 判断前 sum | 决策 | 操作后 sum / cnt |
| --- | --- | --- | --- |
| 1 | 0 | 满意，选入 | 1 / 1 |
| 1 | 1 | 恰好满足，选入 | 2 / 2 |
| 1 | 2 | 不满足，后移 | 2 / 2 |
| 2 | 2 | 满足，选入 | 4 / 3 |

**这里不能像预算模型一样 `break`。** 当前 `t` 太小，后面更大的 `t` 仍可能容忍同一个 `sum`；跳过时必须保持 `sum` 不变。

#### 原 AC：只有选入时才更新状态

以下仅调整排版与注释，保留修正后原 AC 逻辑。`ll` 沿用基础框架别名；按全体输入估计，总服务时间最多 $10^{14}$，累计时间统一使用 `ll`。

```cpp
void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;
    sort(a.begin(), a.end());

    ll sum = 0;
    int cnt = 0;

    for (int t : a) {
        if (sum > 1LL * t) {
            continue; // 后移此人；不计数，也不增加满意前缀的等待
        }

        ++cnt;
        sum += 1LL * t; // 只有确定选入后，才让此人影响后续
    }

    cout << cnt << '\n';
}
```

**复杂度：** 排序 $O(n\log n)$，扫描 $O(n)$，数组存储 $O(n)$；累计状态只有两个变量，每次调用独立初始化。

**边界与改进收益：** 等待等于服务时间仍满意，排除条件是 `>`；重复时间代表不同的人，不能去重。修正的收益不在复杂度，而在**状态只代表已经确定的决策**；原 AC 已是本题合适的主写法，不再复制第二份相同代码。

**如何想到：** 允许重排全部人 → 不满意者可以后移，不影响已满意者 → 优化满意前缀的人数 → 尝试耗时短且影响小的人 → 只累计被选入前缀的时间。
