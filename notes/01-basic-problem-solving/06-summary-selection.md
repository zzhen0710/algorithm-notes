# 1.6 本章总结与选型

覆盖 1.1–1.5：复杂度、枚举、模拟、STL 与位运算。知识正文整理完成不代表所有题目已经独立掌握，典题状态仍以各节为准。

## 1. 先判断问题需要什么

> **先找最容易验证、足以通过数据范围的做法，再考虑是否需要更复杂的算法。熟练的方法应满足条件，而不是仅仅写过。**

| 问题线索 | 优先考虑 | 何时换方法 |
| --- | --- | --- |
| 自由选择少、状态数可接受 | 枚举，先估总操作量 | 状态过多时利用约束降维，不直接堆嵌套循环 |
| 规则明确、按顺序推进 | 模拟，保存足够的最小状态 | 大量重复执行时寻找批量更新或数学关系 |
| 普通排序、找边界、去重 | STL 标准算法 | 特殊统计需求再补竞赛实现，如归并计数 |
| 等值查找或频次统计 | 数组、排序分组或哈希表，按值域选 | 涉及顺序、前驱或范围查询时不能只依赖哈希表 |
| 少量二元选择、小集合 | 位掩码枚举或按位操作 | 状态超过整数位宽或需要更多信息时换表示方式 |
| 两个状态不同的位置数 | 异或后统计置位数量 | 先确认每一位确实对应题目的独立属性 |

方法的详细前提分别见[复杂度](01-complexity-analysis.md)、[枚举](02-enumeration.md)、[模拟](03-simulation.md)、[STL](04-stl/README.md)与[位运算](05-bit-operations.md)。

## 2. 同题比较：CF 467B

[原题](https://codeforces.com/problemset/problem/467/B)的核心判断是两份状态的差异位数是否超过上限。完整个人实现、证明与边界仍在[位运算复盘](05-bit-operations.md#92-cf-467b把差异关系转成异或)，此处只横向比较，不复制整题。

| 差异位计数方式 | 代码长度 | 现场重写与记忆负担 | 主要条件 |
| --- | --- | --- | --- |
| `bitset<32>` 与 `count()` | 短，语义直接 | 低；记住异或与计数 | 位宽足够，适合同时观察各个位 |
| `__builtin_popcount` | 最短 | 低；需要记清参数类型 | GCC 内建函数，32 位与 64 位接口要对应 |
| 每次清除最低位的 `1` | 短循环 | 中；需理解 `x &= x-1` | 使用无符号整数，循环次数等于置位数量 |

三者使用同一个“异或表示差异”的模型，不是三种不同建模。固定机器字宽下都足够轻量，优先选择已经熟悉并能解释的写法；代码更短不是唯一标准。

最低位清除过程见[位运算第 6 节](05-bit-operations.md#6-清除最低位的-1-与计数)，内建函数的类型差异见同节。此处不新增个人 AC 或掌握记录。

## 3. 两种准备场景

| 场景 | 默认建议 | 需要换方案时 |
| --- | --- | --- |
| 蓝桥杯准备：以现场手写为目标 | 优先熟悉的 STL 与短状态维护；本例熟悉 `bitset` 就直接使用 | 对原理进行手写练习时使用最低位清除；环境与参数类型明确、内建函数熟练时可直接调用 |
| CF 准备：允许使用已验证的本地片段时 | 同样优先短而合适的实现；本例可使用熟悉的置位计数接口 | 真正重复出现且容易写错的部分才值得维护模板，不为简单一行操作增加封装 |

**两种场景的首要标准相同：正确、熟悉、范围足够。** 本地库可以减少重复劳动，但不能替代理解接口与边界。

## 4. 本章检查清单

- 能从数据范围估算实际操作量，而不是只看是否有两层循环。
- 能解释枚举状态、模拟更新顺序，以及哪些信息可以省略。
- 知道 STL 接口的前提、返回值与迭代器边界。
- 能确认位宽、类型与移位是否合法。
- 同一题存在多种方法时，能比较代码长度、重写难度与适用条件，而不是为了使用新算法而增加步骤。

后续新增本章内容时同步更新此总结，不将全部 API 重新罗列一遍。
