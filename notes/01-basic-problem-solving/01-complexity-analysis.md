# 1.1 复杂度分析

## 1. 解决什么问题

在比赛中，根据数据范围快速判断哪些算法可能可行，避免在明显超时的方向上浪费时间。

复杂度分析的目的不是机械计算 Big-O，而是回答：

> 这道题的数据范围允许我使用什么级别的算法？

---

## 2. 核心思想

先根据数据范围估算允许的复杂度级别，再根据题目结构选择具体算法。

需要区分两个步骤：

1. **数据范围决定允许的复杂度**
2. **题目性质决定具体使用什么算法**

例如 `n <= 2e5` 往往意味着需要寻找 `O(n)`、`O(n log n)` 附近的方案，但不能仅凭数据范围判断一定使用二分、双指针或某种数据结构。

同时，不能只根据代码有几层循环判断复杂度，而应分析实际总操作次数。

---

## 3. 常见量级直觉

比赛中可以先建立以下粗略直觉：

- `n <= 10`：可以考虑 `O(n!)`
- `n <= 20`：可以考虑 `O(2^n)`
- `n <= 100`：可以考虑 `O(n^3)`
- `n <= 1e3`：可以考虑 `O(n^2)`
- `n <= 1e4`：通常考虑 `O(n log n)`，`O(n^2)` 已经需要谨慎
- `n <= 1e5`：通常考虑 `O(n log n)` 或 `O(n)`
- `n <= 1e6`：优先考虑 `O(n)`
- `n <= 1e7`：通常需要接近 `O(n)`，还要注意常数

约 `1e8` 次基础操作可以视为一个粗略的危险信号。

但这不是绝对界限。

实际运行时间还受到以下因素影响：

- 时间限制
- 常数大小
- CPU 与编译优化
- 内存访问
- 使用的具体操作

例如 `1e8` 次简单整数运算和 `1e8` 次 `map` 操作完全不是一个量级。

---

## 4. 判断循环复杂度

不能机械地认为：

> 两层循环就是 `O(n^2)`，三层循环就是 `O(n^3)`。

需要检查：

- 内层变量是否每轮重新初始化
- 内层循环次数是否依赖外层变量
- 变量的增长方式是什么
- 指针是否只向一个方向移动
- 总工作量应该相乘还是求和

### 情况一：每轮完整执行

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) {
    }
}
```

内层每轮都执行 `n` 次，因此复杂度为：

```text
O(n^2)
```

### 情况二：内层次数依赖外层

```cpp
for (int i = 1; i <= n; ++i) {
    for (int j = i; j <= n; j += i) {
    }
}
```

固定 `i` 时，内层大约执行：

```cpp
n / i
```

次。

因此总操作量约为：

```cpp
n/1 + n/2 + ... + n/n
```

最终为：

```text
O(n log n)
```

### 情况三：变量指数增长

```cpp
for (int i = 1; i <= n; i *= 2) {
}
```

变量依次为：

```text
1, 2, 4, 8, ...
```

执行次数约为 `log n`，因此复杂度为：

```text
O(log n)
```

### 情况四：指针不重置且单调移动

```cpp
int j = 0;

for (int i = 0; i < n; ++i) {
    while (j < n && condition(i, j)) {
        ++j;
    }
}
```

虽然代码形式是两层循环，但 `j` 在整个程序中最多只增长 `n` 次。

外层 `i` 也最多移动 `n` 次，因此总复杂度通常是：

```text
O(n)
```

这类分析以后经常出现在双指针和滑动窗口中。

## 5. 数据范围反推算法

拿到题目后，可以先问自己：

1. 最直接的暴力方案是什么？
2. 暴力复杂度是多少？
3. 根据数据范围，实际大约需要多少次操作？
4. 这个量级能否接受？
5. 如果不能，重复计算发生在哪里？
6. 题目中是否存在可以利用的性质？
7. 能否通过预处理、排序、哈希、双指针、二分或数据结构降低复杂度？

典型思考过程：

```text
先写出暴力
    ↓
计算复杂度
    ↓
结合数据范围判断是否可行
    ↓
寻找重复计算或特殊性质
    ↓
降低复杂度
```

------

## 6. 常见优化方向

### 6.1 预处理换查询时间

例如需要进行大量静态区间和查询。

暴力每次从 `l` 加到 `r`：

- 单次：`O(n)`
- `q` 次：最坏 `O(nq)`

使用前缀和后：

- 预处理：`O(n)`
- 单次查询：`O(1)`
- 总复杂度：`O(n + q)`

本质是：

> 提前计算并保存重复使用的信息。

------

### 6.2 用空间换时间

如果整数值域较小，可以直接使用数组记录信息：

```cpp
cnt[x]++;
```

之后可以近似 `O(1)` 查询某个值出现了多少次。

需要注意：

`bool` 数组只能记录“是否存在”，不能记录重复出现次数。

------

### 6.3 哈希维护历史状态

如果值域很大，无法直接开数组，可以使用：

```cpp
unordered_map
unordered_set
```

维护已经出现过的信息。

例如寻找：

```cpp
a[i] + a[j] = x
```

从左到右扫描时，可以先查：

```cpp
x - a[i]
```

是否已经出现，再把 `a[i]` 加入哈希表。

这样哈希表始终只代表当前位置之前的元素。

> 先查询历史状态，再更新当前状态，可以避免当前元素与自己配对。

------

### 6.4 排序 + 双指针

如果题目允许改变元素顺序，或者只关心元素值而不关心原始位置，可以考虑：

```text
先排序
   ↓
利用有序性
   ↓
两个指针单调移动
```

例如寻找两个数之和为 `x`：

```cpp
left = 0
right = n - 1
```

若：

- `a[left] + a[right] < x`：增大 `left`
- `a[left] + a[right] > x`：减小 `right`
- 等于 `x`：处理答案

排序需要：

```text
O(n log n)
```

两个指针总共只移动 `O(n)` 次。

因此整体通常为：

```text
O(n log n)
```

这个方法体现了一种重要思想：

> 先付出排序代价，换取之后可以利用的单调性。

------

## 7. 常见错误

### 错误 1：看到两层循环就判断为 $O(n^2)$

**为什么错：**

内层循环不一定每次都完整执行 `n` 次。

可能：

- 执行次数取决于外层变量
- 指针不重置
- 指针只单调移动
- 循环变量指数增长

**正确做法：**

分析每个变量在整个程序中的实际总移动次数。

如果内层次数依赖外层，应先写出固定外层时的工作量，再进行求和。

------

### 错误 2：只看单次操作复杂度，忘记操作次数

例如：

```text
单次查询 O(n)
```

看起来不大，但若：

```cpp
q = 2e5
n = 2e5
```

总复杂度实际上可能达到：

```text
O(nq)
```

**正确做法：**

始终计算：

> 单次复杂度 × 执行次数 + 预处理复杂度

最终关心的是整个程序的总复杂度。

------

### 错误 3：只写查询复杂度，忘记预处理

例如前缀和：

单次查询确实是：

```text
O(1)
```

但整个算法不是 `O(q)`，因为还需要：

```text
O(n)
```

预处理。

因此总复杂度应写为：

```text
O(n + q)
```

**正确做法：**

复杂度分析要包含算法所有主要阶段。

------

### 错误 4：把 `1e8` 当成绝对时间界限

**为什么错：**

不同操作的常数差异很大。

整数加法、数组访问、哈希、红黑树操作的实际成本完全不同。

**正确做法：**

把 `1e8` 只当作粗略危险信号。

当复杂度逼近这个量级时，应进一步考虑：

- 时间限制
- 常数
- 数据结构
- 内存访问
- 是否存在更好的算法

------

### 错误 5：看到数据范围就直接猜算法

例如：

```cpp
n <= 2e5
```

不能直接推出：

> 一定是二分。

数据范围只能告诉我们：

> 大概率需要 `O(n)` 或 `O(n log n)` 附近的方案。

**正确做法：**

先由数据范围筛掉不可行复杂度，再由题目性质选择具体算法。

例如：

- 单调性 → 可能二分
- 左右端点单调移动 → 可能双指针
- 静态区间查询 → 可能预处理
- 动态区间问题 → 可能数据结构

------

### 错误 6：用 `bool` 记录存在性，却忽略重复次数

例如：

```text
2 2 3 3
```

寻找和为 `5` 的数对。

只记录：

```cpp
exist[2] = true;
exist[3] = true;
```

只能知道它们存在，却无法知道应该产生：

```text
2 × 2 = 4
```

个数对。

**正确做法：**

如果答案与出现次数有关，应记录：

```cpp
cnt[value]++;
```

而不是只记录是否出现。

------

### 错误 7：在线配对时先加入当前元素，再查询

例如只有：

```cpp
a = [2]
x = 4
```

如果先把 `2` 加入哈希，再查询 `4 - 2`，就可能错误地让当前元素与自己配对。

**正确做法：**

保持：

```text
查询历史状态
    ↓
统计答案
    ↓
加入当前元素
```

这样哈希表始终只表示之前已经处理过的元素。

------

## 8. 一句话触发器

> 看到数据范围，先反推允许的复杂度；看到暴力超时，再寻找重复计算与可利用的结构。
