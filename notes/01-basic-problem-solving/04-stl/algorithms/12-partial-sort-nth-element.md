# 12 · partial_sort / nth_element 与选择问题

这一节介绍 STL 中两个非常重要的**部分排序与选择算法**。

它们解决的问题：

> 不一定需要完整排序，只需要找到某些关键位置。

例如：

-   找前 $k$ 小元素；
-   找第 $k$ 小元素；
-   找中位数。

相比：

``` cpp
sort()
```

可以避免无意义的完整排序。

------------------------------------------------------------------------

# 一、partial_sort

## API

``` cpp
template<class RandomIt>
void partial_sort(
    RandomIt first,
    RandomIt middle,
    RandomIt last
);
```

返回：

``` cpp
void
```

作用：

> 将 `[first, middle)`
> 范围内的元素排好序，并保证它们是整个区间中最小的一部分。

------------------------------------------------------------------------

例如：

``` cpp
vector<int> a = {
    7,2,5,1,6,3,4
};

partial_sort(
    a.begin(),
    a.begin()+3,
    a.end()
);
```

结果：

``` text
1 2 3 | 7 6 5 4
```

保证：

``` cpp
[first, middle)
```

中的元素：

-   是整个数组最小的 3 个；
-   并且已经有序。

但是：

``` text
middle
之后的元素
```

不保证有序。

------------------------------------------------------------------------

# 二、partial_sort 的应用

## 找前 k 小并排序

例如：

``` cpp
partial_sort(
    a.begin(),
    a.begin()+5,
    a.end()
);
```

得到：

``` text
最小5个元素 | 其他元素
```

并且：

``` text
最小5个元素有序
```

适合：

-   $n$ 很大；
-   $k$ 很小；
-   只关心前 $k$ 个结果。

------------------------------------------------------------------------

# 三、nth_element

`nth_element()` 更关注：

> 找第 $k$ 小元素。

## API

``` cpp
template<class RandomIt>
void nth_element(
    RandomIt first,
    RandomIt nth,
    RandomIt last
);
```

返回：

``` cpp
void
```

------------------------------------------------------------------------

作用：

执行后保证：

``` cpp
*nth
```

是排序后应该处于该位置的元素。

并且：

左侧：

$$
\le *nth
$$

右侧：

$$
\ge *nth
$$

但是：

左右两侧内部不排序。

------------------------------------------------------------------------

例如：

``` cpp
vector<int> a = {
    7,2,5,1,6,3,4
};

nth_element(
    a.begin(),
    a.begin()+3,
    a.end()
);
```

寻找第 4 小元素。

排序后：

``` text
1 2 3 4 5 6 7
      ↑
```

所以：

``` text
*nth = 4
```

执行后可能：

``` text
2 1 3 | 4 | 7 6 5
```

保证：

左边：

``` text
2 1 3
```

都小于等于 4。

右边：

``` text
7 6 5
```

都大于等于 4。

------------------------------------------------------------------------

# 四、nth_element 与 sort 区别

| 算法          | 作用            | 是否完全排序 |
| ------------- | --------------- | ------------ |
| `sort`        | 所有元素排序    | 是           |
| `nth_element` | 寻找第 k 个位置 | 否           |

例如：

需求：

找中位数。

如果：

``` cpp
sort(a.begin(), a.end());
```

需要：

$$
O(n\log n)
$$

更优：

``` cpp
nth_element(
    a.begin(),
    a.begin()+n/2,
    a.end()
);
```

平均：

$$
O(n)
$$

------------------------------------------------------------------------

# 五、partial_sort 与 nth_element 区别

| 算法           | 需求              | 结果           |
| -------------- | ----------------- | -------------- |
| `partial_sort` | 前 $k$ 个元素排序 | 前 $k$ 有序    |
| `nth_element`  | 找到第 $k$ 个元素 | 只保证位置正确 |

选择：

| 需求            | 算法           |
| --------------- | -------------- |
| 完整排序        | `sort`         |
| 前 $k$ 小且有序 | `partial_sort` |
| 只找第 $k$ 小   | `nth_element`  |

------------------------------------------------------------------------

# 六、底层思想

## nth_element

本质类似快速排序中的 partition。

快速排序：

``` text
小于 pivot | pivot | 大于 pivot
```

然后递归两边。

------------------------------------------------------------------------

而 `nth_element`：

只递归包含目标位置的一边。

例如：

``` text
        pivot

左边        右边
```

如果目标在左：

``` text
递归左边
```

否则：

``` text
递归右边
```

因此平均：

$$
O(n)
$$

------------------------------------------------------------------------

# 七、复杂度来源

## 1. partial_sort 为什么是 $O(n\log k)$？

目标：

> 找前 $k$ 小，并且让这 $k$ 个元素有序。

`partial_sort` 通常维护一个大小为 $k$ 的堆。

堆大小：

$$
k
$$

一次插入或调整：

$$
O(\log k)
$$

扫描：

$$
n
$$

因此：

$$
n \times O(\log k)
$$

得到：

$$
O(n\log k)
$$

------------------------------------------------------------------------

空间：

只需要维护大小为 $k$ 的堆。

因此：

$$
O(k)
$$

------------------------------------------------------------------------

## 2. nth_element 为什么平均 $O(n)$？

`nth_element` 类似快速选择。

一次 partition：

$$
O(n)
$$

每次只处理目标所在的一侧。

规模类似：

$$
n+\frac n2+\frac n4+\cdots
$$

等比数列：

$$
O(n)
$$

------------------------------------------------------------------------

空间：

因为是原地 partition：

只需要：

-   pivot；
-   left；
-   right。

等少量变量。

因此：

$$
O(1)
$$

------------------------------------------------------------------------

# 八、复杂度总结

| 算法           | 平均时间复杂度 | 空间复杂度  | 原因                         |
| -------------- | -------------- | ----------- | ---------------------------- |
| `sort`         | $O(n\log n)$   | $O(\log n)$ | 完整排序                     |
| `partial_sort` | $O(n\log k)$   | $O(k)$      | 维护大小为 $k$ 的堆          |
| `nth_element`  | 平均 $O(n)$    | $O(1)$      | 类似快速选择，只处理目标方向 |

其中：

-   $n$：数组长度；
-   $k$：需要保留的数量。

------------------------------------------------------------------------

# 九、一个容易误解的地方

竞赛笔记中可以记：

| 算法           | 复杂度       |
| -------------- | ------------ |
| `partial_sort` | $O(n\log k)$ |
| `nth_element`  | 平均 $O(n)$  |

但需要注意：

- `partial_sort` 通常基于堆结构实现，因此通过维护大小为 $k$ 的结构完成选择；
- `nth_element` 的具体实现与 STL 库有关，常见实现类似 **Introselect**。

其中：

`Introselect`：

- `Intro` 来自 **Introspective（内省式）**，表示根据运行状态判断是否可能退化并调整策略；
- `select` 表示选择第 $k$ 个元素。

简单理解：

> Introselect = 带退化保护的快速选择。

竞赛理解：

```text
partial_sort:

维护 k 个元素
        ↓
    O(n log k)


nth_element:

类似快速选择
        ↓
    平均 O(n)
```

# 十、本节总结

| 算法           | 作用              | 返回   |
| -------------- | ----------------- | ------ |
| `partial_sort` | 排序前 $k$ 个元素 | `void` |
| `nth_element`  | 寻找第 $k$ 个元素 | `void` |

核心：

> 不要为了一个局部需求进行完整排序。

竞赛中：

-   Top K；
-   中位数；
-   第 k 大 / 小；

优先考虑：

``` cpp
nth_element()
```

如果还需要：

``` text
前 k 个结果有序
```

使用：

``` cpp
partial_sort()
```

本节属于：

**高价值算法**

建议掌握。
