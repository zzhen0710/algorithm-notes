# 1.4.6 `queue`：先进先出的队列

## 1. 核心定位

`queue` 是 **FIFO（First In, First Out，先进先出）** 的容器适配器：从队尾加入元素，从队首取出元素。

```cpp
queue<int> q;

q.push(10);
q.push(20);
q.push(30);

cout << q.front(); // 10：最早入队
cout << q.back();  // 30：最近入队

q.pop();           // 删除 10，队首变成 20
```

**典型场景**：按到达顺序处理任务、先进先出缓存、按层搜索（BFS，后续专题学习）。

默认底层容器是 `deque`；`queue` 只暴露 FIFO 所需接口，不提供随机访问和普通迭代器。

---

## 2. 常用 API

以下以默认底层容器的 `queue<int>` 为例，给出常用 **C++11 接口签名**；省略不常用重载。

| API 签名 | 作用与返回值 | 时间复杂度 |
|---|---|---|
| `void push(const int& value)` | 在队尾插入元素，无返回值 | O(1) |
| `void pop()` | 删除队首元素，**不返回被删除的值** | O(1) |
| `int& front()` | 返回队首元素的引用 | O(1) |
| `const int& front() const` | 只读访问队首元素 | O(1) |
| `int& back()` | 返回队尾元素的引用 | O(1) |
| `const int& back() const` | 只读访问队尾元素 | O(1) |
| `size_type size() const` | 返回当前元素数量 | O(1) |
| `bool empty() const` | 判断是否为空 | O(1) |

`size_type` 是容器定义的大小类型；以上复杂度针对默认底层 `deque`。

### 基本调用

```cpp
queue<int> q;

q.push(7);
q.push(9);

int x = q.front(); // 7
q.pop();           // 队首变成 9

if (!q.empty()) {
    cout << q.front();
}
```

---

## 3. 高频陷阱

### 3.1 `pop()` 只删除，不返回元素

```cpp
int x = q.pop(); // 错误：pop() 返回 void
```

正确写法：

```cpp
int x = q.front();
q.pop();
```

### 3.2 空队列不能访问或弹出

```cpp
if (!q.empty()) {
    int x = q.front();
    q.pop();
}
```

空队列上调用 `front()`、`back()`、`pop()` 都不合法。

### 3.3 `queue` 不是 `deque`

```cpp
q[0];       // 错误：没有 operator[]
q.begin();   // 错误：没有普通迭代器接口
q.clear();   // 错误：没有 clear() 接口
```

`queue` 只适合按顺序入队、出队。若需要两端删除、下标访问或直接遍历，考虑 `deque`；若必须按优先级取出元素，考虑 `priority_queue`。

### 3.4 FIFO 与 LRU 不同

FIFO 根据**进入队列的先后**淘汰元素；再次访问已存在的元素不会自动调整其顺序。

LRU 根据**最近使用时间**淘汰元素，命中缓存时可能需要更新次序。不能把两种规则混用。

## 4. 代表题：[P1540 机器翻译](https://www.luogu.com.cn/problem/P1540)

**题型**：队列模拟 / FIFO 缓存 / 辅助标记数组。

内存最多存放 `m` 个不同的单词，按顺序读取 `n` 个单词：

- 已在内存中：直接使用，不查词典，也**不改变入队顺序**；
- 不在内存中：查一次词典，并加入内存；
- 内存已满：先淘汰最早进入内存的单词。

求查词典的总次数。题目用 `0 ~ 1000` 的整数表示单词。

### 4.1 核心建模：两个数据结构各司其职

单独使用 `queue` 可以高效取出最早入队的元素，却不能高效查询任意单词是否存在。

因此使用：

```cpp
queue<int> q;   // 维护进入内存的先后顺序
bool in[1001]{}; // 记录每个单词当前是否在内存中
```

**操作需求决定数据结构分工**：

```text
queue      → 决定谁最早进入，负责 FIFO 淘汰
bool[]     → O(1) 查询某个单词是否已经在内存中
```

### 4.2 独立实现的关键部分

原解的核心代码：

```cpp
bool in[1001]; // 原解使用全局数组，默认初始化为 false

void solve() {
    int m, n;
    cin >> m >> n;

    queue<int> q;
    int cnt = 0;

    for (int i = 1; i <= n; ++i) {
        int t;
        cin >> t;

        if (in[t]) continue; // 命中：顺序不变

        if (q.size() == m) {
            in[q.front()] = false;
            q.pop();
        }

        q.push(t);
        in[t] = true;
        ++cnt;
    }

    cout << cnt << '\n';
}
```

**实现正确，且已是本题推荐的核心算法。**

- 未命中时才入队，不会出现同一单词在队列中重复出现；
- 淘汰前先将旧单词的存在标记清除；
- 命中时直接 `continue`，符合 FIFO 而非 LRU；
- 每次操作只涉及常数次队列与数组访问。

### 4.3 一处小改进：将标记数组放进 `solve()`

题目是单组输入，所以全局 `bool in[1001]` 没有正确性问题。但若将来复用为多组测试，全局标记可能残留上一次的数据。

只需把声明移入 `solve()`，并零初始化：

```cpp
void solve() {
    int m, n;
    cin >> m >> n;

    bool in[1001]{}; // 每组测试都有独立的初始状态
    queue<int> q;

    // 其余代码不变
}
```

不必为这一点重复给出整套几乎相同的代码。

### 4.4 复杂度

设单词种类范围大小为 `U = 1001`：

- 每个输入单词至多触发一次 `push()` 和一次 `pop()`，状态查询、修改均为 O(1)；
- **处理 n 个单词**：O(n)；
- **如果包含每组测试的标记数组初始化**：O(n + U)；
- **空间**：O(m + U)，队列至多存放 `m` 个元素。

与每次遍历队列判断单词是否存在相比，布尔标记数组使查询由 O(m) 降为 O(1)。

## 5. 选型触发器

看到以下问题特征，优先想到 `queue`：

```text
先加入的对象先处理
需要不断从队首取出、队尾加入
只关心处理顺序，不需要随机访问
```

如果还要查询队列内任意对象的状态，可搭配标记数组或哈希集合：

> **一种容器不必承担全部操作。让 `queue` 维护顺序，其他结构维护快速查询所需的信息。**

如果只是后进先出，选 `stack`；如果需要真正从两端进出，选 `deque`；如果取出顺序取决于优先级，选 `priority_queue`。
