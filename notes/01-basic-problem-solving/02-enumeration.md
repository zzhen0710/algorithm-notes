# 1.2 枚举

## 1. 解决什么问题

枚举用于在候选解空间中系统地检查所有可能成为答案的状态。

它的核心不是“写几层 `for`”，而是先设计好：

- **枚举对象是什么**
- **真正的自由变量有几个**
- **哪些约束可以提前进入循环边界**
- **哪些变量能由已知变量直接计算**
- **哪些重复计算可以预处理**

因此，枚举题真正要问的不是：

> 我要写几层循环？

而是：

> **什么东西需要我主动选择？什么东西一旦确定，整个方案就基本确定了？**

---

## 2. 核心思想：只枚举真正的自由量

例如：

\[
x+y+z=S
\]

如果已经枚举 `x、y`，那么：

```cpp
int z = S - x - y;
```

`z` 已经被约束唯一确定，不再是自由变量。

```cpp
for (int x = ...; ...; ++x) {
    for (int y = ...; ...; ++y) {
        int z = S - x - y;   // 直接计算，不再枚举
        if (valid(x, y, z)) {
            ...
        }
    }
}
```

这就是最基本的**枚举降维**：

```text
枚举全部变量
    ↓
寻找变量之间的约束
    ↓
只保留真正的自由变量
    ↓
其余变量直接计算
```

---

## 3. 枚举空间设计

### 3.1 约束尽量进入循环边界

若要求：

\[
1\le a<b\le n
\]

不要先枚举所有 `(a,b)` 再判断：

```cpp
for (int a = 1; a <= n; ++a) {
    for (int b = 1; b <= n; ++b) {
        if (a >= b) continue;
    }
}
```

而应直接：

```cpp
for (int a = 1; a <= n; ++a) {
    for (int b = a + 1; b <= n; ++b) {
        ...
    }
}
```

> **能写进循环边界的约束，就尽量不要留到循环体里。**

代数关系也可以继续缩小范围。例如：

\[
a+b=S,\quad a<b
\]

则：

\[
2a<S
\]

因此 `a` 无需枚举到 `S`。

又如：

\[
ab=n,\quad a\le b
\]

则：

\[
a^2\le n
\]

可以写成：

```cpp
for (int a = 1; 1LL * a * a <= n; ++a) {
    if (n % a == 0) {
        int b = n / a;
        ...
    }
}
```

将枚举范围从 `O(n)` 缩小到 `O(sqrt(n))`。

### 3.2 枚举对象不一定是元素

枚举对象可以是：

```text
数值 / 下标 / 区间端点 / 分界线 / 状态 / 操作次数 / 候选答案
```

因此遇到题目时，还应该问：

> **真正决定整个方案的“关键量”是什么？**

### 3.3 分清“值不同”和“位置不同”

例如：

```text
1 1 2 2
```

统计和为 `3` 的**下标对**时，虽然数值组合只有：

```text
(1, 2)
```

但下标方案有：

\[
2\times2=4
\]

因此必须先确认题目统计的是数值方案、下标方案、排列还是集合，否则容易错误去重。

## [P1618 三连击（升级版）](https://www.luogu.com.cn/problem/P1618)

### 题型：变量关系型枚举

要求三个三位数满足：

\[
a:b:c=A:B:C
\]

难点不在数字判重，而在于三个变量存在固定比例。如果同时枚举 `a、b、c`，实际上重复枚举了已经被比例关系确定的变量。

解决思路：

> **先处理比例，只枚举公共尺度。**

优化路线：

```text
同时枚举 a、b、c
→ 利用比例关系降维
→ 先把输入比例约成最简整数比
→ 只枚举公共尺度 k
→ 直接计算 a、b、c
```

### 重点坑：输入比例不保证已经最简

不能默认：

```cpp
a % A == 0
b % B == 0
c % C == 0
```

因为输入的 `A:B:C` 可能不是最简整数比。

例如：

```text
A:B:C = 2:4:6
a:b:c = 123:246:369
```

二者比例完全相同：

\[
123:246:369=1:2:3=2:4:6
\]

但：

```cpp
123 % 2 != 0;
```

如果强行要求 `a/A` 为整数，就会把合法答案错误排除。

因此应先约分：

```cpp
int g = gcd(A, gcd(B, C));
A /= g;
B /= g;
C /= g;
```

然后枚举公共尺度：

```cpp
bool valid(int a, int b, int c) {
    bool used[10]{};

    for (int x : {a, b, c}) {
        if (x < 100 || x > 999) return false;

        for (int i = 0; i < 3; ++i) {
            int d = x % 10;
            x /= 10;

            if (d == 0 || used[d]) return false;
            used[d] = true;
        }
    }

    return true;
}

void solve() {
    int A, B, C;
    cin >> A >> B >> C;

    int g = gcd(A, gcd(B, C));
    A /= g;
    B /= g;
    C /= g;

    bool found = false;

    for (int k = 1; ; ++k) {
        int a = A * k;
        int b = B * k;
        int c = C * k;

        if (max({a, b, c}) > 999) break;
        if (min({a, b, c}) < 100) continue;

        if (valid(a, b, c)) {
            found = true;
            cout << a << ' ' << b << ' ' << c << '\n';
        }
    }

    if (!found) cout << "No!!!\n";
}
```

这里九个位置全部来自 `1~9` 且互不重复，因此自然意味着 `1~9` 各使用一次。

## [P3392 涂条纹](https://www.luogu.com.cn/problem/P3392)

### 题型：边界型枚举

题目表面是一个 `N × M` 字符矩阵，但最终合法图案一定是：

```text
若干白行
若干蓝行
若干红行
```

真正决定整个方案的不是每个格子的颜色，而是两条分界线：

```text
1 ... a       -> W
a+1 ... b     -> B
b+1 ... n     -> R
```

一旦 `a、b` 确定，每一行最终应该是什么颜色就全部确定。

解决思路：

> **从枚举元素，转为枚举决定整个方案的关键边界。**

进一步发现，每组边界都会重复统计连续若干行的修改代价，因此可以预处理三种颜色的前缀代价。

优化路线：

```text
枚举每个格子的状态
→ 枚举两条分界线
→ 逐段统计修改代价
→ 预处理每行代价
→ 前缀和 O(1) 求三个区间代价
```

### 推荐写法

```cpp
void solve() {
    int n, m;
    cin >> n >> m;

    vector<array<int, 3>> pre(n + 1);

    for (int i = 1; i <= n; ++i) {
        string s;
        cin >> s;

        pre[i] = pre[i - 1];

        for (char c : s) {
            pre[i][0] += (c != 'W');
            pre[i][1] += (c != 'B');
            pre[i][2] += (c != 'R');
        }
    }

    int ans = INT_MAX;

    for (int a = 1; a <= n - 2; ++a) {
        for (int b = a + 1; b <= n - 1; ++b) {
            int cost =
                pre[a][0] +
                (pre[b][1] - pre[a][1]) +
                (pre[n][2] - pre[b][2]);

            ans = min(ans, cost);
        }
    }

    cout << ans << '\n';
}
```

循环边界：

```cpp
a <= n - 2;
b >= a + 1;
b <= n - 1;
```

已经天然保证白、蓝、红三部分都至少有一行。

复杂度：

```text
预处理：O(nm)
枚举边界：O(n^2)
总复杂度：O(nm + n^2)
```

### 输入易错点

不推荐：

```cpp
cin.get();       // 手动猜分隔符
cin.get(c);
cin.get();
```

这种写法隐含假设分隔符恰好只有一个字符；遇到 `\r\n` 或额外空白时容易发生读取错位。

无空格字符串直接：

```cpp
string s;
cin >> s;
```

更稳定。

## [P8635 [蓝桥杯 2016 省 AB] 四平方和](https://www.luogu.com.cn/problem/P8635)

### 题型：数学约束型枚举

要求：

\[
a^2+b^2+c^2+d^2=N,\qquad 0\le a\le b\le c\le d
\]

最直接是四重枚举，但四个变量并不独立：

\[
d^2=N-a^2-b^2-c^2
\]

当 `a、b、c` 已知时，`d` 已经由余量确定，因此不应该再枚举。

解决思路：

> **枚举 `a、b、c`，计算余量，再判断余量是否为完全平方数。**

优化路线：

```text
四重枚举
→ d 由余量确定，降为三重枚举
→ sqrt 直接得到 d 的唯一候选
→ 大小关系写入循环边界
→ 按字典序枚举，第一个合法解直接返回
```

### 本节写法

```cpp
void solve() {
    int n;
    cin >> n;

    for (int a = 0; a * a <= n; ++a) {
        for (int b = a; a * a + b * b <= n; ++b) {
            for (int c = b;
                 a * a + b * b + c * c <= n;
                 ++c) {

                int rem = n - a * a - b * b - c * c;
                int d = sqrt(rem);   // 得到唯一候选，不再枚举 d

                if (d >= c && d * d == rem) {
                    cout << a << ' ' << b << ' '
                         << c << ' ' << d << '\n';
                    return;
                }
            }
        }
    }
}
```

`sqrt(rem)` 返回浮点结果，赋给 `int` 后小数部分被截去，因此必须再次验证：

```cpp
int d = sqrt(rem);

if (d * d == rem) {
    // rem 是完全平方数
}
```

例如：

```text
rem = 20
sqrt(20) ≈ 4.472...
d = 4
4 * 4 != 20
```

而：

```text
rem = 25
d = 5
5 * 5 == 25
```

在本题数据范围内，配合平方校验即可稳定判断。

循环从：

```cpp
b = a;
c = b;
```

开始，已经直接保证：

\[
a\le b\le c
\]

再检查：

```cpp
d >= c
```

即可满足完整顺序约束。

同时枚举顺序本身就是 `a、b、c` 的字典序，`d` 又由前三者唯一确定，因此找到第一组合法解后可以直接：

```cpp
return;
```

### 关于“最佳解”

这份写法用于本节训练：

```text
枚举降维 + 数学判断代替循环 + 枚举顺序服务于答案
```

但它不应被理解为这道原题在所有数据范围下的理论最优解。

当数据范围继续增大时，还可以把：

\[
a^2+b^2+c^2+d^2=N
\]

拆成两个“两数平方和”，通过预处理配合后续的二分或哈希进一步优化。学到对应知识后再回到这题升级。

## 5. 常见错误

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| 所有变量都各写一层循环 | 部分变量可能已经被约束唯一确定 | 只枚举真正的自由变量 |
| `a < b` 仍枚举所有 `(a,b)` | 产生无效状态和重复方案 | 直接从 `b = a + 1` 开始 |
| 把输入比例当成最简整数比 | 原比例可能还能约分，合法解不一定分别整除原始比例项 | 先 `gcd` 约分，或使用等价的交叉乘关系 |
| 求最小值却 `ans = 0` | `min(0, cost)` 永远不会得到正代价 | `INT_MAX + min` |
| 用 `cin.get()` 手动吞固定字符 | 依赖具体分隔格式，容易读取错位 | 无空格字符串优先 `cin >> s` |
| 用循环寻找平方根 | 可以直接算出唯一候选 | `sqrt + 平方校验` |
| 只保证 `a <= b <= c`，忘记 `c <= d` | 顺序约束不完整 | 显式检查 `d >= c` |
| 找到字典序第一解后继续搜索 | 后续状态不可能更优 | 按字典序枚举后直接 `return` |
| 把数值组合和下标方案混为一谈 | 重复值可能对应多个不同下标方案 | 先确认题目统计对象 |

## 6. 枚举优化检查表

面对暴力方案，可以按这个顺序检查：

```text
1. 真正的自由变量有几个？
2. 有变量能由等式、比例或函数直接算出吗？
3. 大小关系能写进循环边界吗？
4. 是否枚举了重复方案？
5. 真正决定方案的可能是边界或状态吗？
6. 枚举过程中是否反复计算相同信息？
7. 某一层循环能否换成一次数学判断？
8. 枚举顺序能否直接满足字典序或最优性要求？
9. 一旦答案确定，能否提前退出？
```

## 7. 一句话触发器

> **看到多重暴力枚举，先问真正的自由变量有几个；能算出来的变量，就不要再枚举。**

再进一步问：

> **什么东西一旦确定，整个方案就确定了？**
