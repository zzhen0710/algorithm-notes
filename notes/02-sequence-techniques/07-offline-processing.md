# 2.7 离线处理

## 1. 解决什么问题

多个询问分别处理时，可能会重复扫描相同的数据。若询问可以提前读完，且改变处理顺序不影响各自答案，就能选择更适合复用状态的顺序。

> **先收集询问，再按有利于计算的顺序处理；用原编号恢复输出顺序。**

离线是一种组织方式，不是一种固定的数据结构。本节只整理**排序询问＋单向扫描**的基础用法，使用 C++11，沿用[竞赛基础框架](../../templates/01-basic-problem-solving/cpp-contest-template/README.md)中的 `using ll = long long;`，不重复通用框架。

## 2. 在线与离线

| 方式 | 如何处理 | 主要条件 |
| --- | --- | --- |
| 在线 | 不依赖未来询问，逐个计算答案 | 当前数据与当前询问足以作答 |
| 离线 | 先收集，再调整顺序或统一预处理 | 所需信息可提前取得，重排不破坏语义 |

**能提前读入，不代表能随意排序。** 还需要确认：

- 询问是否针对同一份静态数据？
- 后续询问是否依赖前一次答案？
- 原顺序是否表示数据变化的时间？
- 改变顺序后，究竟能复用哪部分计算？

原问题若要求保留位置关系，可以只排序“询问或下标”，而不是直接打乱原数组。对应技巧见[离散化中的下标排序](03-discretization.md#34-另一种写法iota--比较器排序下标)。

### 误区：离线不是状态维护方式

最初把离线处理与“动态累加 `sum`”联系起来，容易为了维护这个变量而增加离散化、频次等步骤。更应该先分清三层：

- **处理组织：** 能否预先获得整批询问，利用这些信息安排计算？本节通过排序询问，选择便于复用计算的顺序。
- **推进依据：** 处理顺序确定后，哪些旧计算可以保留，哪些新记录需要加入？本节利用阈值递增，让指针无需回退。
- **状态表示：** 答案需要保存什么？可以是累计和、指针位置、频次或其他结构，不要求必须存在独立的 `sum`。

> **离线决定怎样组织询问；状态维护决定怎样算出当前答案。两者可以分别选择。**

“分步处理”也不是离线的独有特征。例如每读入一个数就更新累计和并输出，既有动态状态，也分步执行，但不依赖未来数据，仍是在线处理。

| 已有模型 | 怎样维护当前答案 | 为什么采用离线 |
| --- | --- | --- |
| 阈值以内的加权贡献和 | 加入新记录时更新 `sum`；负贡献还可能让它减小 | 询问排序后，可以保留已加入记录 |
| CF 600B：离散化＋频次 | 跨过一个不同值，加入整组频次 | 调整询问顺序，让不同值只扫描一次 |
| CF 600B：排序原数组 | 每个原位置贡献 `1`，直接用 `p` 作数量 | 同样调整询问顺序，让数组位置只扫描一次 |
| CF 474B：所属堆号 | 越过已经结束的堆，答案为 `p+1` | 询问编号有序后，堆位置无需回退 |

**先确认处理顺序能带来什么复用，再选择最少且含义直接的状态。** 每条记录贡献都是 `1` 时，位置数已经表达累计数量，无需为了“动态维护”再增加一个等价变量。

排序只是本节使用的离线组织方式，不是所有离线算法都必须采用的步骤；反过来，使用前缀和或动态累计变量，也不会自动变成离线处理。

## 3. 基础模型：阈值以内的贡献和

每条记录包含关键值 `key` 与贡献 `value`。给定多个阈值 $t$，分别求所有关键值不超过阈值的记录之和：

$$
F(t)=\sum_{\mathrm{key}_i\le t}\mathrm{value}_i
$$

逐个询问扫描全部记录，需要 $O(nm)$。若阈值从小到大处理，之前满足条件的记录在下一次询问中仍满足，只需要加入新出现的记录。

```text
记录按 key 升序排列
询问按 limit 升序排列，并保留原编号
→ 指针 p 只向右，加入 key<=limit 的记录
→ 保存当前累计状态
→ 答案写回原编号
```

**举这个模型，是为了把“调整询问顺序”与“共享扫描状态”连起来。** 只有排序、却每次重新从头扫描，仍没有消除重复计算。

### 3.1 先明确变量、容器和范围

- **`events`：记录数组，共 `n` 条。** 每条记录保存一个 `key` 与它的贡献 `value`；容器下标为 `0..n-1`，容量按记录数确定，不按最大 `key` 开空间。
- **`key`：记录所在的比较坐标。** 它可以是时间、价格或其他条件值，不一定连续，也可以重复；它不是 `events` 的数组下标。
- **`value`：这条记录的贡献。** 通过 `events[p].value` 读取，不是拿 `key` 直接访问数组。
- **`limits`：原始询问数组，共 `m` 项。** 每项与 `key` 属于同一比较范围，但角色不同：`key` 是单条记录的坐标，`limit` 是本次允许纳入的上限。
- **`queries`：带编号的询问数组，共 `m` 项。** `queries[i]={limits[i],i}`，排序后位置可以变化，`id` 始终保留原询问下标。
- **`p`：下一条尚未加入的记录下标。** 范围为 `0..n`；`p=n` 表示已全部加入，此时不能再访问 `events[p]`。
- **`sum`：已加入记录的累计贡献。** 在不同询问之间保留，通过新增记录更新，不重新扫描旧记录。
- **`ans`：预先分配的答案数组，共 `m` 项。** `ans[q.id]` 对应原询问；按编号写入后，再顺序输出。

> **记录数决定容器下标范围，`limit` 决定本次纳入哪些 `key`。物理边界与题目条件是两件事。**

`key` 的最小、最大值只决定贡献何时开始或全部加入，不决定数组容量。没有恰好等于 `limit` 的记录时，本次可能没有新增贡献，但此前较小 `key` 的累计贡献仍要保留，不能把总答案清成 `0`。

### 3.2 按执行顺序拆开流程

1. **收集输入：** 记录数组保存各条 `key/value`，询问数组保存各个 `limit`，同时生成原编号 `id`。
2. **分别排序：** 记录按 `key` 升序，询问按 `limit` 升序；本模型允许记录重排，因为只对符合条件的贡献求和。
3. **逐个处理询问：** 外层取出 `q`，用 `q.limit` 决定本轮最多纳入哪些记录。
4. **补充新增记录：** 内层检查 `p<n` 且 `events[p].key<=q.limit`；满足就读取该记录的 `value` 加到 `sum`，再推进 `p`，直到没有新的符合条件记录。
5. **分发答案：** 将当前 `sum` 写入 `ans[q.id]`，保留处理顺序与输出顺序之间的对应关系。
6. **顺序输出：** 所有询问处理后，按 `ans[0],ans[1],...` 输出，即原询问顺序。

**`ans` 更准确的模型是“按编号归位”，不是队列插入。** 数组位置已经分配好，写回不会移动其他答案；最终顺序读取虽然类似排队输出，但不需要队列操作。

### 3.3 两个循环各自负责什么

- **外层范围 `for`** 遍历 `queries` 的有效元素，自动处理询问何时结束，不需要额外读取 `queries[m]`。
- **内层 `p<n`** 保护记录访问；条件从左到右短路求值，确认 `p` 有效后，才读取 `events[p].key`。
- **内层阈值条件** 控制本轮是否继续加入记录；一次询问可能跨过很多记录，必须用 `while`，不能只处理一次。
- **`id` 的有效性** 来自构造时写入 `0..m-1`，与记录的 `p` 无关。

> **外层管理询问，内层管理记录；先检查容器边界，再判断业务条件，最后写回原编号。**

### 3.4 数据结构与范围约定

```cpp
struct Event {
    ll key;
    ll value; // 这条记录对答案的贡献，可以为负
};

struct Query {
    ll limit;
    int id; // 原询问下标，供答案写回
};
```

本例采用 0 下标；记录数与询问数可用 `int` 表示，每条贡献在 $[-10^9,10^9]$ 内，保证任意扫描顺序下的累计值都能用 `ll` 保存。关键值和阈值只参与比较，可使用 `ll` 范围内的值。

### 3.5 排序与扫描实现

```cpp
// events 按值传入：排序副本，不改变调用方的记录顺序
// 返回值与 limits 的原顺序一致；空记录、空询问也适用
vector<ll> sumByLimit(vector<Event> events, const vector<ll>& limits) {
    int n = static_cast<int>(events.size());
    int m = static_cast<int>(limits.size());

    vector<Query> queries(m);
    for (int i = 0; i < m; ++i) {
        queries[i] = {limits[i], i};
    }

    sort(events.begin(), events.end(), [](const Event& x, const Event& y) {
        return x.key < y.key;
    });

    sort(queries.begin(), queries.end(), [](const Query& x, const Query& y) {
        return x.limit < y.limit;
    });

    vector<ll> ans(m);
    int p = 0;
    ll sum = 0;

    for (const Query& q : queries) {
        // 阈值递增，之前加入的记录不必撤销；只补充新记录
        while (p < n && events[p].key <= q.limit) {
            sum += events[p].value;
            ++p;
        }

        // 排序改变的是处理顺序，答案仍放回原询问位置
        ans[q.id] = sum;
    }

    return ans;
}
```

比较器只使用参数，不需要捕获外部变量，所以写 `[]`。返回严格小于，不能写 `<=`；相同阈值的询问结果相同，不依赖它们之间的稳定排序。

> **`p` 和 `sum` 在询问循环外初始化一次；若每个询问都重置，就丢掉了离线扫描要复用的状态。**

## 4. 不变量与具体过程

回答阈值 $t$ 时，所有 `key<=t` 的记录都已加入；`p` 指向第一条尚未加入的记录，`sum` 恰好是这些已加入记录的贡献和。

阈值递增时，满足条件的记录集合只会扩大。旧记录不必移除，每条记录最多加入一次，因此扫描不会漏项或重复计入。

例如记录为 $(2,5),(4,-8),(4,3),(7,6)$，原询问为 $[7,1,4,2]$：

| 处理阈值 | 原编号 | 本次新增贡献 | 当前和 | 写回位置 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 无 | 0 | `ans[1]=0` |
| 2 | 3 | $+5$ | 5 | `ans[3]=5` |
| 4 | 2 | $-8,+3$ | 0 | `ans[2]=0` |
| 7 | 0 | $+6$ | 6 | `ans[0]=6` |

最终按原顺序得到 $[6,0,0,5]$。

```cpp
// 调用演示：没有平台题的输入处理，结果按原询问顺序输出
void demoOffline() {
    vector<Event> events = {{2, 5}, {4, -8}, {4, 3}, {7, 6}};
    vector<ll> limits = {7, 1, 4, 2};

    vector<ll> ans = sumByLimit(events, limits);
    for (ll value : ans) cout << value << ' '; // 6 0 0 5
    cout << '\n';
}
```

### 状态推进与答案分发

对相邻处理阈值 $t_1\le t_2$，只需要加入它们之间的新记录：

$$
S(t_2)=S(t_1)+\sum_{t_1\lt \mathrm{key}_i\le t_2}\mathrm{value}_i
$$

这就是本例的增量状态更新，不必为每个阈值保存一份完整状态表。处理完一个询问，再把当前状态的结果写到它的原编号位置。

> **状态按便于计算的顺序推进，答案按原编号分发，最后顺序读取。**

因此可以不建立全量前缀结果并逐询问查索引；但若询问需要即时回答或本来就适合前缀表＋二分，仍应按场景选择。相关写法先在来源节保留，跨节反复出现后再评估是否独立成范式。

## 5. 相同关键值与等号

本例查询的是“不超过”，所以必须用 `key<=limit`，**在回答之前加入全部等于阈值的记录**。不能加入第一条相同记录后就立即回答。

| 查询要求 | 加入条件 |
| --- | --- |
| 关键值不超过阈值 | `key<=limit` |
| 关键值严格小于阈值 | `key<limit` |

如果改成把数据与询问混合排序的事件写法，等值时的处理顺序也要对应：不超过时，先加入数据再回答；严格小于时，先回答再加入等值数据。

**等号是否成立由题意决定，不能只靠排序后的巧合顺序。**

## 6. 复杂度与选型

记录排序为 $O(n\log(n+1))$，询问排序为 $O(m\log(m+1))$。两个序列各扫描一遍，总时间为：

$$
O\bigl(n\log(n+1)+m\log(m+1)+n+m\bigr)
$$

本实现复制了记录，另存询问和答案，占 $O(n+m)$ 额外空间。不是每个询问都扫描 $n$ 次；`p` 的总推进次数不超过 $n$。

| 需求 | 可考虑的方式 |
| --- | --- |
| 静态数据，询问可重排，状态容易增量维护 | 排序询问后扫描 |
| 静态数据，需要逐个到来即回答 | 排序数据＋前缀状态＋二分定位 |
| 询问本身已按需要的条件有序 | 可以直接扫描，省去询问排序 |
| 数据不断修改，或后续询问依赖前一次答案 | 先保留时间与依赖关系，不能直接套本节重排 |

**离线并不一定比二分更快。** 还要比较询问排序的成本、额外空间、是否必须实时回答，以及状态是否容易维护。

## 7. 与前面几节的区别

- [双指针](04-two-pointers.md#4-同向双指针子序列匹配)解释扫描为什么能安全前进；本节先调整询问顺序，为复用扫描创造条件。
- [前缀和](01-prefix-sum.md#2-一维前缀和状态与推导)保存已有顺序上的区间信息；离线决定先回答哪个询问，两者可以配合使用。
- [二分答案](06-binary-search-on-answer.md#2-先定义判定再证明单调)寻找可行性的真假分界；本节利用的是满足条件的记录集合随阈值扩大，**不要求答案数值单调**。示例中的负贡献让和先升后降，仍不影响扫描。

二分的候选可能来回变化，需要独立初始化每次判定；本节询问已经排好顺序，所以有意在询问之间保留 `p` 和 `sum`。**能否共享状态，取决于处理顺序与状态变化方式。**

## 8. 易错边界与不适用情况

- **忘记原编号：** 排序后直接输出会改变答案对应的询问；使用 `ans[id]` 写回。
- **边界未检查：** `p<n` 必须在访问 `events[p]` 前判断，全部记录加入后仍可能有后续询问。
- **漏掉重复记录：** 本例每条记录独立贡献，相同关键值不能去重丢掉贡献；若合并，需把贡献相加。
- **遗漏空情况：** 无符合条件的记录时和为 `0`；无询问返回空数组。
- **把询问状态全部重置：** 本例跨询问复用累计值；多组数据之间则必须重新初始化。
- **丢失时间关系：** 数据从 `1` 修改为 `10`，修改前后分别询问“不超过 3 的数量”，答案为 `1` 与 `0`。仅排序两个询问并写回编号，不能恢复修改时刻的数据。

带修改的题目也可能设计离线算法，但需要额外保留或处理时间关系，不能把“离线”理解成任意重排。

### 9.1 CF 474B：用末编号确定所属区间

各堆按原顺序排列，内部元素依次使用连续整数编号；查询编号所属的堆。堆数与询问数至多 $10^5$，每堆大小为 $1..10^3$，总数不超过 $10^6$，查询编号合法，堆号从 `1` 开始。

**收录原因：** 同一份区间边界可以支持多种定位方式；先保留数据的真实顺序，再选择询问的处理顺序，避免把计算顺序误认为输出顺序。

#### 我的思路与原 AC

`k[i]` 保存第 `i+1` 堆的末编号，数组天然递增，不排序各堆。询问按编号升序处理，越过所有末编号小于当前查询值的堆，剩下的第一堆就是答案。

```cpp
struct Query {
    int limit;
    int id;
};

vector<int> get_ans(const vector<int>& keys, const vector<int>& limits) {
    int n = keys.size();
    int m = limits.size();

    vector<Query> queries(m);
    for (int i = 0; i < m; ++i) {
        queries[i] = {limits[i], i};
    }

    sort(queries.begin(), queries.end(), [](const Query& x, const Query& y) {
        return x.limit < y.limit;
    });

    vector<int> ans(m);
    int p = 0;
    int sum = 1; // 当前堆号；始终等于已经越过的堆数 p 加 1

    for (const auto& q : queries) {
        // keys[p] 是当前堆末编号，超过它才进入下一堆
        // 本题编号上限为 10^6，+1 安全；等价条件为 keys[p]<q.limit
        while (p < n && keys[p] + 1 <= q.limit) {
            ++sum;
            ++p;
        }
        ans[q.id] = sum; // 按原询问编号写回
    }
    return ans;
}

void solve() {
    int n; cin >> n;
    vector<int> k(n);
    cin >> k[0]; // 每个 k[i] 最终保存第 i+1 堆的末编号
    for (int i = 1; i < n; ++i) {
        cin >> k[i];
        k[i] += k[i - 1];
    }
    int m; cin >> m;
    vector<int> q(m);
    for (int& x : q) cin >> x;
    q = get_ans(k, q); // 用答案覆盖询问数组，随后按原顺序输出
    for (int x : q) cout << x << '\n';
}
```

只增加过程注释和调整排版，原逻辑、类型与数组复用方式保持。

#### 正确性与边界

循环结束时，`p` 恰好是末编号小于查询值的堆数，所以所属堆号为 `p+1`。原代码的 `sum` 始终满足 `sum=p+1`，以 `1` 初始化没有偏移错误。

`keys[p]+1<=q.limit` 与 `keys[p]<q.limit` 对整数等价。本题编号上限为 $10^6$，加一安全；直接写后者更贴近“越过已结束区间”的含义，也避免把加一写法带到可能溢出的坐标范围。

查询落在某堆末编号时仍属于该堆，只有严格超过末编号才推进。每堆大小为正，末编号严格递增；合法查询不超过最后末编号，答案始终在 `1..n`。

`p<n` 保护记录访问，外层范围 `for` 遍历合法询问；`ans[q.id]` 由原编号恢复输出顺序，最后用答案覆盖 `q` 不影响先前计算。

时间为 $O(n+m\log(m+1)+m)$，空间为 $O(n+m)$。个人 AC 已通过原题样例、逐编号归属对照、端点与最大规模核验。

#### 完善与其他解法

原离线实现已经正确。可省去与 `p` 重复的 `sum`，改为写入 `p+1`；也可将 `keys[p]+1<=limit` 改为 `keys[p]<limit`，属于状态与表达简化，不改变复杂度。

**其他解：** [本章总结中的前缀和＋二分、离线扫描、直接建表](09-summary-selection.md#2-同题多解cf-474b)完整比较代码长度、重写难度与适用场景。本题默认更简短的选择是前缀边界＋`lower_bound`，离线版保留作为状态推进与答案归位的练习。

**如何想到：** 每堆对应一个连续编号区间 → 前缀和得到末编号 → 查询本质是定位第一个覆盖该编号的末端 → 查询有序时堆位置只前进 → 写回原编号后顺序输出。

### 9.2 CF 600B：两处独立漏计

对每个 $b_j$，输出数组 $a$ 中不大于它的元素数量。$1\le n,m\le2\times10^5$，值域为 $[-10^9,10^9]$，答案按 $b$ 的原顺序输出。

**收录原因：** 多层映射中，每个下标必须有单一含义；一次状态更新是否足够，应由需要跨越的记录数量决定，不能从样例的“只差一”推断成简单偏移。

#### 我的实现（修正后）

先离散化，统计不同值的频次，再将询问排序，逐步加入频次。以下采用已确认正确的修正版本，只调整排版与过程注释。

```cpp
struct Query {
    int limit;
    int id;
};

int get_id(const vector<int>& xs, int x) {
    auto it = lower_bound(xs.begin(), xs.end(), x);
    return it - xs.begin() + 1; // 值编号从 1 开始；x 来自原数组，必在 xs 中
}

vector<int> get_ans(const vector<int>& xs, const vector<int>& limits,
                    const vector<int>& cnt) {
    int m = limits.size();
    int k = xs.size();
    vector<Query> queries(m);
    for (int i = 0; i < m; ++i) {
        queries[i] = {limits[i], i};
    }
    sort(queries.begin(), queries.end(), [](const Query& x, const Query& y) -> bool {
        return x.limit < y.limit;
    });
    int p = 0;
    int sum = 0;
    vector<int> ans(m);
    for (const auto& q : queries) {
        // 一次询问可能跨过多个不同值，必须补齐后才能回答
        // 先检查 p<k，再访问 xs[p]，保护容器边界
        while (p < k && xs[p] <= q.limit) {
            // xs[p] 对应编号 p+1；先自增后读取 cnt，映射并没有偏移
            sum += cnt[++p];
        }
        ans[q.id] = sum; // 此时已加入所有 <=limit 的频次，按原询问编号写回
    }
    return ans;
}

void solve() {
    int n, m; cin >> n >> m;
    vector<int> a(n);
    vector<int> b(m);
    for (int& x : a) cin >> x;
    for (int& x : b) cin >> x;
    vector<int> xs(a);
    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());
    vector<int> id(n); // 数组位置为 0..n-1，里面存放的值编号为 1..k
    for (int i = 0; i < n; ++i)
        id[i] = get_id(xs, a[i]);
    vector<int> cnt(xs.size() + 1);
    // 遍历的是原数组位置，不能因为值编号从 1 开始就从 i=1 遍历
    for (int i = 0; i < n; ++i)
        ++cnt[id[i]];
    b = get_ans(xs, b, cnt);
    for (int x : b) {
        cout << x << ' ';
    }
    cout << '\n';
}
```

#### 踩坑一：数组位置与值编号混用

早期版本的 `id(n+1)` 按 `0..n-1` 填充，统计却遍历 `1..n`，因此漏掉 `id[0]`，并把尚未填入的 `id[n]=0` 计入 `cnt[0]`。当前版本已改为 `id(n)`，统计也统一遍历 `0..n-1`。

> **遍历原数组位置用 `i=0..n-1`；读取 `id[i]` 后得到的值编号才是 `1..k`。不能把编号范围套到位置循环上。**

扫描只累加 `cnt[1..k]`，错误计入的 `cnt[0]` 不会进入答案。**包含首项的询问可能因此少一个；不包含首项的询问则不一定受这个错误影响。**

最小反例：`a=[5]`、询问为 `5`，原输出 `0`，正确答案为 `1`。

#### 踩坑二：修正频次后，`if` 仍会漏计

修正频次下标后，处理询问仍用了 `if`，因此仍然 WA。阈值可能跨过多个尚未处理的值，必须用 `while` 将它们全部加入后再回答。

> **`if` 只判断并处理一次；`while` 才能补齐所有符合当前阈值的记录。写回答案前，不应还有未加入的 `xs[p]<=limit`。**

| 原数组 | 询问 | 只修频次、保留 `if` | 改成 `while` 后 |
| --- | --- | --- | --- |
| $[1,2,3]$ | $[3]$ | $[1]$ | $[3]$ |
| $[1,2,3]$ | $[3,3]$ | $[1,2]$ | $[3,3]$ |

相同阈值应得到相同答案；若结果随重复询问逐次增加，说明状态尚未补齐就提前回答。两个反例均已本地复现。

虽然使用两层循环，`p` 只递增、不回退，全部询问中最多推进 `k` 次；排序后的扫描成本为 $O(k+m)$，不是每个询问都完整扫描一次。

反例：`a=[9,1,2,3]`、询问为 `3`。被首项统计错误漏掉的是 `9`，它本来就不该贡献；但原 `if` 只加入值 `1`，输出 `1`，正确答案为 `3`。这说明漏计并不总是一个。

两个错误可以独立发生；以下保留历史修正路径，当前原解已经落实：

```diff
- for (int i = 1; i <= n; ++i)
+ for (int i = 0; i < n; ++i)
      ++cnt[id[i]];

- if (p < k && xs[p] <= q.limit) {
+ while (p < k && xs[p] <= q.limit) {
      sum += cnt[++p];
  }
```

**`cnt[++p]` 本身没有错。** `xs` 用 0 下标，`cnt` 用 1 基值编号：检查 `xs[0]` 后应累加 `cnt[1]`，之后 `p=1` 指向下一条记录。为便于阅读，也可拆成 `sum+=cnt[p+1]`、`++p`，但这不是修复的必要条件。

#### 推荐实现：保留原数组的重复位置，直接扫描

本题每个原数组位置贡献 `1`。排序时保留重复值，指针走过多少个位置，就已经计入多少个元素，无需额外建 `xs/id/cnt`。

**值域大不意味着循环次数多。** 这里的 `p` 是数组下标，只从 `0` 走到 `n`，不是从 `0` 枚举到最大数值。数组为 `[2,1000000000]`、阈值为 `1000000000` 时，只加入两个实际位置，`p` 从 `0` 到 `2`；中间不存在的数值不会被枚举。

原值扫描累计最多推进 `n` 次，离散化版本扫描不同值累计最多推进 `k` 次，且 `k<=n`。后者是否值得使用，取决于是否需要编号、频次和其他后续操作，而不是担心最大值导致十亿次循环。

```cpp
struct Query {
    int limit;
    int id;
};

void solve() {
    int n, m; cin >> n >> m;
    vector<int> a(n);
    for (int& x : a) cin >> x;
    sort(a.begin(), a.end()); // 保留重复值，每个位置都贡献一次

    vector<Query> queries(m);
    for (int i = 0; i < m; ++i) {
        cin >> queries[i].limit;
        queries[i].id = i;
    }
    sort(queries.begin(), queries.end(), [](const Query& x, const Query& y) {
        return x.limit < y.limit;
    });

    int p = 0;
    vector<int> ans(m);
    for (const auto& q : queries) {
        while (p < n && a[p] <= q.limit) ++p;
        ans[q.id] = p; // p 个原数组位置满足条件，无需再建频次表
    }

    for (int x : ans) cout << x << ' ';
    cout << '\n';
}
```

回答当前询问时，排序数组中前 `p` 项恰好都不大于阈值，后面都更大；因此 `p` 就是答案。重复值仍按位置逐个计入，不会被错误去重。

| 写法 | 中间状态 | 主要取舍 |
| --- | --- | --- |
| 离散化＋频次＋离线 | 原值表、位置到编号映射、频次、指针、累计数 | 适合还需要不同值编号或分值统计；映射边界较多 |
| 排序原数组＋离线 | 保留重复位置、指针、答案 | 本题状态更少，计数直接对应已扫位置 |
| 排序原数组＋逐询问二分 | 有序数组，使用 `upper_bound` 得到计数 | 不用排序询问；横向选择见[本章总结](09-summary-selection.md#4-补充对照cf-600b) |

个人修正后版本与推荐离线版均为排序加线性扫描的量级；前者还多出逐项查编号的步骤，整体仍为 $O(n\log(n+1)+m\log(m+1)+n+m)$。两版空间均为 $O(n+m)$，推荐版减少中间数组与映射，而非降低空间阶数。

个人修正版本与推荐版已通过原题样例、逐元素计数对照、重复值、负值、乱序询问和最大规模核验。个人修正后正确的结果依据本人说明；未独立查询平台提交，推荐版只标本地核验。

**如何想到：** 每条原记录独立贡献一次 → 只有阈值条件，没有必须压缩的巨大值域数组 → 原值排序后已满足扫描需求 → 指针位置直接是数量 → 需要编号时再增加离散化，不为使用已学方法而增加映射。
