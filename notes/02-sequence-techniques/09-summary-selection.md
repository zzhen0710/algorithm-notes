## 1. 方法按需求选择，不按章节顺序套用

| 需求 | 常用首选 | 可替代方案与边界 |
| --- | --- | --- |
| 静态数组上反复查询区间和 | 前缀和 | 询问少或区间很短时直接累加也可能够用 |
| 连续枚举定长区间和 | 滚动和或前缀和 | 只需下一窗口时滚动和状态更少；还要任意区间查询时保留前缀和 |
| 批量区间加，最后统一取值 | 差分 | 修改少可直接模拟；修改与即时查询交错时不能只靠最后还原 |
| 大值域等值计数 | 哈希表或排序分组 | 需要紧凑编号配合数组结构时再离散化 |
| 编号还需保持大小顺序 | 排序去重的离散化 | `unordered_map` 不能直接提供有序编号、前驱或范围计数 |
| 连续区间随条件调整 | 双指针、滑动窗口 | 必须能证明移走的端点不必回退，含负数的区间和要重新分析 |
| 静态阈值询问 | 排序数据后二分；或离线排序询问后扫描 | 比较排序成本与状态维护，不默认离线更快 |
| 候选最优值很多，判定单调 | 二分答案＋独立判定 | 已有公式或一次扫描能解决时，不必再增加二分 |
| 静态序列中，统计有位置先后的大小关系 | 归并计数 | 必须证明跨两半的贡献能利用有序性批量统计；动态修改不能直接照搬 |

**离散化不是哈希表的普遍升级，离线也不是前缀和或二分的普遍替代。** 先看是否需要值的顺序、实际距离、任意区间查询，以及是否可以改变询问处理顺序。

**离线是询问的组织方式，累计和或指针位置是状态维护方式。** CF 600B 可以用整组频次累加，也可以直接用已扫位置数 `p`；两者都能采用离线顺序。分步更新本身不能区分在线与离线，详见[本节概念误区](07-offline-processing.md#误区离线不是状态维护方式)。

这些方法不要求互斥选择。前缀和可以提供边界，再由二分或离线定位；离散化提供编号，差分维护编号之间的覆盖；先排序固定一维关系，再用归并统计另一维。

> **先确定需要维护什么关系，再选择状态、处理顺序和实现工具。** 不应为了使用某个算法，额外引入本来不需要的数组或映射。

## 2. 同题多解：CF 474B

[原题](https://codeforces.com/problemset/problem/474/B)：各堆大小为正，按原顺序连续编号，查询一个编号属于哪一堆。堆数和询问数至多 $10^5$，总编号上限 $U\le10^6$。

设第 $i$ 堆的末编号为 $P_i$，则它覆盖：

$$
[P_{i-1}+1,P_i]
$$

所以要找第一个满足 $P_i\ge x$ 的堆。**这里前缀和建立区间边界，二分或离线扫描负责定位；它们可以组合，而不是互斥。**

个人 AC 与离线证明保留在[2.7 的本题复盘](07-offline-processing.md#91-cf-474b用末编号确定所属区间)。以下是新增的其他解法，仅标本地核验，不冒充个人提交。

### 2.1 前缀和＋逐询问二分

```cpp
void solve() {
    int n; cin >> n;
    vector<int> pref(n);
    for (int i = 0; i < n; ++i) {
        cin >> pref[i];
        if (i > 0) pref[i] += pref[i - 1];
    }

    int m; cin >> m;
    while (m--) {
        int label; cin >> label;
        // 第一个末编号 >=label 的堆，正好包含该编号
        auto it = lower_bound(pref.begin(), pref.end(), label);
        cout << it - pref.begin() + 1 << '\n';
    }
}
```

每堆大小为正，末编号严格递增，`lower_bound` 返回第一个不小于查询编号的边界，正好是所属堆。查询保证合法，不会返回 `end()`；返回位置是 0 下标，输出堆号时加一。

时间为 $O(n+m\log(n+1))$，空间为 $O(n)$。不保存全部询问，读到一个就能回答。

### 2.2 前缀和＋离线扫描

完整代码引用[个人 AC](07-offline-processing.md#91-cf-474b用末编号确定所属区间)：询问排序后，逐个越过已经结束的堆，再按原编号写回答案。

时间为 $O(n+m\log(m+1)+m)$，空间为 $O(n+m)$。如果询问本身已经非降序，就能省去排序与原编号写回，直接维护一个堆位置。

### 2.3 稠密编号直接建表

```cpp
void solve() {
    int n; cin >> n;
    vector<int> size(n + 1);
    int total = 0;
    for (int i = 1; i <= n; ++i) {
        cin >> size[i];
        total += size[i];
    }

    // 这里才是按实际编号分配：合法编号为 1..total
    vector<int> owner(total + 1);
    int label = 1;
    for (int pile = 1; pile <= n; ++pile) {
        for (int j = 0; j < size[pile]; ++j) {
            owner[label] = pile;
            ++label;
        }
    }

    int m; cin >> m;
    while (m--) {
        int x; cin >> x;
        cout << owner[x] << '\n';
    }
}
```

预先记录每个合法编号属于哪一堆，查询直接访问 `owner[x]`。此时 `owner` 的下标就是实际编号，确实按 `U+1` 分配，区别于按记录数分配的 `events`。

时间为 $O(n+U+m)$，空间为 $O(n+U)$；因为每堆至少一个元素，$n\le U$，也可将空间写为 $O(U)$。这里 $U$ 较小，建表可行；编号范围很大且稀疏时不应照搬。

三种实现都已通过逐编号归属对照及题目边界核验。具体个人解题过程、踩坑与原代码只在 2.7 维护。

## 3. 写法成本与选择

本节比较**整个章节的方法**。前面的多解例题用于验证选择，不代替本章的适用范围。

代码量按必要状态与控制流程估计；现场重写成本还包括能否推导公式、核对边界，不等于背下多少行。

| 方法 | 代码量 | 现场重写 | 理解与记忆重点 | 主要成本或风险 |
| --- | --- | --- | --- | --- |
| 一维前缀和 | 短，预处理与查询各一段 | 低 | 区间起点前一项、空前缀 | 多存一份累计信息，注意溢出 |
| 二维前缀和 | 中，两重循环与容斥 | 中 | 上、左多算与左上重复 | 矩阵空间，四项下标 |
| 一维差分 | 短，端点更新＋还原 | 低 | 开始生效、越过右端后撤销 | 留出 `r+1`，不能直接即时求最终值 |
| 二维差分 | 中，四角更新＋还原 | 中 | 每个角控制哪片区域 | 正负号、行列和边界容量 |
| 离散化 | 中，建表＋映射 | 中 | 值、编号、原距离三者不同 | 排序/查找；距离不能用编号差代替 |
| 双指针 | 短到中，按模型推进 | 中 | 每次移动的排除依据 | 排序可能有成本，不能丢原位置语义 |
| 滑动窗口 | 短到中，增删状态 | 定长低，变长中 | 区间约定、可撤销状态与收缩依据 | 总移动次数及状态更新成本 |
| 二分答案 | 搜索短，判定随题变化 | 中 | 单调方向、可行范围、独立 `check` | 判定被重复调用，边界容易反向 |
| 排序询问的离线扫描 | 中到较长 | 中 | 重排安全、推进条件、按 `id` 写回 | 排序、保存询问，不能破坏时间关系 |
| 归并计数 | 较长，递归＋缓冲区 | 中到高 | 三类数对、批量贡献、相等边界 | 递归和复制，会改变数组顺序 |

**优先使用能直接表达目标、且足以通过范围的熟悉写法。** 比较方法时也要算完整成本：前缀和包括预处理和空间，离线包括询问排序，二分包括每次判定，归并包括缓冲区与复制。

### 几组容易混淆的选择

- **前缀和与滚动和：** 任意区间反复查询用前缀和；只从当前窗口推进到下一个、状态能直接增删时，用滚动维护更省状态。顺序扫描仍需匹配历史前缀时，不能因此删除历史信息。
- **离散化与哈希：** 只做等值频次统计，哈希或排序分组可能更直接；需要有序编号、数组结构或按相邻原坐标算贡献时，离散化更合适。
- **双指针与滑动窗口：** 前者强调指针推进与不回退的依据；后者还要明确当前连续区间及其增删状态，不是多写一个 `while` 就成立。
- **二分与离线：** 在线查询有序静态数据，STL 二分通常较短；能重排且状态有复用价值时再考虑离线。二分答案则是在搜索候选答案，不能与一次 `lower_bound` 混为一谈。
- **归并计数与普通排序：** 排序只给最终顺序，归并计数还利用排序过程统计原序列关系。不能用排序后的数组或比较器调用次数替代逆序对数。

### 按场景推荐

以下覆盖整章，场景仅表示准备和复用方式，具体实现仍由题目条件决定。

| 问题类型 | 蓝桥杯准备：以现场手写为目标 | CF 准备：可使用已验证片段时 |
| --- | --- | --- |
| 静态区间和、批量区间更新 | 熟练手写一维前缀和/差分；二维从容斥或四角影响推导，不只背正负号 | 同样优先直接写；反复使用的二维更新可复用短辅助函数，避免重型封装 |
| 大值域统计与有序编号 | 等值统计优先熟悉的哈希或排序分组；确需编号再写排序去重＋二分 | 复用离散化接口前核对基数、缺失返回值；不能用哈希替代顺序或范围关系 |
| 有单调推进依据的数对、连续窗口 | 按题写清指针含义与增删过程，优先少状态的定长维护 | 仍以题目状态为中心；可复用已验证的频次维护片段，不套万能窗口 |
| 单调可行性下的最优值 | 固定一种熟悉的整数二分写法，**先单独推导并验证 `check`** | 复用边界搜索，按题编写判定；检查方向、范围和每轮临时状态 |
| 静态阈值询问 | 优先评估**排序数据＋STL 二分**；重排能明显复用计算时再写离线 | 可复用询问结构与写回方式，但仍比较排序成本、状态收益和实时性 |
| 静态逆序或可转化的数对计数 | 掌握一个可独立重写的归并核心，记住返回计数、返回有序段和相等处理 | 复用已验证的归并计数入口，把注意力放在建模与排序副作用上 |

> **现场手写重在少状态、可推导、易检查；片段复用重在接口稳定、前提明确、已验证。两者都不能省去题意到模型的证明。**

当前可复用入口见[离散化](../../templates/02-sequence-techniques/discretization/README.md)、[整数二分](../../templates/02-sequence-techniques/binary-search/README.md)与[归并计数](../../templates/02-sequence-techniques/merge-counting/README.md)。CF 专用本地库的构型仍待讨论，本页不表示该专用库已经落地。

## 4. 补充对照：CF 600B

[个人实现与易错点](07-offline-processing.md#92-cf-600b两处独立漏计)使用离散化、频次和离线扫描，能保留不同值及其频次，但对“只计不大于阈值的元素个数”而言不一定需要这些中间数组。

- **排序原数组＋`upper_bound`：** 单次询问返回第一个严格大于阈值的位置，该位置之前的元素个数就是答案。代码短，不用重排询问，时间为 $O(n\log(n+1)+m\log(n+1))$。
- **排序原数组＋离线扫描：** 保留重复值，指针走过的位置数就是计数；具体实现见原节推荐版，省去编号和频次映射。
- **离散化＋频次前缀和：** 值已经压缩、还需要按不同值统计时合适；查询阈值不一定在表中，应按 `upper_bound` 定位，而不是强求精确编号。

单独用 `unordered_map` 可统计每个值的频次，但不能直接得到“不大于阈值”的总数，还需要有序键或其他范围统计方法。

## 5. 归并计数：复用核心，重新证明模型

[P1908 与 CF 1915F 的完整复盘](08-merge-counting.md#9-典题与复盘)复用同一套计数核心，区别在进入模板之前：

| 题目 | 模板前需要完成什么 | 可以直接复用什么 |
| --- | --- | --- |
| P1908 逆序对 | 原序列已表达位置与大小关系 | 严格逆序计数 |
| CF 1915F Greetings | 证明相遇条件，按起点排序后提取终点序列 | 同一套严格逆序计数 |

**值得记住的是模型接口，而不只是代码文本。** 模板接收有确定顺序的一维序列，统计严格逆序并将数组排序；来源问题要自行证明为何符合这个条件。

当前不需要为了另一个题名复制模板，也不需要提前引入尚未学习的结构作为第二份“更优解”。以后确需动态维护或其他计数关系，再比较相应方法。
