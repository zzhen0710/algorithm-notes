## 1. 方法按需求选择，不按章节顺序套用

| 需求 | 常用首选 | 可替代方案与边界 |
| --- | --- | --- |
| 静态数组上反复查询区间和 | 前缀和 | 询问少或区间很短时直接累加也可能够用 |
| 连续枚举定长区间和 | 滚动和或前缀和 | 只需下一窗口时滚动和状态更少；还要任意区间查询时保留前缀和 |
| 批量区间加，最后统一取值 | 差分 | 修改少可直接模拟；修改与即时查询交错时不能只靠最后还原 |
| 大值域等值计数 | 哈希表或排序分组 | 需要紧凑编号配合数组结构时再离散化 |
| 编号还需保持大小顺序 | 排序去重的离散化 | `unordered_map` 不能直接提供有序编号、前驱或范围计数 |
| 连续区间随条件调整 | 双指针、滑动窗口 | 必须能证明移走的端点不必回退，含负数的区间和要重新分析 |
| 静态阈值询问 | 排序数据后二分；或离线排序询问后扫描 | 比较排序成本与状态维护，不默认离线更快 |
| 候选最优值很多，判定单调 | 二分答案＋独立判定 | 已有公式或一次扫描能解决时，不必再增加二分 |

**离散化不是哈希表的普遍升级，离线也不是前缀和或二分的普遍替代。** 先看是否需要值的顺序、实际距离、任意区间查询，以及是否可以改变询问处理顺序。

**离线是询问的组织方式，累计和或指针位置是状态维护方式。** CF 600B 可以用整组频次累加，也可以直接用已扫位置数 `p`；两者都能采用离线顺序。分步更新本身不能区分在线与离线，详见[本节概念误区](07-offline-processing.md#误区离线不是状态维护方式)。

## 2. 同题多解：CF 474B

[原题](https://codeforces.com/problemset/problem/474/B)：各堆大小为正，按原顺序连续编号，查询一个编号属于哪一堆。堆数和询问数至多 $10^5$，总编号上限 $U\le10^6$。

设第 $i$ 堆的末编号为 $P_i$，则它覆盖：

$$
[P_{i-1}+1,P_i]
$$

所以要找第一个满足 $P_i\ge x$ 的堆。**这里前缀和建立区间边界，二分或离线扫描负责定位；它们可以组合，而不是互斥。**

个人 AC 与离线证明保留在[2.7 的本题复盘](07-offline-processing.md#91-cf-474b用末编号确定所属区间)。以下是新增的其他解法，仅标本地核验，不冒充个人提交。

### 2.1 前缀和＋逐询问二分

```cpp
void solve() {
    int n; cin >> n;
    vector<int> pref(n);
    for (int i = 0; i < n; ++i) {
        cin >> pref[i];
        if (i > 0) pref[i] += pref[i - 1];
    }

    int m; cin >> m;
    while (m--) {
        int label; cin >> label;
        // 第一个末编号 >=label 的堆，正好包含该编号
        auto it = lower_bound(pref.begin(), pref.end(), label);
        cout << it - pref.begin() + 1 << '\n';
    }
}
```

每堆大小为正，末编号严格递增，`lower_bound` 返回第一个不小于查询编号的边界，正好是所属堆。查询保证合法，不会返回 `end()`；返回位置是 0 下标，输出堆号时加一。

时间为 $O(n+m\log(n+1))$，空间为 $O(n)$。不保存全部询问，读到一个就能回答。

### 2.2 前缀和＋离线扫描

完整代码引用[个人 AC](07-offline-processing.md#91-cf-474b用末编号确定所属区间)：询问排序后，逐个越过已经结束的堆，再按原编号写回答案。

时间为 $O(n+m\log(m+1)+m)$，空间为 $O(n+m)$。如果询问本身已经非降序，就能省去排序与原编号写回，直接维护一个堆位置。

### 2.3 稠密编号直接建表

```cpp
void solve() {
    int n; cin >> n;
    vector<int> size(n + 1);
    int total = 0;
    for (int i = 1; i <= n; ++i) {
        cin >> size[i];
        total += size[i];
    }

    // 这里才是按实际编号分配：合法编号为 1..total
    vector<int> owner(total + 1);
    int label = 1;
    for (int pile = 1; pile <= n; ++pile) {
        for (int j = 0; j < size[pile]; ++j) {
            owner[label] = pile;
            ++label;
        }
    }

    int m; cin >> m;
    while (m--) {
        int x; cin >> x;
        cout << owner[x] << '\n';
    }
}
```

预先记录每个合法编号属于哪一堆，查询直接访问 `owner[x]`。此时 `owner` 的下标就是实际编号，确实按 `U+1` 分配，区别于按记录数分配的 `events`。

时间为 $O(n+U+m)$，空间为 $O(n+U)$；因为每堆至少一个元素，$n\le U$，也可将空间写为 $O(U)$。这里 $U$ 较小，建表可行；编号范围很大且稀疏时不应照搬。

三种实现都已通过逐编号归属对照及题目边界核验。具体个人解题过程、踩坑与原代码只在 2.7 维护。

## 3. 写法成本与选择

代码长度按实现结构比较，不把省略框架后的行数当作性能指标。

| 方法 | 代码长度 | 现场重写 | 理解与记忆负担 | 主要成本 |
| --- | --- | --- | --- | --- |
| 前缀和＋`lower_bound` | 短，一个 `solve()` | 低 | 记住“第一个末编号不小于查询值” | 每个查询做二分 |
| 前缀和＋离线扫描 | 较长，需询问结构与写回 | 中 | 同时区分边界位置、原编号和扫描状态 | 询问排序、额外数组 |
| 直接建 `owner` | 中，建表后查询很短 | 低到中 | 记清编号从 1 开始与总编号范围 | 遍历全部编号并占空间 |

### 按场景推荐

| 场景 | 默认建议 | 换方案的条件 |
| --- | --- | --- |
| 蓝桥杯准备，以现场重写为目标 | 本题优先前缀和＋`lower_bound`，代码短、边界容易核对 | 若更熟悉直接建表且总编号范围明确，使用 `owner` 也合适 |
| CF 准备，有已验证本地片段可用时 | 本题仍优先短二分；有模板不等于必须使用更复杂方案 | 询问已经有序，或很多同类问题共享增量状态时考虑扫描；小编号域、查询很多时考虑直接建表 |
| 询问已经非降序 | 前缀边界＋单向指针 | 不再需要排序和随机写回 |
| 编号域远大于记录数 | 前缀边界＋二分，或按需离线 | 不按最大编号开 `owner` 数组 |

> **推荐的是在具体条件下最省心的方案，不是为每道题指定唯一算法。**

CF 专用本地模板库的构型与维护规范仍待讨论，本页不以它已经存在为前提；当前通用模板入口保持不变。

## 4. 补充对照：CF 600B

[个人实现与易错点](07-offline-processing.md#92-cf-600b两处独立漏计)使用离散化、频次和离线扫描，能保留不同值及其频次，但对“只计不大于阈值的元素个数”而言不一定需要这些中间数组。

- **排序原数组＋`upper_bound`：** 单次询问返回第一个严格大于阈值的位置，该位置之前的元素个数就是答案。代码短，不用重排询问，时间为 $O(n\log(n+1)+m\log(n+1))$。
- **排序原数组＋离线扫描：** 保留重复值，指针走过的位置数就是计数；具体实现见原节推荐版，省去编号和频次映射。
- **离散化＋频次前缀和：** 值已经压缩、还需要按不同值统计时合适；查询阈值不一定在表中，应按 `upper_bound` 定位，而不是强求精确编号。

单独用 `unordered_map` 可统计每个值的频次，但不能直接得到“不大于阈值”的总数，还需要有序键或其他范围统计方法。
