# 2.6 二分答案

## 1. 解决什么问题

有些题直接求最优值很难，但给定一个候选值后，判断它是否可行比较容易。

例如“最少需要多少时间”，可以先问：**给定时间 $T$，能否完成任务？**

> **把“求最优值”转成“判断候选值是否可行”，再利用单调性寻找可行与不可行的分界。**

[STL 二分查找](../01-basic-problem-solving/04-stl/algorithms/02-binary-search.md#一二分查找的核心思想)在已有序列中找边界；二分答案在候选答案范围中找边界，通常不需要把全部候选存成数组。

本节采用 C++11，沿用[竞赛基础框架](../../templates/cpp-contest-template/README.md)中的 `ll`、标准库与命名空间约定，只展示相关函数。

## 2. 先定义判定，再证明单调

令 $\mathrm{check}(x)$ 表示“答案取候选值 $x$ 时，能否满足要求”。常见的两种方向：

| 优化目标 | 判定含义示例 | 随 $x$ 增大 | 要找的边界 |
| --- | --- | --- | --- |
| 最小可行值 | 在 $x$ 时间内能完成任务 | 不可行 → 可行 | 第一个 `true` |
| 最大可行值 | 每份至少为 $x$ 时仍能满足分配数量 | 可行 → 不可行 | 最后一个 `true` |

```text
最小可行值：false false false | true true true
                              ↑

最大可行值：true true true | false false false
                       ↑
```

关键不是题目出现了“最大”“最小”，而是：

- 若某个候选可行，更宽松的候选是否一定可行？
- 若某个候选不可行，更严格的候选是否一定不可行？

**反例：** $\mathrm{check}(x)$ 若表示“$x$ 恰好是某个数组元素”，对于数组 $[2,4]$，在候选 $[1,4]$ 上是 `false、true、false、true`，不能直接用本节的边界二分。

> **单调的是判定结果。原数组是否有序、目标是否叫最优值，都不能代替这项证明。**

## 3. 整数二分：最小可行值

约定整数候选范围为 $[L,R]$，判定结果从 `false` 变为 `true`，并且**`check(R)` 为真**。因此区间中至少有一个可行候选。

始终维护：**最小可行值仍在 $[l,r]$ 中。**

```cpp
// 前提：0 <= L <= R <= 10^18，check 为 false -> true
// check(R) 必须为真；check 对同一候选应返回一致结果
template<class Predicate>
ll firstTrue(ll L, ll R, Predicate check) {
    ll l = L, r = R;

    while (l < r) {
        ll mid = l + (r - l) / 2; // 向下取中点

        if (check(mid)) {
            // mid 已可行，但更小的值可能也可行，保留 mid
            r = mid;
        } else {
            // 单调性保证 <=mid 都不可行，一起排除
            l = mid + 1;
        }
    }

    return l; // l=r，候选只剩最小可行值
}
```

例如候选为 $[0,10]$，$x\ge6$ 时可行：

| 当前范围 | `mid` | 判定 | 新范围 |
| --- | --- | --- | --- |
| $[0,10]$ | 5 | 不可行 | $[6,10]$ |
| $[6,10]$ | 8 | 可行 | $[6,8]$ |
| $[6,8]$ | 7 | 可行 | $[6,7]$ |
| $[6,7]$ | 6 | 可行 | $[6,6]$ |

每轮都保留答案且严格缩小范围，最终返回 `6`。

**不能在可行时直接写 `r=mid-1`**：`mid` 可能就是最优值，当前框架没有额外变量替它保存答案。

## 4. 整数二分：最大可行值

仍使用闭区间 $[L,R]$，但判定从 `true` 变为 `false`，要求**`check(L)` 为真**。

```cpp
// 前提：0 <= L <= R <= 10^18，check 为 true -> false
// check(L) 必须为真；check 对同一候选应返回一致结果
template<class Predicate>	// Predicate 占位谓语
ll lastTrue(ll L, ll R, Predicate check) {
    ll l = L, r = R;

    while (l < r) {
        ll mid = l + (r - l + 1) / 2; // 向上取中点

        if (check(mid)) {
            // mid 可行，继续尝试更大的值，但仍保留 mid
            l = mid;
        } else {
            // 单调性保证 >=mid 都不可行
            r = mid - 1;
        }
    }

    return l;
}
```

### 为什么这里必须向上取中点

若当前只剩 $[4,5]$，向下取中点得到 `mid=4`。当 `check(4)` 为真时，`l=mid` 仍是 `4`，范围完全没变，会死循环。

向上取中点得到 `5`，无论判定真假，都会缩小范围。

| 目标 | 中点取法 | 可行时 | 不可行时 |
| --- | --- | --- | --- |
| 第一个 `true` | 向下取整 | `r=mid` | `l=mid+1` |
| 最后一个 `true` | 向上取整 | `l=mid` | `r=mid-1` |

> **中点取法要与边界更新配套。只剩两个相邻候选时，检查每个分支是否仍能推进。**

这两份函数都假定范围内有解。若题目可能无解，先检查对应端点：最小可行值检查 `check(R)`，最大可行值检查 `check(L)`；失败时按题意返回无解结果。

若判定中存在除法，候选 `0` 可能不合法。此时从合法范围开始搜索，另行处理无解，不能为了套边界而调用无定义的判定。

## 5. 完整二分示例：并行生产

有若干台独立机器，第 $i$ 台每隔 $t_i$ 时间生产一件，第一次完成在 $t_i$ 时刻。求累计生产至少 $q$ 件所需的最少整数时间。

**举这个例子，是为了把前面的二分框架与实际判定接起来：** 单独记住边界更新，还不能直接解决题目；需要定义候选值、写出判定，并给出覆盖答案的范围。

这里二分的是**时间**。循环封装在第 3 节的 `firstTrue` 中，由末尾的 `firstTrue(0, upper, check)` 调用：

- `check(time)` 只回答一次：“给定时间够不够？”它不会自己求最短时间。
- `firstTrue` 反复取 `mid`、调用 `check(mid)`，依据结果缩小范围。
- `minProductionTime` 把机器数据、搜索范围与判定组合起来，返回最小可行时间。

> **逐台累计产量是一次判定；反复改变候选时间并寻找分界，才是这里的二分。**

在时间 $T$ 内，第 $i$ 台完成 $\lfloor T/t_i\rfloor$ 件，所以：

$$
\mathrm{check}(T)=\left(\sum_i\left\lfloor\frac{T}{t_i}\right\rfloor\ge q\right)
$$

时间增加，每台机器完成的数量都不会减少，判定为 **`false → true`**。

下界取 `0`，上界可取 $\min(t_i)\times q$：即使只让最快的一台工作，也能在这个时间内完成任务。

本示例约定机器数组非空，$1\le t_i\le10^9$、$0\le q\le10^9$，保证除法有定义且上界乘积不超过 $10^{18}$。

```cpp
// t[i] 表示第 i 台机器生产一个产品需要的时间
// need 表示目标生产数量
// 机器同时工作，给定时间 time 后统计总产量
ll minProductionTime(const vector<ll>& t, ll need) {
    if (need == 0) {
        return 0;
    }

    // 最快机器单独完成所有任务的时间
    // 作为二分右边界
    ll fastest = *min_element(t.begin(), t.end());
    ll upper = fastest * need;

    auto check = [&](ll time) {
        ll made = 0;
        // 当前时间内已经生产的数量

        for (ll period : t) {
            // 当前机器在 time 时间内能生产的数量
            ll add = time / period;

            // 如果已经达到目标，无需继续计算
            if (add >= need - made) {
                return true;
            }

            made += add;
        }

        return false;
    };

    // 二分寻找第一个满足 check(time)=true 的时间
    return firstTrue(0, upper, check);
}
```

例如周期为 $[2,3]$、需求为 $5$：时间 `5` 时共完成 `3` 件，时间 `6` 时完成 `5` 件，因此答案为 `6`。

**判定也需要证明正确：** 此处直接逐台计数即可；其他模型若在 `check` 中使用贪心、搜索或 DP，还必须分别说明它们为何能正确判断可行性。

## 6. 复杂度与选型

设整数候选数量为 $W=R-L+1$，单次判定成本为 $C$，总时间为：

$$
O\bigl(C(1+\log W)\bigr)
$$

二分本身只维护常数个变量，额外空间由判定过程决定。生产示例每次检查至多遍历全部机器，因此为 $O(n(1+\log W))$ 时间、$O(1)$ 额外空间，不计输入数组。

> **二分减少候选数量，不会自动加速一次判定。写完 `check` 后，仍要把它的成本乘进去。**

| 情形 | 处理 |
| --- | --- |
| 已存储的有序数组中找位置 | 优先使用 `lower_bound` / `upper_bound` |
| 候选很多，判定单调且容易计算 | 考虑二分答案 |
| 能直接推导公式或单次扫描求解 | 先比较是否需要二分 |
| 判定反复真假切换 | 不能套本节框架 |

## 7. 实数二分：缩小误差范围

实数候选不能使用 `mid+1`、`mid-1`，也不能期待左右端点最终恰好相等。

以求非负数平方根为演示：在非负范围内，$x^2$ 随 $x$ 增大而增大，可以不断缩小根所在的区间。实际求平方根优先使用标准库 `sqrt`，这里仅用于说明边界更新。

```cpp
// 前提：0 <= value <= 10^12
// 只演示近似计算，不保证对所有非零值都具有相同相对误差
double sqrtByBinary(double value) {
    double l = 0.0;
    double r = max(1.0, value); // value<1 时也要覆盖真正的根

    for (int step = 0; step < 100; ++step) {
        double mid = l + (r - l) / 2.0;

        if (mid * mid >= value) {
            r = mid;
        } else {
            l = mid;
        }
    }

    return l + (r - l) / 2.0;
}
```

精确算术下，迭代 $s$ 次后区间宽度为初始宽度的 $2^{-s}$。实际 `double` 还受舍入限制，不能把这个理论宽度当成最终精度保证。

固定迭代次数更容易避免终止条件错误，但次数应结合初始范围、输出要求与类型精度选择。若使用区间宽度作为停止条件，也要考虑中点可能因舍入而不再变化。

**输出小数位数不等于计算精度。** 应先满足题目的绝对或相对误差要求，再设置输出格式；本节典题先练整数二分。

## 8. 易错边界

- **先保证有解。** 搜索范围需要覆盖最优值，两个函数各自要求可行端点；不能把返回边界自动当成可行答案。
- **每轮必须推进。** 特别检查只剩两个候选、答案在左右端点、全体候选可行的情况。
- **中间运算也会溢出。** `ll` 接收结果不能挽救已经发生的 `int` 乘法溢出；先提升运算类型。
- **中点公式有范围前提。** `l+(r-l)/2` 避开了 `l+r`，但若允许 `LLONG_MIN` 到 `LLONG_MAX`，`r-l` 也会溢出；本文整数函数限定非负且不超过 $10^{18}$。
- **判定不能带入旧状态。** 多次调用顺序并非从小到大；频次、累计量和临时数组应按本次候选重建或正确恢复。
- **判定的数学含义不能偷换。** “至少”“至多”“恰好”是不同约束，不能为了单调性直接替换。

### 9.1 P1873：输入最小值不等于答案下界

设置整数锯片高度，切下高于锯片的部分，要求取得至少 $M$ 的木材，求最高高度。$1\le N\le10^6$，$1\le M\le2\times10^9$，树高不超过 $4\times10^5$，所有树高总和大于 $M$。

**收录原因：** 候选值与输入值可能属于不同的范围；不能把输入的最小值、最大值未经论证就当作搜索边界。

#### 原思路与错误实现

给定锯片高度，逐树累计切下的木材；木材足够时保存高度，再向更高处搜索。判定方向与二分更新成立，但原下界取最矮树高，遗漏了合法答案。

```cpp
void solve() {
    int n;
    ll m;
    cin >> n >> m;

    vector<int> a(n);
    // 错误边界：答案可能低于最矮树高，原实现待修正
    int l = INT_MAX, r = 0;

    for (int& x : a) {
        cin >> x;
        l = min(l, x);
        r = max(r, x);
    }

    int ans = 0;
    while (l <= r) {
        int mid = (l + r) / 2;
        ll sum = 0;

        for (int x : a) {
            if (mid < x) {
                sum += 1LL * (x - mid);
            }
        }

        if (sum >= m) {
            ans = mid;
            l = mid + 1;
        } else {
            r = mid - 1;
        }
    }

    cout << ans << '\n';
}
```

**反例：** 只有一棵高度为 `10` 的树，需要 `1` 米木材。答案为 `9`，原实现只检查高度 `10`，最后输出 `0`。

#### 修正版：从合法高度 0 开始

仅将下界改为 `0`，删除读取时更新最小树高的语句，保留其余逻辑。

```cpp
void solve() {
    int n;
    ll m;
    cin >> n >> m;

    vector<int> a(n);
    int l = 0, r = 0;

    for (int& x : a) {
        cin >> x;
        r = max(r, x);
    }

    int ans = 0;
    while (l <= r) {
        int mid = (l + r) / 2;
        ll sum = 0;

        for (int x : a) {
            if (mid < x) {
                sum += 1LL * (x - mid);
            }
        }

        if (sum >= m) {
            ans = mid;
            l = mid + 1;
        } else {
            r = mid - 1;
        }
    }

    cout << ans << '\n';
}
```

高度增大，切下的木材不会增多，判定为 `true → false`。`0` 可以取得全部木材，最大树高则切不到木材，答案被覆盖。

循环中，可行的 `mid` 先存入 `ans` 再排除；不可行时排除它及更高高度。结合判定单调性，最终保留最大可行高度。

总时间为 $O(n(1+\log(H+1)))$，其中 $H$ 是最大树高；输入数组占 $O(n)$，除此之外为 $O(1)$。木材累计可能超过 `int`，使用 `ll`；本题 `l+r` 不超过 $8\times10^5$，原中点运算在约束内安全。

修正版已通过逐高度枚举及最大规模边界对照；原错误实现仍标待修正，不将本地修正版写成个人 AC。

**如何想到：** 高度越高取得越少 → 固定高度容易计数 → 找最大可行高度 → 从锯片允许的位置推导边界，而不是照搬树高范围。

### 9.2 P1182：从前缀和判定到最小滚动状态

将数列分成恰好 $M$ 个非空连续段，使各段和的最大值最小。$1\le M\le N\le10^5$，输入格式允许 $0\le A_i<10^8$，答案不超过 $10^9$。题目描述称正整数数列，但输入格式写非负整数，兼顾零值。

**收录原因：** 从复杂分支中重新确定状态的职责：先让一次判定正确，再寻找最优边界；用直接对应观察量的状态减少维护负担。

#### 我的思路与原 AC

候选 `limit` 是每段和的上限。先用前缀和查询当前段，再从左到右尝试加入元素；**只有超过上限才结束旧段，当前元素留到新段**。

- `i`：当前段起点；`j`：本轮尝试加入的位置。
- `a`：前缀和，单项通过相邻差还原。
- `res`：包含当前段在内的剩余段额度，开新段时减一，减到 `0` 表示段数超限。

以下采用修正后通过平台评测的版本作为原解；仅调整排版和注释，保留逻辑与类型。

```cpp
void solve() {
    int n, m;
    cin >> n >> m;

    vector<ll> a(n + 1);
    ll l = 0, r = 0;

    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
        // 此时 a[i] 还是原值，先更新答案下界，再改成前缀和
        l = max(l, a[i]);
        a[i] += a[i - 1];
    }

    r = a[n]; // 总和作为可行上界

    auto check = [&](ll limit) {
        // i 是当前段起点，j 是本轮尝试加入的位置
        int i = 1, j = 1;
        // res 包含当前段在内的剩余段额度；每开新段减一
        int res = m;

        while (j <= n) {
            // a 已是前缀和，通过相邻差还原单项
            int newx = a[j] - a[j - 1];

            if (newx > limit)
                return false;

            ll sum = a[j] - a[i - 1]; // 尝试加入第 j 项后的段和

            // 等于上限仍合法；只有严格超限才开新段
            if (sum > limit) {
                --res;

                if (!res)
                    return false;

                i = j; // 当前项不能丢，它成为新段第一项
            }

            ++j;
        }

        return true;
    };

    while (l <= r) {
        ll mid = (l + r) / 2;

        if (check(mid)) {
            r = mid - 1;
        } else {
            l = mid + 1;
        }
    }

    // 结束时 l=r+1，正好是最小可行上限
    cout << r + 1 << '\n';
}
```

#### 判定为什么成立

**不变量：** 每轮开始时，已经结束的段均合法，当前段为 $[i,j-1]$。加入第 `j` 项后若超限，旧段仍合法；确认单项不超限后，从 `j` 开新段，当前项不会遗漏。

非负数保证一段尽量往右放不会使后续所需段数增加。对任意合法划分，贪心首段的末端不会更早；把首个切点移到贪心末端，只会从后续段中移走非负元素。逐段重复，可知贪心得到的段数最少。

因此 `check(limit)` 判断的是：**能否用至多 $M$ 段，让每段和不超过候选上限。**

题目虽然要求恰好 $M$ 段，但不足时可以继续拆分非空段。非负数拆段不会增大段和，且 $M\le N$ 保证可以拆够，因此这里的“至多”与题目要求等价。

上限增大，原来合法的划分仍合法，判定为 `false → true`。答案下界为最大单项，上界为总和；总和对应的一段方案可继续拆成 $M$ 段，所以覆盖了答案。

原实现使用 `l<=r`，可行时排除 `mid` 并继续向左找。已经排除的更小值都不可行，更大的值都可行；结束时 `l=r+1`，输出 `r+1` 即最小可行值。它与前文 `l<r`、保留可行中点的框架不同，不能混用更新语句。

#### 四条关键收获

**1. 只需顺序累加时，优先维护当前和。**

本题每次只决定下一项能否加入当前段，`sum+x` 就能完成更新。前缀和版本正确，但需要区分原值、前缀值与段和，也增加了相邻差和两个边界的解释。

> **是否使用前缀和，取决于后续需要什么查询；“顺序扫描”只是判断线索，不是一条禁止规则。**

若仍要频繁查询不同区间、跳过整段或复用已有前缀信息，前缀和仍然合适。两版都用一个数组，滚动版并没有降低空间阶数。

**2. 拆开职责，等号尽量交给合法状态自然处理。**

本题先判断“单项能否容纳”，再判断“当前段加上它是否超限”。等于上限仍合法，因此只在 `sum>limit` 或整理版的 `sum+x>limit` 时开新段，不需要额外的等号分支。

例如当前和恰好等于上限，下一项为正数才会超限；下一项为 `0` 时仍能留在当前段，提前结算反而会引入额外处理。

> **先明确 `<`、`=`、`>` 各自的含义，再合并行为相同的状态；不能为了少写分支而删除有不同语义的等号情况。**

**3. 二分框架与判定 lambda 分离。**

`check(limit)` 只回答一次候选是否可行；外层只负责取中点、缩范围和寻找最优值。单独检查几个候选时，不需要同时追踪整段二分过程。

每次调用重新初始化段数与当前和。lambda 捕获输入数组，但不沿用上一次候选的临时状态。

可复用实现见[整数二分模板](../../templates/binary-search/README.md)，识别与迁移见[独立判定范式](../../patterns/binary-search-on-answer.md)。

**4. 从 1 记录已用段数，状态更直接。**

整理版使用 `cnt=1`，开新段时 `++cnt`，直接比较 `cnt>m`。它回答的是“现在用了几段”，调试时无需反推。

原版递减同样正确。两者的关系是：

$$
\mathrm{res}=M-\mathrm{cnt}+1
$$

这里 `res` 包含当前段在内，并不是已经扣掉当前段后的纯空闲名额。递增版让含义更直观，两种计数的时间成本相同。

#### 推荐实现：原值数组、滚动和、已用段数

保留 1 下标与原外层二分形式，只简化判定需要的状态。

```cpp
void solve() {
    int n, m;
    cin >> n >> m;

    vector<ll> a(n + 1);
    ll l = 0, r = 0;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
        l = max(l, a[i]);
        r += a[i]; // 保留原值，不建立前缀和
    }

    auto check = [&](ll limit) {
        int cnt = 1; // 已用段数，包含正在填充的当前段
        ll sum = 0;

        for (int j = 1; j <= n; ++j) {
            ll x = a[j];
            if (x > limit) return false;

            if (sum + x > limit) {
                // 旧段放不下 x，让 x 成为新段第一项
                ++cnt;
                sum = x;

                if (cnt > m) return false;
            } else {
                // 等于上限仍合法，下一项为 0 时也无需提前分段
                sum += x;
            }
        }

        return true;
    };

    while (l <= r) {
        ll mid = l + (r - l) / 2;

        if (check(mid)) {
            r = mid - 1;
        } else {
            l = mid + 1;
        }
    }

    cout << r + 1 << '\n';
}
```

| 比较项 | 原 AC | 推荐实现 |
| --- | --- | --- |
| 保存的数组 | 前缀和 | 原值 |
| 当前段和 | 用两个前缀相减查询 | 直接滚动累加 |
| 当前单项 | 用相邻前缀差还原 | 直接读取 |
| 段数 | 剩余额度递减 | 已用段数递增 |
| 主要收益 | 区间和可直接查询 | 状态含义直接，减少不必要的边界与映射 |

两版每次判定均为 $O(n)$；设搜索候选数为 $W$，总时间为 $O(n(1+\log W))$，输入数组为 $O(n)$ 空间，额外状态为 $O(1)$。推荐版的收益是简化状态与降低出错机会，不是改变复杂度阶数或宣称实测更快。

原版 `newx` 使用 `int` 安全，因为相邻前缀差仍是原单项，小于 $10^8$；前缀和可能接近 $10^{13}$，必须用 `ll`。本题 `l+r` 小于 $2\times10^{13}$，原中点运算也安全；推荐版改为差值写法，便于沿用。

边界包括：$M=1$ 时答案为总和，$M=N$ 时为最大单项；单元素与全零输入均成立，等于上限不提前分段。两版已通过连续切分枚举及大规模边界对照；原 AC 的平台结果依据个人说明，推荐实现只标本地核验。

#### 错误路径与修正

最初的判定混淆了前缀值与原值，超限后从 `j+1` 开始导致漏项，尾段又使用 `a[n]-a[i]` 漏掉第一项；嵌套分支中的 `else` 还因缺少大括号而绑定到内层条件。

| 早期错误输入 | 错误输出 | 正确答案 | 修正认识 |
| --- | --- | --- | --- |
| $[5]$，$M=1$ | 1 | 5 | 区间查询应减起点前一项的前缀 |
| $[2,2,1]$，$M=2$ | 4 | 3 | 超限项留给新段，前缀值不能当单项 |
| $[1,1,100]$，$M=2$ | 2 | 100 | 扫描包含最后一项，统一处理所有位置 |

修正后的原 AC 使用 `j<=n` 统一扫描，`i=j` 保留超限项，只在严格超限时扣减额度，不再单独拼接复杂尾段分支。

**如何想到：** 直接枚举切点组合太多 → 固定每段上限后只需判断最少段数 → 非负数允许每段尽量放长 → 用一个当前和完成判定 → 上限放宽不会破坏可行性 → 用独立 lambda 接入最小可行值二分。

> **先写出足够表达问题的最少状态，再考虑需要哪些预处理；判定与搜索分开核验。**
