# 2.4 双指针

## 1. 解决什么问题

枚举两个位置时，直接写两层循环，往往会反复检查已经不可能产生答案的组合。

如果能根据当前状态，**安全地排除一批候选，并让指针沿各自方向推进**，就不必每次重新寻找。

> **双指针的核心不是“用了两个变量”，而是：移动有依据，排除不漏解，过去的位置无需重查。**

本节使用 C++11，数组下标统一从 `0` 开始，序列长度均可用 `int` 表示。“指针”指扫描位置，不要求使用 C++ 指针类型。

## 2. 两种常见移动方式

| 形式 | 移动方式 | 常见用途 |
| --- | --- | --- |
| 相向 | 左端右移，右端左移 | 有序数列中的数对、两端配对 |
| 同向 | 两个位置都向右，各自按条件前进 | 子序列匹配、两有序序列扫描 |

移动方式只是外形。真正需要说明的是：**当前位置为什么可以舍弃？舍弃以后为什么不必回头？**

## 3. 相向双指针：有序数组中的两数之和

给定非降序数组，判断是否存在两个**不同位置**，使两数之和等于目标 $t$。重复值和负数均可出现。

初始化左端 `l=0`、右端 `r=n-1`，比较 $a_l+a_r$：

- **和偏小，移动左端**：即使配上当前最大的右端，仍不足；左端与中间任何值配对也不足。
- **和偏大，移动右端**：即使配上当前最小的左端，仍过大；右端与中间任何值配对也过大。
- **恰好相等**：已经找到一对，可以返回。

偏小时，对所有仍可能与左端配对的位置，有：

$$
a_l+a_j\le a_l+a_r\lt t,\qquad l\lt j\le r
$$

偏大时，同理：

$$
a_i+a_r\ge a_l+a_r\gt t,\qquad l\le i\lt r
$$

> **一次移动排除的是整个端点对应的一批组合，不是凭感觉让和变大或变小。**

### 3.1 注释实现

```cpp
// a 已按非降序排列，元素类型为 int，个数可用 int 表示
// 只判断是否存在，不统计所有位置数对
bool hasPair(const vector<int>& a, ll target) {
    int l = 0;
    int r = static_cast<int>(a.size()) - 1;

    // l<r 保证使用不同位置；空数组和单元素也会直接结束
    while (l < r) {
        // 先提升类型再相加，避免两个 int 在相加时溢出
        ll sum = 1LL * a[l] + a[r];

        if (sum < target) {
            // 左端与最大的候选相加仍不足，可以排除整个左端
            ++l;
        } else if (sum > target) {
            // 右端与最小的候选相加仍过大，可以排除整个右端
            --r;
        } else {
            return true;
        }
    }

    return false;
}
```

例如 $a=[1,3,4,8]$，目标为 $7$：

| `l` | `r` | 当前和 | 处理 |
| --- | --- | --- | --- |
| 0 | 3 | 9 | 过大，排除右端 `8` |
| 0 | 2 | 5 | 偏小，排除左端 `1` |
| 1 | 2 | 7 | 找到 `3、4` |

**不变量：** 已排除的端点不可能与剩余候选组成答案；若答案存在，仍位于当前未排除的范围内。

每轮至少排除一个端点，扫描最坏为 $O(n)$，额外空间为 $O(1)$。如果原数组无序，先排序后的总时间为 $O(n\log n)$。

负数不会破坏上述证明，**有序性才是这里的关键条件**。

## 4. 同向双指针：子序列匹配

判断序列 `a` 是否能从序列 `b` 中删除若干元素得到，要求匹配位置保持先后顺序，但不要求连续。

例如 `a={2,2}`，`b={2,1,2}`，可以跳过中间的 `1`，所以匹配成立。

让 `i` 指向 `a` 中下一个待匹配元素，`j` 指向 `b` 中当前检查的位置：

- 相等：完成一次匹配，`i` 前进。
- 无论是否相等，`b[j]` 都已处理，`j` 前进。

> **优先使用最早能匹配的位置，给后续元素留下尽可能长的后缀。这里不能排序，否则会破坏原来的先后关系。**

```cpp
// 不要求两个序列有序；比较的是原来的先后关系
bool isSubsequence(const vector<int>& a, const vector<int>& b) {
    int n = static_cast<int>(a.size());
    int m = static_cast<int>(b.size());
    int i = 0, j = 0;

    while (i < n && j < m) {
        // 例如 a={2,2}、b={2,1,2}
        // 第一个 2 匹配后，i 指向第二个 2；遇到 1 时只移动 j
        if (a[i] == b[j]) {
            ++i;
        }

        ++j;
    }

    // a 的所有元素都已找到；空 a 也满足这个条件
    return i == n;
}
```

**不变量：** 已扫描的 `b` 前缀中，按最早位置匹配了 `a` 的前 `i` 项。

不相等时，当前位置无法匹配当前所需元素，可以跳过；相等时，选择更晚的位置不会为后续留下更多空间，因此无需回退寻找另一种匹配。

两个位置都只前进，时间为 $O(n+m)$，额外空间为 $O(1)$。`a` 非空而 `b` 为空时返回 `false`。

## 5. 如何判断复杂度

**看指针总共移动多少次，而不是只看循环嵌套了几层。**

- 两个指针各自最多走完整个序列，且每次检查只做常数工作，总扫描通常是线性的。
- 如果每次外层循环都把另一个指针重置到起点，可能重新退化为 $O(n^2)$。
- 如果移动指针时还反复统计整段，必须把这部分开销计入，不能直接称为线性。

本节 [P1102 的 `count` 超时复盘](#踩坑用了-count即使指针前进也会-tle)展示了“指针前进，但内部仍重复扫描”的具体情况。

[P1097 的排序分组实现](03-discretization.md#本题按需求简化排序后分组)虽然包含内层 `while`，但每次跳过完整的一组，相同元素不会被下一组重复扫描，所以排序后的分组阶段仍为线性。

### 简单调用

```cpp
vector<int> values = {8, 1, 4, 3};
sort(values.begin(), values.end());
cout << hasPair(values, 7) << '\n'; // 输出 1，存在 3+4=7

vector<int> pattern = {2, 2};
vector<int> data = {2, 1, 2};
cout << isSubsequence(pattern, data) << '\n'; // 输出 1，可跳过中间的 1
```

## 6. 易错点与适用边界

- **不能只凭当前数值决定移动方向**：先证明哪些候选可以一起排除；没有这个性质，双指针可能漏解。
- **排序是否允许**：数对只关心数值时可以排序；涉及原位置、相邻关系或子序列时，要先确认是否会破坏题意。
- **存在性不等于计数**：找到一对后直接计一次、同时移动两端，并不一定能统计所有重复位置组成的数对。
- **边界先判断，再访问数组**：同向匹配要同时检查两个序列是否结束；相向求和用 `l<r`，避免同一位置使用两次。
- **结果类型单独估算**：单个数能放入 `int`，两数之和或数对数量仍可能超过其范围。

滑动窗口是同向双指针的一类应用，重点还包括区间状态的加入、删除和合法性维护，留到下一节单独整理。

### 7.1 P1102：实际值与所需值匹配

$n\le2\times10^5$，$0\le a_i\lt 2^{30}$，$1\le C\lt 2^{30}$。统计满足 $A-B=C$ 的位置数对；相同数值出现在不同位置，要分别计数。

**收录原因：** 通过改写关系，把两个值之间的约束变成“实际值与所需值相等”；进一步按重复组汇总贡献，理解指针移动次数与每次移动内部成本必须一起计算。

#### 我的思路：变换一份数组，再同向匹配

把关系改写为：

$$
A-B=C\iff B=A-C
$$

排序后的 `a` 提供实际可用的 $B$；复制一份 `need`，每项减去 $C$，表示对应的 $A$ 所需要的 $B$。统一减去常数不会改变顺序，两张表仍然有序。

两个指针依次比较 `x=a[i]` 与 `y=need[j]`：

- `x<y`：当前实际值比最小的剩余需求还小，可以排除 `x`。
- `x>y`：当前需求比最小的剩余实际值还小，可以排除 `y`。
- `x==y`：把两边相同值的整组都数完，用两组数量的乘积累计。

例如两个 `1`、三个 `3`，$C=2$：两个实际的 `1` 可以分别与三个需要 `1` 的 `3` 配对，共有 $2\times3=6$ 对。

> **每个重复位置都保留自己的贡献，但不必为每个位置重新搜索整个重复组。**

#### 原 AC

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n, c; cin >> n >> c;
    vector<int> a(n);
    for (int& x : a) cin >> x;
    sort(a.begin(), a.end());

    // need 保存每个 A 所需要的 B：B=A-C
    // a 有序，统一减去 c 后，need 仍然有序
    vector<int> need(a);
    for (int& x : need) x -= c;

    ll ans = 0;
    int i = 0, j = 0;

    while (i < n && j < n) {
        int x = a[i];
        int y = need[j];

        // x 是实际可用的 B，y 是当前 A 所需要的 B
        if (x == y) {
            ll cnt1 = 0;
            ll cnt2 = 0;

            // 当前值的整组只扫描一次，结束后 i 停在下一组
            while (i < n && a[i] == x) {
                ++cnt1;
                ++i;
            }

            // 同样统计有多少个 A 需要这个 B
            while (j < n && need[j] == y) {
                ++cnt2;
                ++j;
            }

            // 每个 B 都能与每个对应 A 组成一对
            // 例如两个 1、三个 3，c=2 时贡献 2*3=6
            ans += cnt1 * cnt2;

        } else if (x < y) {
            // 后面的需求不会更小，当前 x 已无法匹配
            ++i;
        } else {
            // 后面的实际值不会更小，当前需求 y 已无法匹配
            ++j;
        }
    }

    cout << ans << '\n';
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

#### 为什么成立与复杂度

不同值之间的大小关系保证每次排除安全；两组匹配时，每个实际值位置都能与每个需求位置配对。两组数量分别为 $\mathrm{cnt}_1$、$\mathrm{cnt}_2$，因此贡献为：

$$
\mathrm{cnt}_1\times\mathrm{cnt}_2
$$

本题 $C\gt 0$，匹配的两个原值不同，不会把同一位置与自身配成一对。整组处理后，后续也不会重复统计这组值。

两个指针只前进，组内扫描过的位置不会再扫描，因此匹配阶段为 $O(n)$。加上排序，总时间为 $O(n\log n)$，总空间为 $O(n)$；额外的 `need` 数组占 $O(n)$。

`a[i]-C` 的范围仍能用 32 位 `int` 表示，出现负数也不影响匹配。答案可能很大：两种相差 $C$ 的值各出现 $10^5$ 次，就产生 $10^{10}$ 对。因此两个计数使用 `ll`，乘法也在宽类型中进行。

#### 踩坑：用了 `count`，即使指针前进也会 TLE

曾用 `count` 统计相同值数量，出现 TLE。问题在于：**`std::count` 会检查传入范围内的每个元素，数组已排序也不会自动让它提前结束。**

若每次匹配都对整个 `a` 和 `need` 分别调用 `count`，外层指针前进并不能消除这些内部扫描。

例如原值为 $0,1,\ldots,n-1$，$C=1$，会匹配 $n-1$ 组，每组只有一个元素。即使统计后同步前移 `i、j`，每次全表计数仍检查约 $2n$ 项：

$$
2n(n-1)=\Theta(n^2)
$$

即使从当前指针起统计长后缀，后缀长度逐渐缩短，总扫描量仍可能为平方级。TLE 依据原做题记录，这里只分析反复扫描整表或长后缀的计数方式，不还原未保留的完整错误代码。

修正是**只向前数完当前相同值的一组，并让指针停在下一组**。每个位置只归入一次组内扫描，内层 `while` 不会让整体退化。

这也补充了第 5 节的判断方法：不能只数指针增减，还要检查 `count` 等库函数和其他内部操作访问了多少元素。

#### 推荐实现：直接维护匹配值的左右边界

保留排序后的 `a`，对当前 $A=x$，令 $B=x-C$。用两个只前进的边界表示：

- `l`：第一个大于等于目标 $B$ 的位置。
- `r`：第一个严格大于目标 $B$ 的位置。

>相等值都在半开范围 `[l,r)`，数量为 `r-l`。当前 $A$ 每出现一次，就加上这份可匹配的 $B$ 数量。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n, c;
    cin >> n >> c; // 本题 c>0

    vector<int> a(n);
    for (int& x : a) cin >> x;
    sort(a.begin(), a.end());

    ll ans = 0;
    int l = 0, r = 0;

    for (int x : a) {
        int want = x - c; // 固定 A=x，寻找值为 A-C 的所有 B

        // l 找到第一个 >= want 的位置
        while (l < n && a[l] < want) {
            ++l;
        }

        // r 找到第一个 > want 的位置
        // 例如 want=1、a={1,1,3,3,3}，范围为 [0,2)
        while (r < n && a[r] <= want) {
            ++r;
        }

        // [l,r) 中全部等于 want，每个都与当前 A 配成一对
        ans += r - l;
    }

    cout << ans << '\n';
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

随着 $A$ 非降，目标 $A-C$ 也非降，两个边界无需回退。完成两次推进后，`[l,r)` 恰好包含全部目标值；如果不存在，范围为空，贡献为 `0`。

重复的 $A$ 会重复加同一个范围大小，效果仍是两组数量相乘。例如三个 `3` 各加两个 `1`，总贡献仍为 `6`。

总时间仍为 $O(n\log n)$，扫描为 $O(n)$，总空间为 $O(n)$；相对原解省去一份 `need` 数组。代价是必须明确两个边界分别对应 `<` 与 `<=`，不能混淆。

两种实现都已通过本地独立位置数对枚举与最大规模核验。原解更直观地展示两表匹配，推荐版减少存储，并不改变算法阶数。

#### 如何想到

两值关系 → 改写为“一个值需要另一个值” → 排序让需求与实际值都有序 → 比较即可排除不可能匹配的值 → 重复项整组汇总贡献。

继续观察：需求只是当前值减去固定常数，可以即时得到，不一定要存整张表；匹配组也可以由两个单调边界直接描述。

### 7.2 CF 6C：比较两端下一次空闲时刻

$1\le n\le10^5$，每块巧克力耗时 $1\le t_i\le1000$。Alice 从左往右、Bob 从右往左依次吃，吃完立即继续；若同时开始吃同一块，归 Alice。输出两人各吃多少块。[洛谷中文题面](https://www.luogu.com.cn/problem/CF6C)。

**收录原因：** 将连续进行的过程表达为少量事件时刻，跳过无须逐秒模拟的中间状态；再判断当前摘要能否增量维护，避免为单次扫描保存过多历史信息。

#### 我的思路：前缀和、后缀和记录累计耗时

原数组顺序决定两人的取块顺序，不能排序。

当 $n\ge2$ 时，先把两端第一块分别分给两人。`l` 表示 Alice 已分配部分的最后位置，`r` 表示 Bob 已分配部分的最左位置：

- `a[l]` 原地变为前缀和，表示 Alice 吃完 `0..l` 的时刻。
- `suf[r]` 表示 Bob 吃完 `r..n-1` 的时刻。
- 中间尚未分配的位置是 `l+1..r-1`。

> **比较的是两人下一次能领取巧克力的时刻，不是当前巧克力的单块耗时。**

谁更早空闲，谁领取下一块；相同则先分给 Alice。每分配一块，向中间推进对应边界，直到两边相邻。

#### 原 AC

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;

    // 两人同时面对唯一一块，按题意归 Alice
    if (n == 1) {
        cout << "1 0\n";
        return;
    }

    // suf[r] 表示 Bob 吃完 r..n-1 这些块的时刻
    // 后续只会访问 r>=1，suf[0] 不需要参与计算
    vector<int> suf(a);
    for (int i = n - 2; i > 0; --i)
        suf[i] += suf[i + 1];

    // a 原地改为前缀和，a[l] 表示 Alice 吃完 0..l 的时刻
    for (int i = 1; i < n; ++i)
        a[i] += a[i - 1];

    // n>=2 时，左右两端的第一块分别归两人
    int l = 0, r = n - 1;
    int t = 0; // 原实现遗留变量，未参与计算，可删除

    // 中间还有未分配块时，由更早空闲的一方领取下一块
    while (l < r - 1) {
        // 相同时由 Alice 先领取，满足相遇规则
        if (a[l] <= suf[r]) {
            ++l;
        } else {
            --r;
        }
    }

    // 相遇时 r=l+1，左右分配形成完整切分
    cout << l + 1 << ' ' << n - (l + 1);
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

#### 为什么成立与边界

**不变量：** 已分配部分分别构成左前缀和右后缀，两人的累计耗时就是各自下一次空闲的时刻；中间部分保持原顺序且尚未分配。

选择更早空闲的一方，等价于按领取事件的先后顺序推进，不需要逐秒模拟。比较使用 `<=`，保证同一时刻争取最后一块时归 Alice。

当两人同时空闲且仍有多块时，也可以先处理 Alice 的领取。由于每块耗时为正，随后 Bob 仍处于更早的空闲时刻，会从另一端领取，符合两人同时开始的过程。

原后缀循环只构建到 `suf[1]`，这里是成立的：$n=1$ 已提前返回；之后 `r` 最小为 `1`，不访问 `suf[0]`。不能仅凭后缀没有构建到 `0` 就认定错误。

所有块总耗时最多为 $10^8$，原版 `int` 足够。变量 `t` 未参与计算，可以删除；原 AC 中保留这一遗留变量，不影响结果。

两次预处理与边界扫描均为线性，总时间为 $O(n)$；总空间为 $O(n)$，其中 `suf` 是额外的一份数组。原解通过本地逐秒模拟对照、原题样例与最大规模边界核验。

#### 推荐实现：只维护两个累计时刻

每次只会在当前一侧再加一块，累计耗时可以直接维护，不必预先保存所有前缀、后缀值。

让 `[l,r]` 表示**尚未分配**的部分，`timeA、timeB` 表示两人完成已分配部分、下一次空闲的时刻。开始时二者都为 `0`。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;

    int l = 0, r = n - 1;
    int cntA = 0, cntB = 0;
    ll timeA = 0, timeB = 0;

    // [l,r] 是尚未分配的巧克力，允许最后只剩一块
    while (l <= r) {
        if (timeA <= timeB) {
            // Alice 更早空闲；同时空闲时也由 Alice 先领取
            timeA += a[l];
            ++l;
            ++cntA;
        } else {
            // Bob 从右侧领取，累计到下一次空闲时刻
            timeB += a[r];
            --r;
            ++cntB;
        }
    }

    cout << cntA << ' ' << cntB << '\n';
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

每轮按更早空闲的一方分配下一块，时间相同先处理 Alice；分配后增加该人的累计耗时，边界向中间移动。因此事件顺序与原解相同，每块只分配一次。

这里的时刻是“已分配任务完成的时刻”，不表示两人此刻都已经吃完所有分配块。所有块分配完成后，数量已确定，剩余进食过程不再影响答案。

最后只剩一块时仍进入 `l<=r` 的循环，直接按时刻比较归属；$n=1$ 自然输出 `1 0`，不再需要特判。

时间仍为 $O(n)$，存储输入需要 $O(n)$ 空间；除输入数组外，只维护常数个变量。这个版本已通过本地逐秒模拟与最大规模边界核验，尚无独立平台 AC 记录。

#### 收益、代价与如何想到

| 比较项 | 前后缀原解 | 累计时刻实现 |
| --- | --- | --- |
| 保存状态 | 每个位置的前缀/后缀累计耗时 | 当前两人的累计耗时 |
| 除输入外的额外空间 | $O(n)$ | $O(1)$ |
| 时间 | $O(n)$ | $O(n)$ |
| 尚未分配部分 | `l+1..r-1` | `[l,r]` |
| 单块输入 | 单独处理 | 统一进入分配循环 |

两人的累计时刻足以决定下一次领取，推荐版省去后缀数组及预处理，但两套边界含义不同，**不能把原解的终止条件直接搬过来**。

逐秒模拟 → 只有吃完、领取下一块时才影响数量 → 用累计耗时确定下一次事件 → 前后缀可一次查出时刻 → 进一步发现每次只增加一块，可直接累加维护。

[后缀预处理](../../patterns/02-sequence-techniques/suffix-preprocessing.md#如何迁移与选择)适合反复查询不同位置的未来摘要；本题只需当前两端的时刻，增量维护更省状态。两题的完整复盘留在本节，不另建重复范式或模板。
