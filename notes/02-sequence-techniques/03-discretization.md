# 2.3 离散化

## 1. 解决什么问题

只有少量数值需要处理，但取值范围很大，或包含负数，不适合直接作为数组下标。

例如只有 `-5、7、1000000000` 三种值，没有必要开一个十亿规模的数组。

> **把真正出现的值按大小编号，用紧凑的下标保存信息；原值另外保留。**

本节使用 C++11，采用 **从 1 开始的编号**，方便与[前缀和](01-prefix-sum.md)、[差分](02-difference.md)配合。

## 2. 保留什么，丢失什么

将原数组复制后排序、去重，得到不同值的有序表 `xs`。

| 原值 | -5 | 7 | 1000000000 |
| --- | --- | --- | --- |
| 编号 | 1 | 2 | 3 |

**相同值映射到相同编号，原值越大，编号越大。**

因此大小比较、相等判断与排序关系保持不变。

但编号不保留原来的数值间隔：`7` 与 `1000000000` 的编号只差 `1`，实际距离却很大。

> **离散化改变的是值的表示，不是原数组中元素的位置。** 只排序值的副本或下标数组，不打乱原数组。

例如原数组 `100、-5、100、7` 映射后为 `3、1、3、2`，重复次数与先后顺序都保留。

## 3. 标准流程：收集 → 排序去重 → 二分编号

可直接复用的建表与查编号函数见[离散化模板](../../templates/discretization/README.md#接口与约定)，以下按步骤解释其主要逻辑。

### 3.1 收集需要编号的值

```cpp
#include <algorithm>
#include <iostream>
#include <numeric> // iota：生成连续下标
#include <vector>

using namespace std;

// 原值和坐标可能很大，使用 long long 保存
// 离散化后的编号较小，仍使用 int
using ll = long long;
```

```cpp
// 元素个数和不同值个数均在 int 范围内
int n;
cin >> n;

vector<ll> a(n);
for (ll& x : a) cin >> x;

// 复制原值，避免排序打乱原数组的顺序
// 例如：a = {100, -5, 100, 7}
vector<ll> xs = a;

// 排序后，相同值相邻
// xs = {-5, 7, 100, 100}
sort(xs.begin(), xs.end());

// unique 得到不重复的有效前段，erase 删除剩余尾部
// xs = {-5, 7, 100}
xs.erase(unique(xs.begin(), xs.end()), xs.end());

// m 表示不同值个数，也就是编号范围 1..m
// 示例中 m=3；后续演示未直接使用，只在这里说明含义
// 实际代码若不需要这个数量，可以省略这一行
int m = static_cast<int>(xs.size());
```

`unique` 只整理出不重复的有效前段，并返回其末尾，**不改变容器大小**。

先排序让重复值相邻，再配合 `erase` 删除尾部。

### 3.2 查找原值对应的编号

```cpp
// xs 已排序去重，编号从 1 开始
// 找到时返回编号，未收录时返回 -1
int getId(const vector<ll>& xs, ll x) {
    // 找到第一个 >= x 的值
    // 例如：xs = {-5, 7, 100}，x=7 时指向 xs[1]
    auto it = lower_bound(xs.begin(), xs.end(), x);

    // 找到末尾，或者找到的值比 x 大，都说明 x 未收录
    // 例如：x=8 时找到的是 100，不能当成 8 的编号
    if (it == xs.end() || *it != x) return -1;

    // vector 下标从 0 开始，编号从 1 开始
    // x=7 时：下标为 1，编号为 2
    return static_cast<int>(it - xs.begin()) + 1;
}
```

排序后，每个不同值只出现一次。`lower_bound` 找到它在有序表中的位置，这个位置加 `1` 就是编号。

### 3.3 按原顺序映射，并取回原值

```cpp
vector<int> id(n);

// 按原数组顺序查编号，结果也保存在原位置
// a  = {100, -5, 100, 7}
// id = {3, 1, 3, 2}
for (int i = 0; i < n; ++i) {
    // a 中的值都已加入 xs，这里不会返回 -1
    id[i] = getId(xs, a[i]);
}

// 数组非空时，以第一个元素为例取回原值
if (n > 0) {
    // id[0]=3，对应 xs[2]=100，也就是 a[0]
    ll original = xs[id[0] - 1];
    cout << original << '\n';
}
```

需要按值维护次数、权值等信息时，可开 `m+1` 项的数组，用编号访问。

> **编号用于定位，原值仍由 `xs[id-1]` 取得。**

设原数组长为 `n`，不同值有 `m` 个：

- 排序 `O(n log n)`，去重 `O(n)`，单次查编号 `O(log m)`。
- 映射全部元素后，总时间为 **`O(n log n)`**，空间为 **`O(n)`**。

空表的查找仍成立，但不能直接访问其中元素。

### 3.4 另一种写法：`iota` + 比较器排序下标

也可以不排序原值副本，而是让下标按照对应的原值排序。

> **排序下标确定值的先后，再把编号写回原位置。遇到相同值，沿用同一编号。**

`iota(order.begin(), order.end(), 0)` 将 `order` 填成 `0、1、…、n-1`，它只负责生成下标；排序关系由比较器决定。

下列写法在读入 `n、a` 后使用，**替代前面 `xs` 与 `id` 的构建过程**，不是接在原声明之后重复定义。

```cpp
// 保存原数组下标
// 例如:
// a = {100, -5, 100, 7}
//
// iota 填充后:
// {0, 1, 2, 3}
vector<int> order(n);

iota(order.begin(), order.end(), 0);

// 按照下标对应的值排序
// 注意：排序的是下标 order，不是原数组 a
//
// 一种可能的排序结果（两个 100 的下标顺序可互换）:
// order = {1, 3, 0, 2}
//
// 对应:
// a[1] = -5
// a[3] = 7
// a[0] = 100
// a[2] = 100
sort(
    order.begin(),
    order.end(),
    [&](int i, int j) {
        return a[i] < a[j];
    }
);

vector<int> id(n);
// 保存每组的原值，用于判断是否产生新编号，也能反查原值
vector<ll> xs;

for (int pos : order) {

    // 按排序后的顺序访问原数组
    // 第一次:
    // pos=1 -> a[1]=-5
    //
    // 第二次:
    // pos=3 -> a[3]=7
    //
    // 第三、四次:
    // pos=0/2 -> a[pos]=100
    if (xs.empty() || xs.back() != a[pos]) {

        // 遇到新的值，加入并分配新的编号
        xs.push_back(a[pos]);
    }

    // 将编号写回原来的位置
    //
    // 例如:
    // -5  -> 编号1
    // 7   -> 编号2
    // 100 -> 编号3
    //
    // 所以:
    // id[0]=3
    // id[1]=1
    // id[2]=3
    // id[3]=2
    id[pos] = static_cast<int>(xs.size());
}
```

对原数组 `100、-5、100、7`，扫描顺序按原值排列为 `-5、7、100、100`，写回后仍得到 `3、1、3、2`。

**不能直接用排序位置加 `1` 当编号**，否则两个 `100` 会被赋予不同编号。上面的写法仅在出现新值时增加编号，重复值自然共用编号。

比较器使用 `<`，不能写成 `<=`。`sort` 不保证相等元素的原下标顺序，但它们都取得同一编号，因此不需要 `stable_sort`。

| 比较项 | 排序原值副本 + 二分 | 排序下标 + 分组写回 |
| --- | --- | --- |
| 已有元素如何得到编号 | 逐个二分查找 | 按值扫描，直接写回原位置 |
| 总时间、空间阶数 | `O(n log n)`、`O(n)` | `O(n log n)`、`O(n)` |
| 额外处理 | 二分已有值 | 保存下标数组，比较时访问原数组 |
| 后续查任意值或范围 | 继续使用有序表 `xs` | 保留了同样的 `xs`，仍可二分 |

下标排序省去了为每个已有元素二分查编号的步骤，**总复杂度没有降低，也不能据此断言一定更快**。上面的版本还多保存一份 `order` 数组。

只需原数组各项的编号时，下标排序很直接；需要频繁按值查找时，两种写法都应保留有序原值表。二者的离散化结果相同，按后续操作与实现习惯选择即可。

## 4. 查询端点不在表中，怎么办

> **“查已有值的编号”和“查一个数值范围”是两件事。**

例如有序表为 `1、5、10`，查询原值落在 `[2,9]` 的数据，端点 `2、9` 都没有出现，但仍可以通过二分定位。

```cpp
// 查询闭区间 [l,r]，前提：l <= r，xs 已排序去重
ll l, r;
cin >> l >> r;

// 例如：xs = {1, 5, 10}，查询 [2,9]
// L：第一个 >= 2 的位置，指向 5，下标为 1
// R：第一个 > 9 的位置，指向 10，下标为 2
int L = lower_bound(xs.begin(), xs.end(), l) - xs.begin();
int R = upper_bound(xs.begin(), xs.end(), r) - xs.begin();

// 满足条件的值位于 [L,R)，这里只包含 xs[1]=5
// 因此不同值数量为 2-1=1，不是原数组中含重复项的总次数
int distinct = R - L;

cout << distinct << '\n';
```

在此例中 `L=1、R=2`，只包含原值 `5`。

> 没有符合条件的值时 `L=R`。

若另有前缀数组 `s[t]` 表示 `xs` 前 `t` 个位置的累计权值，则范围权值为 **`s[R]-s[L]`**。

权值可以是出现次数，也可以是原值对应的贡献，需先明确含义。

**单纯作为查询阈值的端点不必收录。** 需要被直接修改或编号的值则应提前收集。

## 5. 与差分配合：编号和区间长度分开

如果后续操作会修改某些坐标，应先读入操作并收集全部必要坐标，再统一编号；具体收集哪些点取决于标记方式。

| 处理对象 | 需要留意的坐标 |
| --- | --- |
| 单点加、按原值统计 | 所有可能被修改的原值 |
| 整数闭区间 `[l,r]` 的差分标记 | 使用入口与结束标记时，收集 `l`、`r+1` |
| 连续坐标的半开区间 `[l,r)` | 以边界划分区间时，收集 `l`、`r` |

`r+1` 应使用足够宽的类型，并确认不会溢出。

> **半开区间的停止位置已经是 `r`，不能机械地再加 `1`。**

只涉及大小关系时，直接使用编号即可；涉及长度时，要区分**坐标点**与**两点之间的一段**。

```text
原坐标： 0 -------- 4 -------------------------------- 100
编号：   1          2                                    3
段长：       4                         96
```

相邻坐标划分出的半开小段为 `[xs[i],xs[i+1])`，其实际长度是 **`xs[i+1]-xs[i]`**。

`m` 个不同坐标只划分出 `m-1` 个这样的有限小段。

> **编号差不能当作距离；一段覆盖也不能简单当作长度 `1`。**

整数点计数同样需要明确每段代表多少个整数，不能把收录的坐标数量直接当成整段中的点数。

是否补充相邻坐标取决于模型，不存在统一的“每个值都加减 `1`”规则。

## 6. 适用条件与易错点

- **离散化前先确定信息需求**：大小、相等关系可直接保留；距离、面积、相邻整数关系需要原坐标或额外信息。

- **提前收集，固定编号**：之后若插入新的不同值，已有编号可能整体移动；普通离散化不适合直接处理未知新值持续加入的情形。

- **区分两套下标**：本节编号 `1..m`，`xs` 下标 `0..m-1`；第 4 节的二分边界使用 `vector` 下标。

- **重复值共用编号**：去重的是坐标表，不是删除原数组中的重复元素或贡献。

- **未找到不等于可直接访问**：`lower_bound` 可以返回 `end()`，也可能指向一个更大的值。

- **估算完整规模**：收集的操作边界可能多于原数组元素；复杂度应按收集总量计算。

只要求键值统计、不需要大小关系时，也可以选用哈希表；需要有序访问但值持续新增时，可以考虑 `map`。

**离散化适合值集合可提前确定、并希望使用紧凑数组的场景。**

### 7.1 P1097：原值、编号与次数的映射

`n<=200000`，每个自然数不超过 `1.5×10^9`，不同值不超过 `10000`；按原值从小到大输出各自出现次数。

**收录原因：** 将“数值本身”与“信息的存放位置”分开，通过映射为稀疏对象建立紧凑存储；同时辨别何时需要保留原顺序，何时可以进一步省去中间状态。

#### 我的思路：用编号连接原值与次数

为了练习离散化，先保留完整的编号过程，再按编号统计。

原注释中的 `value -> no -> cnt` 与 `no -> value`，分别对应：

1. **原值 → 编号**：`a[i]` 通过 `get_id` 得到 `id[i]`。相同值必须取得相同编号。
2. **编号 → 次数**：编号为 `no` 的值，其次数保存在 `cnt[no-1]`，每出现一次就累加一次。
3. **编号 → 原值**：`xs[no-1]` 取回对应的真实数值。编号只用来定位，不能替代输出时的原值。

例如：

```text
原数组 a：       100   7   100
对应编号 id：      2   1     2

编号 no：          1     2
原值 xs[no-1]：    7   100
次数 cnt[no-1]：   1     2
```

> **`i` 表示元素在原数组中的位置，`no` 表示值的编号。相同值可以出现在多个位置，但共用一个编号和计数位置。**

`xs` 已按值排序，因此输出时让同一个下标分别访问 `xs` 与 `cnt`，就能得到升序的“原值、次数”。

#### 原实现

仅调整排版与注释，保留原逻辑。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

// 本题只查已经收录的原值，因此不需要判断是否找到
int get_id(const vector<int>& xs, int x) {
    auto it = lower_bound(xs.begin(), xs.end(), x);

    return it - xs.begin() + 1;
}

// 原值 a[i] -> 编号 id[i] -> 次数 cnt[id[i]-1]
// 编号 no -> 原值 xs[no-1]
void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;

    // 例如：a = {100, 7, 100}
    // 排序去重后：xs = {7, 100}，分别对应编号 1、2
    vector<int> xs(a);
    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());

    // 编号仍写在原来的位置：id = {2, 1, 2}
    vector<int> id(n);
    for (int i = 0; i < n; ++i) {
        id[i] = get_id(xs, a[i]);
    }

    // 次数数组使用 0 下标，访问时将编号减 1
    // 最终 cnt 的前两项为 {1, 2}
    vector<int> cnt(n);
    for (int no : id) {
        ++cnt[no - 1];
    }

    // xs 已有序，按相同下标取出原值与次数即可
    // 输出：7 出现 1 次，100 出现 2 次
    int m = xs.size();
    for (int i = 0; i < m; ++i) {
        cout << xs[i] << ' ' << cnt[i] << '\n';
    }
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

#### 为什么成立，以及边界

排序去重后，每个原值都在 `xs` 中有且只有一个位置。所有相同值得到相同编号，每次出现都累加同一个计数位置，因此 `cnt[j]` 就是 `xs[j]` 的真实出现次数。

本题只用 `get_id` 查询来自 `a` 的值，**已经保证该值被收录**，所以省略查找失败分支是成立的。移作通用函数时，仍需补回第 3.2 节的检查。

`cnt(n)` 也正确：不同值个数 `m<=n`，访问的下标最多为 `m-1`。只是开到了元素总数，实际只需要 `m` 项。

原值最多 `1.5×10^9`，单个次数最多 `200000`，本题使用 32 位 `int` 足够。

总时间为 `O(n log n+n log m)`，可写作 `O(n log n)`；空间为 `O(n)`。原实现已通过本地独立计数对照与最大规模边界核验，平台结果未记录，不标 AC。

#### 保留离散化时的小调整

如果编号只用于这一次计数，不需要先保存整个 `id` 数组，可以查到编号后直接累加：

```cpp
// xs 已完成排序去重，a 中的值全部被收录
int m = static_cast<int>(xs.size());
vector<int> cnt(m); // 按不同值个数分配，而不是按元素总数分配

for (int x : a) {
    // 原值 -> 编号 -> 计数位置，不再单独保存 id
    ++cnt[get_id(xs, x) - 1];
}
```

这省去一份编号数组和一次遍历，但时间、空间阶数都不变。练习时保留 `id` 更方便观察映射，原方案无需因此推翻。

#### 本题按需求简化：排序后分组

本题最后只输出每个值及次数，**不再询问某个原位置的编号**。因此可以直接排序原数组，让相同值相邻，然后统计每组长度。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int& x : a) cin >> x;

    // 只需按值输出统计结果，不再需要保留原来的位置
    // 例如：{100, 7, 100} -> {7, 100, 100}
    sort(a.begin(), a.end());

    for (int i = 0; i < n;) {
        int j = i + 1;

        // 从 i 开始找到一整组相同值
        // i=1 时，两个 100 位于 [1,3)
        while (j < n && a[j] == a[i]) {
            ++j;
        }

        // 原值是 a[i]，这一组的元素个数就是出现次数
        cout << a[i] << ' ' << j - i << '\n';

        // 下一组从 j 开始，每个元素只归入一组
        i = j;
    }
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

排序后，一个值的全部出现位置连续且属于同一组；`[i,j)` 的长度 `j-i` 就是次数。输出后跳到下一组，既不遗漏也不重复，且原值天然升序。

这个版本也已通过本地独立计数对照。总时间仍为 `O(n log n)`，空间为 `O(n)`，但只保留一个输入数组，不再维护 `xs、id、cnt`，也省去了逐项二分。

代价是**原数组顺序被改变**，并且没有建立可供后续使用的编号映射；本题不需要这些信息，因此这个版本更简洁。

#### 与哈希表的关系

> **共同点是避免按巨大值域开数组；区别是离散化建立有序的连续编号，哈希表直接按键查找。**

`unordered_map` 可以边读边统计，通常不需要提前收集全部值；但它不保证键的遍历顺序，也不提供可用于比较大小的编号。

| 方案 | 时间 | 主要特点 |
| --- | --- | --- |
| 原离散化实现 | `O(n log n+n log m)` | 明确保留原值、编号、次数的联系 |
| 排序后分组 | `O(n log n)` | 本题所需信息少，实现直接 |
| 哈希统计，再排序不同键 | 平均 `O(n+m log m)` | 只存不同键与次数，但需处理有序输出 |

本题不同值至多 `10000`，哈希统计后只排序不同键，平均复杂度有优势，实际可能更快；但碰撞、常数开销和输入分布都会影响表现，**不能保证一定更快**。也不能把哈希桶的下标当成离散化编号。

#### 如何想到

值域巨大 → 直接按原值开数组浪费空间 → 实际不同值少 → 按值编号，用小数组统计 → 输出时通过有序表取回原值。

继续追问“最后还需要哪些信息”：若只输出整表统计，原位置与编号映射都不再使用，便可简化为排序分组；若后续还要按值查询、维护权值或使用区间工具，离散化建立的编号就能继续复用。

### 7.2 P1496：从逐点覆盖到按段计算

[原题：火烧赤壁](https://www.luogu.com.cn/problem/P1496)。每段是左闭右开区间 `[a,b)`，`n<=20000`，`-2^31 <= a < b < 2^31`，答案小于 `2^31`；求全部燃烧位置的总长度，重叠部分只计算一次。

**收录原因：** 不再逐个位置处理覆盖，而是寻找状态变化的边界；把连续空间划成状态不变的小段，按实际长度合并贡献。理解离散化不仅可以给数值编号，也能为连续区间建立紧凑的状态表。

#### 我的思路：统一端点编号，再对小段差分

最初没有看出离散化的用途。若尝试按原坐标逐点标记或做差分，数组会随坐标范围变得很大；但覆盖状态只在区间端点处改变。

所有左右端点统一排序去重后，最多只有 `2n` 个不同坐标。相邻坐标之间没有新的端点，覆盖次数保持不变，可以作为一整段处理。

> **编号用来定位状态，原坐标用来计算长度。只要覆盖次数大于 `0`，这一段的长度就加一次。**

采用一基编号时，坐标编号 `i` 对应 `xs[i-1]`；还原后的 `d[i]` 表示小段 `[xs[i-1],xs[i])` 的覆盖次数。

例如两段 `[1,5)`、`[3,7)`：

| 编号 `i` | 原坐标 `xs[i-1]` | 右侧小段 | 还原后 `d[i]` | 长度贡献 |
| --- | --- | --- | --- | --- |
| 1 | 1 | `[1,3)` | 1 | 2 |
| 2 | 3 | `[3,5)` | 2 | 2 |
| 3 | 5 | `[5,7)` | 1 | 2 |
| 4 | 7 | 末端，无右侧有限小段 | 0 | 不计 |

总长度是 `6`，中间被覆盖两次的小段仍只贡献一次长度。

#### 过程中的混淆与修正

| 原问题 | 为什么不成立 | 修正 |
| --- | --- | --- |
| 左右端点分别离散化 | 两套编号不在同一条数轴上，大小关系失真 | 所有端点放进同一张 `xs` |
| 用 `idl[al[i]]` 取编号 | 把原坐标当成输入数组下标，可能越界 | 第 `i` 条区间用 `idl[i]、idr[i]` |
| 半开区间在 `r+1` 停止 | 右边界本身就是停止位置，延后一段会多覆盖 | `++d[l]、--d[r]` |
| 用 `al、ar` 的下标计算扫描长度 | 输入顺序与压缩后的坐标顺序没有对应关系 | 回到统一坐标表计算段长 |

> **原数组下标、坐标编号、原坐标值是三种不同的量，不能互相代用。**

#### 原实现

仅调整排版与注释，保留原实现逻辑；平台评测结果未记录，这里不标 AC。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

// 只查询已经收录的端点，返回从 1 开始的编号
int get_id(const vector<int>& xs, int x) {
    auto it = lower_bound(xs.begin(), xs.end(), x);
    return it - xs.begin() + 1;
}

void solve() {
    int n;
    cin >> n;

    vector<int> al(n), ar(n);
    for (int i = 0; i < n; ++i) {
        cin >> al[i] >> ar[i];
    }

    // 左右端点必须在同一张表中编号
    // 例如：[1,5)、[3,7) -> xs = {1,3,5,7}
    vector<int> xs;
    for (int x : al) xs.push_back(x);
    for (int x : ar) xs.push_back(x);
    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());

    // idl[i]、idr[i] 是第 i 条输入区间的端点编号
    vector<int> idl, idr;
    for (int x : al) idl.push_back(get_id(xs, x));
    for (int x : ar) idr.push_back(get_id(xs, x));

    int size = xs.size();
    vector<int> d(size + 1);

    for (int i = 0; i < n; ++i) {
        int l = idl[i];
        int r = idr[i];

        // 半开区间：从左端点开始，到右端点停止
        ++d[l];
        --d[r];
    }

    for (int i = 1; i <= size; ++i) {
        d[i] += d[i - 1];
    }

    int ans = 0;
    for (int i = 1; i <= size; ++i) {
        // d[i] 对应小段 [xs[i-1],xs[i]) 的覆盖次数
        // 最大端点处 d[size]=0，末轮不会读取 xs[size]
        if (d[i] > 0) ans += xs[i] - xs[i - 1];
    }

    cout << ans << '\n';
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

#### 正确性与边界

每条 `[l,r)` 在左端点开始贡献 `1`，到右端点停止。对边界标记求前缀和后，恰好得到每个小段的覆盖次数。

这些小段互不重叠，并覆盖所有可能燃烧的位置；只累加覆盖次数大于 `0` 的段长，既不会漏掉被覆盖位置，也不会重复计算重叠部分。

原循环扫描到 `i==size`。全部区间都已在最大端点处结束，所有加减标记之和为 `0`，因此 **`d[size]==0`**，不会执行包含 `xs[size]` 的表达式。

这个写法在本题条件下成立。不过真正需要计长的小段只有 `size-1` 个，通用写法可以把边界直接写清：

```cpp
// d 已还原，size 是不同端点个数；编号从 1 开始
ll ans = 0;

for (int i = 1; i < size; ++i) {
    if (d[i] > 0) {
        // 先提升为 long long，再计算两个原坐标之差
        ans += 1LL * xs[i] - xs[i - 1];
    }
}
```

题目保证总长度小于 `2^31`，且每次加的都是被覆盖小段的非负长度，所以原版 `int` 的累加和实际执行的段长减法在本题范围内成立。迁移到没有该保证的题目时，坐标差和答案应使用足够宽的类型。

设不同端点数为 `m<=2n`：总时间 `O(n log n+n log m+m)`，即 `O(n log n)`；空间 `O(n)`。原实现已通过本地逐单位覆盖对照、交叠/相接/包含关系及最大规模边界核验，平台结果未记录。

#### 另一种做法：排序合并区间

如果只需要并集长度，可以不保存每段的覆盖次数，而是直接维护当前合并出的区间 `[l,r)`。

1. 按左端点排序，让后面的区间不会回到更左边。
2. 若下一段起点不超过 `r`，扩展右边界；遇到包含关系时取 `max`，不能缩短当前覆盖。
3. 若下一段从 `r` 右侧开始，当前区间已经完整，结算 `r-l` 并开启新区间。
4. 循环结束后，补结算最后一个区间。

```cpp
#include <bits/stdc++.h>

using namespace std;

using ll = long long;
using pii = pair<int, int>;
using pll = pair<ll, ll>;

void solve() {
    int n;
    cin >> n; // 本题 n >= 1

    vector<pll> seg(n);
    for (auto& p : seg) cin >> p.first >> p.second;

    // 先按左端点排序，左端点相同时再按右端点排序
    sort(seg.begin(), seg.end());

    ll l = seg[0].first;
    ll r = seg[0].second;
    ll ans = 0;

    for (int i = 1; i < n; ++i) {
        if (seg[i].first <= r) {
            // 相交或首尾相接，都可继续维护同一片覆盖
            // 例如：[1,5) 接 [3,7)，右边界扩展为 7
            r = max(r, seg[i].second);
        } else {
            // 下一段已在 r 右侧，之后也不会有区间来填补这个空隙
            // 结算当前覆盖，再开启新的一片
            ans += r - l;
            l = seg[i].first;
            r = seg[i].second;
        }
    }

    // 最后一片没有后续区间触发结算，需要在循环外补上
    ans += r - l;

    cout << ans << '\n';
}

int main() {
#ifdef LOCAL
    freopen("input.txt", "r", stdin);
#endif

    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;

    while (T--) {
        solve();
    }

    return 0;
}
```

**不变量：** 扫描过程中，已经结算的区间互不相交；`[l,r)` 描述尚未结算的最后一片连续覆盖。

由于左端点有序，一旦下一段的左端点大于 `r`，后面的区间也不可能填补该空隙，所以可以立即结算。相接的半开区间也可以合并，其并集长度不变。

总时间 `O(n log n)`，存储输入需要 `O(n)` 空间；排序后扫描只维护常数个变量。这个版本也已通过本地独立覆盖对照，平台结果未记录。

最后一片没有后续区间触发结算，对应已有范式：[状态扫描与尾状态处理](../../patterns/02-sequence-techniques/state-scan-finalization.md#区间合并中的尾状态)。

#### 两种做法的收益与代价

| 比较项 | 离散化 + 差分 | 排序合并区间 |
| --- | --- | --- |
| 维护的信息 | 每个小段的覆盖次数 | 覆盖区间的并集 |
| 求并集长度 | 对覆盖数 `>0` 的小段计长 | 对合并后的区间计长 |
| 覆盖至少 `k` 次的长度 | 可以继续利用覆盖次数 | 普通合并会丢失重数，不能直接求 |
| 实现负担 | 统一编号、差分、下标与原坐标转换 | 排序、扩展区间、尾段结算 |
| 总时间、空间阶数 | `O(n log n)`、`O(n)` | `O(n log n)`、`O(n)` |

**只求本题答案，区间合并更直接；需要覆盖重数时，按边界划段的状态表更有用。** 两种方法都是合适方案，不能因为某种知识正在学习，就把它视为唯一解法。

离散化版本还可在收集端点时直接加入 `xs`，并在查到编号后立即写差分，省去 `idl、idr`；这属于中间存储的简化，不改变模型和复杂度。

#### 如何想到与迁移

> 大范围区间覆盖 → 逐点处理的规模取决于坐标范围 → 覆盖状态只在端点变化 → 按端点划分状态不变的小段 → 用原坐标差累计所需贡献。

> 另一条路线是：只需并集 → 不必保存覆盖重数 → 排序保证新区间从左到右到来 → 合并相交或相接区间，分片结算。

通用的识别方法提炼为[稀疏边界划段：按状态不变的区间计算](../../patterns/02-sequence-techniques/sparse-boundary-segments.md)。建表与编号查询复用[离散化模板](../../templates/discretization/README.md#接口与约定)；完整个人过程和双解仍保留在本题下。
