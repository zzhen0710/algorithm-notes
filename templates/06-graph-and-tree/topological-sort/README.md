# 拓扑排序与关键路径

实现：[topological_sort.hpp](topological_sort.hpp)。来源：[6.5 拓扑排序与关键路径](../../../notes/06-graph-and-tree/05-topological-sort.md)，按已有通用实现自行收敛。

## 接口与边界

- `topo_sort(g,order)`：**1-based 有向图**，g 至少有占位项 `g[0]`，所有端点合法；点数和各点入度均可用 int 表示。
- 每次先清空 order；返回 `true` 时，order 包含全部点的合法顺序。**返回 `false` 时，order 只是部分前缀，不能当作完整拓扑序。**
- 不修改输入图；入度由全部边重新统计，多次调用相互独立。重边必须在统计和删除时保持同样的记录数。
- 孤立点也入队；自环或任意连通部分的有向环都会导致失败。`g.size()==1` 表示零个点，返回成功且顺序为空。
- 普通队列给出任意合法顺序，**不保证字典序最小**；若题目要求，需要改为小根堆。

时间与辅助空间分别为 `O(n+m)`、`O(n)`。模板只安排计算顺序；最长路、计数等 DAG DP 的状态、初值与更新仍由题目决定，不塞进排序函数。

## AOE 关键路径：正反两次时间递推

实现：[critical_path.hpp](critical_path.hpp)；教学：[6.5 补充：关键路径与项目工期](../../../notes/06-graph-and-tree/05a-critical-path.md)。同属 6.5 单元，保留基础拓扑与应用的接口区分。

```cpp
#include "critical_path.hpp"

std::vector<Activity> edges;
edges.push_back({u, v, w}); // u、v 是事件；这条边是一项耗时为 w 的活动
auto r = critical_path(n, edges);
if (r.ok) {
    long long project_time = r.duration;
    long long earliest_event = r.ve[u];
    long long latest_event = r.vl[u];
    long long activity_slack = r.slack[id];
    // r.critical 中保存零余量活动的原边 id
}
```

**用途速记：** 给出完整 AOE 活动表，返回统一项目的最短工期、事件最早／最迟时刻、活动余量和全部关键活动 id。正向 Kahn＋max 处理前驱下界，逆拓扑＋min 处理后继上界；不枚举项目安排或所有最长路径。

| 输入／结果 | 约定 |
| --- | --- |
| n、端点 | n≥1，事件 1..n，0 号不使用 |
| Activity{u,v,w} | 每条活动只存一次，w≥0，原边 id 为输入表下标 0..m−1 |
| r.ok | 成功为 true；有环或负耗时返回 false，其他数组为空、工期为 0 |
| r.duration | 全部活动完成的最短统一工期 T |
| r.ve、r.vl | n+1 项，分别为事件最早与不超过 T 时的最迟发生时间 |
| r.slack[id] | vl[v]−w−ve[u]，该活动的总余量 |
| r.critical | 按输入顺序列出全部零余量活动 id；不保证只是一条路径 |

- **条件：** 图为 DAG、所有活动都须完成、资源充足且允许并行；不处理有限机器或额外资源约束。
- **多源／多终点：** 所有源事件可从 0 开始，全部终点共用 T 的截止时间；相当于补零耗时统一起终点，但实现不增点。不同分支若有各自独立截止时间，需要另改模型。
- **无边／孤立点：** 合法；无边时 T=0。孤立事件 ve=0、vl=T，0 号占位数值无意义。不用 duration==0 判断成功。
- **重边／零耗时：** 允许，活动按 id 分别保存，入度也配套统计；自环按有向环拒绝。
- **类型：** C++11；n+1、m、入度和列表长度需能用 int 表示；所有路径累计耗时需用 long long 容纳，可用 (n−1)×最大耗时估计上界。
- **时间／空间：** O(n+m)／O(n+m)。函数不修改原活动表，每次调用重建全部状态，不依赖系统递归深度。
- **结果含义：** 事件时间不等于活动开始时间。活动最早开始为 ve[u]，最迟开始为 vl[v]−w；不是直接读 vl[u]。多个活动的总余量不能未经分析同时累加使用。
- **复用方式：** 基础 topo_sort 继续只返回顺序；关键路径函数在 Kahn 阶段同步计算最早时间，再反向递推。不修改基础接口，也不建立第二份反向图。

本仓库按 AOE 模型自行实现；与基础拓扑模板共用一个知识单元和目录，分别保留必要接口。参考 [Princeton Algorithms：关键路径法](https://algs4.cs.princeton.edu/44sp/index.php)。[P1113 实际实现复盘](../../../notes/06-graph-and-tree/05a-critical-path.md#7-典题复盘p1113-杂务)补任务点权到入边权的转换：无前置任务从虚拟起点接入，边权为自身耗时。通用算法未改；个人代码只做静态复盘，不把模板验证记为个人掌握。
