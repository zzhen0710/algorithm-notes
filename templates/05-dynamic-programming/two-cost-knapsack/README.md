# 两种费用的 0/1 背包

实现：[knapsack_2d.hpp](knapsack_2d.hpp)。来源与读写图见 [5.13 多维费用背包](../../../notes/05-dynamic-programming/13-two-cost-knapsack.md)。模型参考 OI Wiki，函数按本仓库契约自行整理，不依赖其他模板。

```cpp
#include "knapsack_2d.hpp"

std::vector<BiItem> items{{2, 1, 5}, {1, 2, 6}};
ll a = knapsack_2d(3, 3, items); // 11，两件都选。
ll b = knapsack_2d(3, 2, items); // 6，第二种资源不足以同时选择。
```

**用途速记：** 给出每件的两项消耗与收益，在两项资源上限内返回最大总收益。每件至多一次、允许不选；两容量倒序，读取上一轮的来源。

| 接口 / 字段 | 含义 |
| --- | --- |
| `BiItem {cost1,cost2,value}` | 本件同时消耗两种资源，增加一份收益 |
| `knapsack_2d(cap1,cap2,items)` | 两项总占用分别不超过上限时的最大收益 |
| 返回值 | ll，允许空方案，至少为 0 |

## 前提与边界

- items 为 0-based；容量下标为 `0..cap1`、`0..cap2`。cap1、cap2 取 `0..200000`，且 `(cap1+1)*(cap2+1)` 不超过 4000000 个格；这是本模板约定的存储边界，不是同时取大规模的时间保证。估算乘积时使用 ll，仍须结合时限和内存限制。
- 两项消耗为非负 int，允许一项或两项为 0；超出任一总上限的物品直接跳过。负的费用不在适用范围。
- 物品数不超过 200000，`abs(value)<=1e12`；累计值绝对值不超过 `2e17`，ll 足够。负价值允许不选；不同物品即使字段相同，也各有一次选择机会。
- 两项费用都为 0 时，每件对每格只更新一次，正收益只加一次。这里不是同组多个候选互斥的模型，不需要组内 best。
- 输入只读，每次调用新建局部表；空列表返回 0，多次调用无需额外清理，容量为 0 仍会处理对应零费用物品。
- 仅处理每件至多一次、两项资源上限与最大收益；不要求恰好用满，不处理必须选、方案计数、方案恢复或跨物品依赖。
- `ll`、`BiItem`、`knapsack_2d` 为头文件级名字，合并代码时避免重复定义。无其他模板依赖。

“最多选几项”和“有多少种选法”的状态、初始化与代码对照，见[笔记中的计数对照](../../../notes/05-dynamic-programming/13-two-cost-knapsack.md#对照统计合法选法数量)；计数不属于本头文件接口。

## 复杂度与核验

n 件物品，两项容量为 C1、C2。计入建表，时间上界 O((n+1)(C1+1)(C2+1))，额外空间 O((C1+1)(C2+1))，输入另占 O(n)。一般简写 O(nC1C2)、O(C1C2)。

正文实现与头文件分别核对小规模子集枚举，覆盖零费用、负收益、容量不足、空输入、重复物品和多次调用；另检查较大数值与表大小边界。P1507、P1855 个人实现已静态复盘，主体与通用实现相同，区别在输入与收益字段；个人 Item 对应本模板 BiItem，无需另增接口。未重复编译、运行或对拍个人代码，通用核验不代表平台结果或个人掌握。
