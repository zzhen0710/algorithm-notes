# 多重背包：二进制拆分与单调队列

实现：[bounded_knapsack.hpp](bounded_knapsack.hpp)。状态、拆分证明与配题见 [5.10 多重背包](../../../notes/05-dynamic-programming/10-bounded-knapsack.md)。自行按数量覆盖与 0/1 转移整理，不依赖其他头文件。

## 接口与使用

```cpp
#include "bounded_knapsack.hpp"

std::vector<BoundedItem> items{{2, 3, 3}, {3, 5, 2}};
ll ans = bounded_knapsack(8, items); // 13：取第一种 1 件、第二种 2 件

// 已有 dp 时，可逐种加入，保持此前组合。
std::vector<ll> dp(9, 0);
add_bounded(dp, 2, 3, 3);
add_bounded(dp, 3, 5, 2);
// dp[8] == 13；不要在两次调用之间清空 dp。
```

**用途速记：** 每种物品给单件占用、价值和最多件数，返回总占用不超过容量的最大价值。把数量拆成少量包，每包各做一次倒序 0/1 更新；允许不装满。

| 接口／字段 | 约定 |
| --- | --- |
| `BoundedItem {cost, value, count}` | 单件占用、单件价值、数量上限；数量 0 表示不能选 |
| `bounded_knapsack(cap, items)` | 新建全 0 数组，处理全部种类，返回 `dp[cap]` |
| `add_bounded(dp, cost, value, count)` | 在现有容量上限状态上加入一种物品，原地修改 dp；不返回完整表副本 |

## 前提与边界

- 物品数组 **0-based**；`dp` 非空，下标 `0..cap`，`cap=(int)dp.size()-1`。不需要 1 基占位。
- 本模板约定 `0<=cap<=200000`、`cost` 为正 int、数量 count 为非负 int，可取 `INT_MAX`、`0<=value<=1e9`；同类物品成本与价值相同、可直接累加。超出这些范围须重新核对乘法和倍增范围。
- 先将数量截为 `min(count, cap/cost)`，所以包占用不超过 cap，`take*cost` 不会越过 int；包价值及累计值用 ll，总价值不超过 `cap*1e9`。
- 空物品数组、容量 0、数量 0 均合法；单件占用超过容量时自动跳过。`cost=0` 不在契约内，不能传入。
- `add_bounded` 接收的每格必须已表示相同“不超过容量”的最大价值；不能传恰好容量的不可达哨兵表并期待自动兼容。
- `bounded_knapsack` 不修改输入；每次调用独立初始化。`add_bounded` 保留之前的 dp，多测须由调用者新建或重置。
- 只求最优值，不保存选法；**不直接支持方案计数、恰好装满或无限次字段约定**。输入中用 0 表示无限次时，应先按原题语义区分。

## 单调队列版：每种扫描一遍容量

实现：[bounded_knapsack_queue.hpp](bounded_knapsack_queue.hpp)。推导、同余分组与执行图见 [5.11 单调队列优化 DP](../../../notes/05-dynamic-programming/11-monotonic-queue-dp.md)。

```cpp
#include "bounded_knapsack_queue.hpp"

std::vector<BoundedItem> items{{2, 3, 3}, {3, 4, 2}};
ll answer = bounded_knapsack_queue(13, items); // 17
```

- `bounded_knapsack_queue(cap, items)`：新建 DP，求容量内最大价值，不修改 items。
- `add_bounded_queue(dp, cost, value, count)`：在已有上限语义 DP 中加入一种物品，原地写入新行；内部复制 old，全部候选来自旧行。
- 复用原头文件中的 `BoundedItem`、ll 与相同输入契约，不重复定义结构体。现场复制为单文件时，把结构体与函数放到一起，不必复制二进制函数主体。
- 队列保存“组内编号、固定分数”，每组重新清空；同分删旧留新。负分数可以合法，不能自动当作不可达。
- 数量 0、容量 0、单件占用超过容量时直接保留原 DP；`INT_MAX` 先被容量截断，不直接参与倍增或乘法。
- 本实现仍只支持容量上限最大价值、非负价值；不直接支持带 −INF 哨兵的恰好容量表。外部传入的 DP 须满足原语义，所有中间算式可用 ll 表示；原契约下变形分数与加回后的值均安全。

时间 $O(n(C+1)+C)$，常简写 $O(nC)$；辅助空间 $O(C+1)$，包括一份旧行与候选队列。单次加入一种物品为 $O(C+1)$，不可选的种类提前 $O(1)$ 返回。

| 选择 | 主要转移 | 代价与用途 |
| --- | --- | --- |
| 二进制拆分 | $O(C\sum\log(m'_i+1))$ | 代码较短，直接复用 0/1 思路 |
| 单调队列 | $O(nC)$ | 多一份旧行、同余分组与分数变形；转移次数更少 |

两者独立核验，旧个人题目继续保留原写法，不因新增模板补记平台结果。

## 入队顺序由当前转移决定

本队列实现先加入旧行的 `s=t` 再查询，因为当前种类取 0 件也合法。不能把这个顺序直接套到所有 DP。

[P1725／P2627 的实际复盘](../../../notes/05-dynamic-programming/11-monotonic-queue-dp.md#两题对照候选算好不等于已经可以入队)分别展示“补入新进入窗口的旧状态后计算”与“先计算当前状态，再入队供后续使用”。两题自己定义路径／舍弃成本状态，不直接调用本多重背包接口；特别是带不可达与合法负值的路径 DP，不能忽略初始化契约。

## 两题怎样共用

[P1776](../../../notes/05-dynamic-programming/10-bounded-knapsack.md#p1776-宝物筛选)读入“价值、重量、数量”后直接调用；[P1833](../../../notes/05-dynamic-programming/10-bounded-knapsack.md#p1833-樱花)先把时间差转成分钟，再把原题表示无限次的 0 改成 `cap/cost`。不改变同一套状态与转移。

因为本实现先截断数量，也能用 `INT_MAX` 暂代无限次；原解保留显式 `cap/cost`，含义更清楚。**不能把原始 0 直接交给本模板，那会被解释成一件也没有。**

## 复杂度与核验

设 n 为种数，B 为按有效数量拆出的总包数。包装函数时间 `O(n+cap*(B+1))`，包括容量数组初始化；逐种加入接口不重复初始化。

**常用写法：** 每种有效数量最多 M 时，主要转移为 $O(n\cdot cap\cdot\log(M+1))$，另计 $O(n+cap)$ 的遍历与初始化。因为每种有对数个包、每包仍要扫描容量，不能把整体写成对数时间。

**辅助空间为 O(cap)**，只维护一维 dp，不保存全部包，也没有复制物品数组。

C++11 教学实现与模板分别对照小规模原数量枚举，检查容量 0、空输入、零数量、余包、同占用、数量截断、大价值、重复调用与输入不变。数量取 `INT_MAX` 的截断边界另行核对。两题实际实现已静态复盘，通用核验不补记个人平台结果。
